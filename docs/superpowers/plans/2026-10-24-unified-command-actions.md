# 统一战术提案实施计划

依据：[统一战术设计](../specs/2026-10-24-unified-command-actions-design.md)。用户已确认统一提案、整队评分选择与分阶段执行的方向，并要求尽量减少不必要的测试。本计划将验证收敛到直接受影响的接口与实际行为；实际进度见下方阶段记录。

## 本地基线与执行方式

- 当前基线为本地 `a9aece9` 加用户未提交修改，不拉取、合并或检出远端内容。实施前再次检查其他对话是否有新增提交。
- 建议在当前对话由同一执行者顺序完成下面三个阶段。各阶段验证通过后更新记录、提交并普通推送 `origin/main`，无需逐个阶段再次询问。
- 不并行运行多个实战测试，避免性能采样互相影响；不启用子 agent。
- `enemy_attack_position_action.gd`、`enemy_melee_cover_action.gd` 等已显示工作区修改状态。修改前保留当前文件基线，提交时审查实际差异，不能把其他任务变更一并上传。
- 本机未找到设计流程提到的 `writing-plans` 技能；本文件按仓库现有实施计划格式整理，不声称调用了不存在的技能。

## 阶段1：接通统一候选协议

目标：保留现有任务执行链，使多个动作通过共同入口提供候选，并迁移默认行为、突进和现有支援射击的选择方式。

1. 在 `actions/enemy_action.gd` 增加共同 `prepare_command_offers(query, cursor, deadline_usec)` 与 `validate_command_offer(query, offer)`；默认返回明确的未适配原因。保留命令执行与个人生命周期入口。
2. 在 `squad_contract.gd` 定义提案身份、用途、代价、纯值载荷和延续字段；角色资格查询返回可用集合，不能用第一个执行器屏蔽其他动作。原任务五项身份和权限校验继续使用。
3. Context 增加统一请求/结果通道，AI 接入预算内的动作遍历与统一校验。实际动作实例只归 AI 持有；按冻结装配列表枚举，记录每个动作准备进度、不可用原因及继续游标。清理复位/离队后的旧请求结果。
4. 将 `enemy_search_formation.gd` 的岗位/路线几何与动作选择分离。共享机会先提供几何，各动作声明适用性、参数和效果，输出原任务可消费的候选；不同动作共用同一截止时间及几何批次。
5. 修改协调器 `_plan()` / `_member_work()` 收集共同候选，接入原 `enemy_team_planner.gd` 整队成本评价及 `_commit()` 原子提交。容量限制保留作用不同的候选，轮询覆盖全部动作；提交前和动作接单前走共同校验。
6. 默认巡逻、搜索、远程/近战接敌、换弹及协作动作接入提案入口；保留原关键入口同步、搜索朝向、奔跑与当前有效任务。
7. 短程突进把原 `contact_executor()` 内的适用判断迁回动作，继续使用原加速/冷却；既有可见支援射击走同一入口。用通用可用性变化触发重评，移除突进专用选择通道及其重排判断。
8. 同时核对任务延续条件：单纯重新估值不得重置动作阶段、压制枪数、观察时间、等待期限或冷却。连续目标小位移仍能保留有效准备工作。

阶段1直接验证：扩展原合同/模块化夹具，证明新 ID 动作无需修改协调器便可参与、获选与执行，同时覆盖同角色竞争、遍历公平、过时结果拒绝和查询无执行副作用。实战只选普通档 `--pursuit` 与一档 `--support-burst`，复用原真实加速、命中及扣弹断言。此阶段不宣称所有可选战术已迁移。

## 阶段2：补齐全部战术的实际过程

目标：全部已装配动作都能通过共同入口提交和执行其真实战术过程。

1. `cover` / `covering_retreat`：原避险服务保留压力需求和公共掩体几何，动作负责躲藏、探出、撤回及移动射击的适用性和参数；删除服务与基础执行器中按 `covering_retreat` ID 选行为的分支。
2. `attack_position`：复用原攻击区域评估中的合法选位算法，将对象引用转为纯值关联及版本，接入移动/保持射击阶段；不得只返回普通接敌点并更换动作标签。
3. `melee_cover`：复用原接近、出口及近战几何，提案提供当前批准路线与有限后续意图；新目的地和占位经协调器续接提交。保留必要观察、低墙姿态、受阻/失视处理和实际近战命中。
4. `suppression`：共用原压制证据、预览、有限波次与 Fire。本人失视、近身压力和真实支援分别提供方案，所有用途走同一提案入口。补齐有限记忆射击的合同、提交、接单与原 Fire 校验链，保证证据一次消费、实际发射扣数和合法退出。
5. 支援候选在完整整队方案中绑定真实受益任务；纯标签和共享报告不授予长点射或记忆射击权限。仍由原 `squad_support.gd` 核对需求/观察，保留退出与有限恢复。
6. 动态枚举两个兵种目录及 includes，核对全部12个动作。兼容 `exit_suppression` 继续走原迁移，不恢复已退出的出口封锁行为。剩余动作未适配必须明确记录，不能用基类空实现通过审计。

阶段2直接验证：优先给现有混编运行入口增加一个集中验证模式，分别形成攻击占位、近战掩体接近、有限压制的有效现场，读取实际移动/开火/命中。只在原压制合同中补充共同提案造成的新权限与一次消费边界，不重新复制整套火控时序测试。掩体/撤退复用最贴近当前改动的一项原场景；新失败才增加窄范围对照。

## 阶段3：联合行为收尾与维护

1. 选择一组纯远程交战和一组强档混编搜索转交战，核对交叉/后侧火力、真实检查与支援、朝向、同步和失效恢复。已有模式可以覆盖时不新建重复场景。
2. 所有实战运行同步采集整队耗时；保留 P99 <16毫秒、峰值 <50毫秒门槛。动作更多不能把每动作预算相加后扩大总预算。
3. 全程核对指挥期间个人 Utility 为零，训练资格未被小队等级授予，动作执行未私自切目标/目的地。生命周期只复用上述场景已有的减员、单人和复位流程。
4. 搜索代码中残留的动作专用选择分支与首个执行器假设，核对结果；兼容资源 ID 转换不属于调度分支，不为静态搜索结果删除合法兼容代码。
5. 同步 README、项目结构、enemy-ai、enemy-tests、TODO 及本实施记录。分开记录用户要求、实现参数、已通过与未覆盖范围。

## 精简验证规则

- 不执行全仓或完整敌人回归；不重跑检查器、插件、玩家、表现及无关地图测试。
- 不先跑全部旧基线。使用已有运行记录作为背景，仅对新出现且归因不明的失败做最小修改前后对照。
- 接口结构检查优先集中于现有合同套件；运行测试检查真实效果，不以方法存在、动作名或计数标签代替。
- 不做“所有动作 × 全部等级 × 全部地图”的组合。共同路径通过一组代表用例，普通/强档有不同控制流程的部分才分别覆盖。
- 同一批生产代码的相关验证通过后不重复运行；后续更改触及已验证路径，才重跑对应部分。
- 不降低原断言、期限和性能门槛，不改用户保存的场景、训练或武器。实例输入可按有效夹具需要设置。
- 若增加正式测试模式或文件，运行 `python movement_demo/tests/run_regressions.py --check` 检查登记；提交前始终审查差异与 `git diff --check`。

### 后续修复：完整训练下近战警戒停顿

用户继续反馈近战停顿且显示“警戒”。独立复现确认 `guard / objective_changed` 最长189帧：原流程等一个成员的全部复杂候选完成才处理下一个，玩家持续移动又会使未完成准备作废。此前专用追击只装配窄范围战术，未覆盖完整训练与连续移动的组合。

在既有协调器和动作职责内修复：每个成员保存自己的准备游标，轮询推进；接敌有警戒/受阻/已完成成员时，先提交当前可行的整队方案，并保留有效队友及剩余动作的准备工作。全部候选完成后仍进行完整比较，搜索和巡逻仍使用完整观察/支援集合。近战掩体先核对原入口有效性和推进条件，再按出口续算，复用选中的出口评估。没有按动作 ID 添加协调器选择分支，没有改训练解锁、评分框架或原时间预算。

新增原混编脚本的 `--guard-stall --all-trained` 组合，只把完整训练的停顿检查与强制突进专项分开；原 `--pursuit` 的所有要求保留。最终普通/强档完整训练各11/11，最长无故停顿均3帧、警戒停顿0帧，全部已装配动作确实进入查询。原突进10/10、近战掩体7/7、完整训练混编搜索15/15、合同33/33；所有最终运行保持原性能门槛。近战掩体准备前提同步允许已经真实目击后进入遮蔽，实际阶段和命中断言不变。

中间直接刷新当前接敌终点的尝试引入通行等待，修改前对照通过后已撤回；最终不保留该路径。没有将失败历史改写为通过，详见[敌人测试](../../enemy-tests.md)。本阶段只提交本任务代码与维护说明，用户其他本地修改保留。
