## 实施顺序

1. 新增独立表现状态、动画映射和模型挂载组件。空配置不改变占位外观；模型预览不保存内部实例；动画只影响自身模型。
2. 新增玩家、敌人和 NPC 适配器，补充实际发射、结算受伤、死亡及对话来源通知。敌人加入冲刺识别，保留无模型的原倒地 Tween。
3. 新增命中快照、表面配置、独立特效管理器及粒子示例。只连接真实射击出口，覆盖缺省、禁用、寿命、暂停、复位及重复派发。
4. 在主场景、敌人和掩体场景中增量添加空配置节点，保留所有已有节点路径、UID、实例参数和用户修改。
5. 增加专项测试和演示，运行敌人、战斗、移动、交互、掩体保存回归；检查实际渲染结果。
6. 更新接入说明、目录及设计状态，记录验证结果和未覆盖的正式素材限制。

## 验证与保护

- 开始前保存三个用户已修改文件的内容到忽略的 logs/presentation_baseline，作为最终差异核对依据。
- 测试不保存用户场景和资源；所有临时文件放 logs。
- 首先检查脚本导入与主场景空配置，之后验证有素材的状态切换和命中特效。
- 不修改武器数值、AI 评分、训练设置、碰撞尺寸或地图布局。
- 所有新增脚本保留 Godot 生成的 UID；文档和测试入口随实现更新。

## 执行结果

已完成上述六个阶段。新增节点默认不配置模型、动画或特效，主场景仍使用原外观。模型与动画后端合并到 VisualPresentation，额外提供独立移动采样辅助；玩家、敌人和 NPC 分别适配已有状态，敌人包含冲刺。命中事件在伤害前保存、在实际射击结束后派发，掩体无需血量组件。

提供 `scenes/presentation/presentation_preview.tscn`、简单带动画模型、动画对应表和金属火花示例。正式角色美术、骨骼重定向、上下半身混合、音效、弹孔附着和可破坏掩体不包含在本轮。

### 已有测试边界

movement_test、sprint_test、interaction_test 仍有失败。使用改动前 Git 快照并叠加用户原有 enemy.tscn、ranged.tres、arena.tres，在隔离工程中得到相同失败项：移动7项、冲刺11项、交互1项。前两套仍包含立即停止及立即达到目标速度的旧断言；交互套仍假定离开时没有待完成会话。本轮没有改动现有移动规则来迎合这些旧断言。对照日志及清单位于 `logs/presentation_baseline/`，基线压缩包保留，解压工程已清理。

test_cover_instance_save 属于编辑器测试，range_reset_test 提供 run(scene) 而不继承 SceneTree；首次错误地通过 --script 直接运行不能作为功能失败，已改用正确入口验证。新编辑器进程的断言全通过，但 --editor --script 退出时仍有仓库先前记录的编辑器 RID/资源释放提示；该退出提示与运行模式专项结果分开记录。
