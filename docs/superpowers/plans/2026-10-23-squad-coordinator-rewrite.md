## 1. 用户已经明确的要求

1. 删除旧协调器实现，重写协调器及相关规划、任务交接代码；不继续把旧协调器上的零散补丁作为最终交付。
2. 普通配合和强配合都是团队统一指挥。在接敌和搜索期间，包括只剩一名成员时，协调器都必须持续负责规划、分工、站位、通行、执行反馈和重排。
3. 不能因为没有形成队列、候选不足、路线失败、任务到期、成员暂时受阻，就让队员自行接管战术决策。只剩一个成员时仍由协调器调度；此项按用户最新确认替代此前的单人接管例外。
4. 协调器必须结合地图静态信息和每名成员的实际信息规划，不只是接收个人各自想做的动作再尝试拼接。
5. 同时解决两个问题：没有形成队列后搜索方向断掉；多人挤在一起后不能合理分配站位、入位路线与通行次序。
6. 删除任务相关 UI；当前主场景不再摆放相关交互演示物。敌人规划不使用大面板，路线、方向与目的地直接标在地图上，采用 RTS 式表现。
7. 验证以实际试玩和针对性复现为主，只做必要检查，不用大量无关回归替代实际效果。
8. 必须按每名成员实际生效的兵种单位、训练配置和装备能力分工并执行，提供可读取成员数据的接口。在加载战斗场景、成员完成装配后，统一读取并保存本场战斗的能力档案，创建默认分工模板；本场后续调度以此为基础。下一次加载战斗场景时再重新读取和创建，不要求战斗中监听配置修改并自动重建模板。

9. 保留个人 Utility AI 评分机制，只在“仅视野共享”等级启用。普通配合和强配合停用个人 Utility 评分与自主选择，包括只剩一名成员时；成员执行协调器任务。

10. 共享情报统一经过协调器：个人真实发现后上报，协调器接收并向有共享资格的成员发布；仅视野共享等级也保留情报收发，但不下发团队战术任务。

11. 协调器相关内容重构的时候禁止用之前的代码来改，要完全重写

“仅视野共享”仍不等同于团队指挥。本次统一指挥的硬约束适用于用户明确指出的普通配合、强配合。本文后续涉及的文件拆分、调度频率、算法与实施顺序都是待审阅的技术方案，不写成用户指定参数。

## 2. 已核实的现状与本次不冒认的结论

当前有明确的架构偏差：

- `enemy_team_planner.gd::propose()` 对普通配合直接调用 `_recommend_positions()`，走建议分支。
- `squad_coordination.gd` 会把普通配合提案改成 `constraint_mode = advisory`，没有统一的强制执行权。
- `EnemyContext.coordination_choices()` 在任务为空或为 advisory 时重新放行个人候选。这不是持续团队调度。
- 队形几何、组队尝试、任务期限、搜索后续和个人恢复之间存在多套退出条件。组队失败后，协调器可能不再保有完整的后续分工。
- 入位顺序曾采用逐人贪心：先找到一个人的可行路线就落定，再安排下一个人。局部可行不代表全员顺序可行。

本轮后台确实采到三人失视后均为个人搜索、协调器持续返回 `no_complete_combination`，随后一人重新目击才恢复战斗分工。该片段不能证明用户所有拥堵情况的唯一原因。

当前工作区已有未提交的 UI 清理、世界路线渲染、旧队形失效修补和入位顺序探索修改。实施已暂停：这些修改保留在本地供审阅，不当作新协调器已经完成。UI 部分可独立收尾；旧协调器补丁在重写时由新实现覆盖，不保留第二套调度路径。用户原有的插件、资源、感知脚本与其他任务改动保持原状。

## 4. 新架构：唯一指挥链

数据流：

`加载战斗场景 → 读取本场成员能力档案 → 创建本场整队默认分工模板`

`默认分工模板 + 地图静态信息 + 已合法获取的情报 + 全员身体/装备/动作即时事实`

`→ 协调器维护队级目标 → 生成全员方案 → 导航/动作核验可执行性 → 原子提交任务表和空间预约`

`→ 成员执行任务 → 返回进度/受阻/完成/紧急事实 → 协调器续接或重排`

情报流独立于战术决策等级：`个人感知 → 上报协调器 → 校验并维护团队情报 → 向合法成员发布 → 个人情报缓存/团队规划读取`。

关键约束：

- 成员可以报告“做不到、受阻、正在不可打断动作中”，但不能把拒绝任务变成取得自主战略决策权。
- 规划器根据队级目标决定需要哪些位置、路线与角色，再请求个人能力服务核验；不是等个人先自主选择目的地。
- 每个仍在队内的活成员始终有任务记录；未接敌时由协调器给出巡逻/警戒安排，无目标不是放弃指挥权的条件。接敌/搜索期间必须持续分配相应职责。可行动者有当前目标；暂不可行动者有明确的占用状态、恢复条件和恢复后的接续任务。
- 新计划提交前核对全员身份、版本、静态地图版本和实时占位。失败不清空旧有效任务；只替换受影响任务，必要时原子切换整队方案。
- 计算尚未完成时沿用旧有效计划；首次接管时先建立由协调器发出的短期观察/防守/等待任务，并立即继续规划。不能留下无主空档。
- 等待是有原因、依赖对象、退出条件和检查时点的任务。全员无限等待、反复续同一个空任务不算“始终有规划”。

### 4.1 成员能力档案：战斗场景加载时读取并保存

已核对的现有基础：`EnemyUnitProfile` 提供能力标识、默认行为和战术目录；`EnemyTrainingProfile` 提供训练选择与生效参数读取；`enemy_ai.gd::refresh_configuration()` 解析并实例化合法动作，失败实例会从可用集合移除，完成后发布配置修订。本方案在**战斗场景加载且成员实际装配完成后**读取其结果，生成本场能力档案；不新增战斗中的配置监听/热更新流程。不能只在节点 `_ready()` 时读取训练勾选项，也不能把尚未成功实例化的动作算成能力。

建议由原装配/Context 边界提供两类公开只读接口，以下名称是技术方案示意：

| 接口 | 内容与用途 |
| --- | --- |
| `member_capability_snapshot()` | 成员身份、本场能力档案身份、兵种标识与能力标签、最终装配的默认行为/已解锁战术、各动作支持的任务与限制、实际生效的相关训练参数、武器规格及装备资格、移动和身体规格。供战斗场景加载、成员完成装配时读取并保存，本场调度复用该档案。 |
| `member_runtime_snapshot()` | 当前位置、速度、生命、弹药、换弹剩余、当前任务进度、可移动/可攻击状态、已合法获取的观察及受阻事实。供运行中规划和执行校验读取。 |

档案采用纯值快照并带本场战斗的档案身份；协调器按成员分别保存，不能持有可写的共享训练 Resource 再修改它。训练参数遵循原有默认值/显式覆盖的解析规则，不能另写一套优先级。兵种名用于识别和解释，分工资格由真实能力决定；同兵种不同训练、同训练不同武器必须能形成不同档案。

档案中的可用任务须能追溯到实际动作执行器：岗位需要哪些兵种能力、训练动作和装备条件，要有明确声明和检查。动作被禁用、依赖缺失或装配失败时，该任务不可分配。训练中的“未解锁”是硬限制，不能因为团队缺人就临时赋予能力。

加载流程：加载战斗场景 → 本场成员完成兵种/训练/装备及动作装配 → 通过接口读取并保存成员档案 → 协调器汇总本场队伍 → 创建默认分工模板 → 结合地图给出首次实际任务。未就绪成员有显式准备状态，不执行尚未确认能力的任务；某成员加载失败不能无限挡住其他已就绪成员。此处的加载是战斗场景初始化，不是战斗中的每次重规划。

档案与模板默认保存在当前运行的小队实例中，不新增磁盘存档，也不把自动计算结果写回用户的 `.tres`。持久化或手工编辑模板属于后续需求，本次不作为依赖。

### 4.2 默认分工模板：整队的初始职责安排

该模板可以实现，并作为新协调器的正式输入。它在没有敌人具体位置时即可生成，记录职责优先级和替补关系；具体目标、站位和路线由运行时规划确定。

模板由**全队能力一起计算**，不是分别给每人贴一个标签后让他们自己行动。建议包含：

- 本场模板身份、成员名单及对应的能力档案身份。
- 接敌、搜索、巡逻/警戒各阶段的优先职责、允许的备选职责，以及对应执行动作。
- 每项职责的能力/训练/装备硬条件、当前队内可承担者和替补顺序。
- 团队缺少的能力及可行替代方式；没有替代者时明确不能采用该战术，不能生成虚假掩护或虚假搜索能力。
- 分工依据，例如“具备枪械资格，已装配压制动作，武器兼容”，便于后台解释和核对。

示例仅说明生成方式，不预设项目必须包含这些兵种组合：

| 实际配置 | 可以生成的默认倾向 | 必须保留的限制 |
| --- | --- | --- |
| 具备枪械资格、已解锁并装配专门压制动作，且装备兼容 | 接敌时优先火力支援，按其他能力列出替补职责 | 不能因模板写着压制就绕过射程、弹药、视线和原火控条件。 |
| 具备近战装备资格、已装配对应接近/突进动作 | 优先近战接近或突入，搜索职责另核对实际模块 | 不能套用远程掩护岗位，也不能分配未解锁的突进动作。 |
| 同为远程兵，一人具有侧向机动训练，另一人只有基础行为 | 前者更适合侧向接近，后者承担其真实能力允许的正面接敌/观察 | 不得仅凭同一 `unit_id` 给两人同样的高级战术。 |
| 三名成员配置完全相同 | 都是同一组岗位的合格候选，生成稳定的初始分工和替补关系 | 后续按地图、位置及状态选具体执行者，不能虚构一名专职人员，也不能把三人都派到同一站位。 |

模板是职责偏好，不是永久锁死的职位。运行中先排除能力不符、路线不可行或身体暂不可执行的任务，再综合队级目标、当前岗位连续性、真实距离/风险和模板偏好分配。明显不适合当前现场时可以改派，但改派者仍是协调器。不能让模板优先级压过可达性、安全间距或成员能力。

没有合适执行者时，协调器改选全队能够执行的方案；仍然遵守普通/强配合统一指挥，不因“模板缺一个岗位”让队员自行接管。

### 4.3 本场复用、实时调度与下次加载

用户已明确：读取配置和创建默认模板的时点是**加载战斗场景时**。此前计划加入的“配置变化时自动更新档案/模板”超出要求，删除该流程及相应验收。

- **本场初始化**：统一读取本场成员的实际装配结果，保存能力档案并创建默认分工模板；不在每次规划时重新读取训练资源。
- **本场战斗过程**：复用该档案与默认模板，根据实时位置、生命、弹药、换弹、受阻和目标变化调整具体任务、站位、路线及替补。任务重排不等于重新创建默认模板。
- **成员死亡/离队**：更新当前可调度成员和具体任务，依据本场档案及模板安排替补；不因此重新读取全队训练配置。暂时换弹或受阻不算离队。
- **下一次加载战斗场景**：释放上一场的档案、模板、任务和预约，按这次加载的队员配置重新读取并生成模板。编辑后的配置在下一次场景加载流程中采用；本次不实现战斗中的配置热更新。
- **执行校验**：任务仍检查本场成员身份、计划版本和即时执行条件，旧场景/旧任务反馈不能影响新任务。模板不能绕过实际身体、弹药、装备资格及动作执行校验，但这些校验不触发配置重读或模板重建。
- **缺失/失败数据**：标记未就绪或具体能力不可用并给出原因，不能默认成“全训练”；加载失败和配置错误可诊断，但不能凭空让该成员执行缺失模块的工作。

### 4.4 选择机制：队级目标、约束规划与执行状态分开

建议采用“硬约束筛选 + 整队方案评分选择 + 执行状态机”，尚未实施。评分负责从可行方案中选分工，状态机负责推进与反馈；不采用仅靠固定状态分支分配所有岗位，也不采用允许收益抵消硬约束的纯加权评分。

1. **目标与阶段规则**：按合法情报和实际进度维护巡逻、接敌、搜索等目标。失视触发搜索，队形失败触发当前目标下的重排，不删除目标或交回个人决策。
2. **全员约束规划**：从本场能力档案、默认分工模板、地图和实时状态生成有限数量的完整方案。先检查能力权限、可达性、站位间距、通行依赖与实际执行条件；违反硬约束的方案不能靠高评分通过。
3. **整队方案比较**：先保证当前目标下必要职责与全员任务完整，不能靠全员等待取得最低风险而压过可行推进；再在可执行方案之间比较目标推进、搜索覆盖/射界、行程与等待、暴露风险及改派成本；模板提供职责偏好，已有有效任务提供连续性偏好。这是协调器对整队方案的选择，不运行成员个人 Utility，也不等待个人先选动作。具体权重和预算属于实施参数，不能写成用户指定值或无限枚举所有排列。
4. **执行状态机**：管理任务已分配、准备、执行、受阻、完成等生命周期及同步放行。状态机不单独决定谁站哪里，站位、路线和通行顺序由规划器给出。
5. **失败续接**：没有可行编队时，保留队级目标，由协调器选择其他入口、布局、分区或顺序；计算期间保有合法任务和明确重排条件。只剩一人时规划退化为一人的合法任务，决策权不变。

动作的能力核验、路线查询和执行时间估计可以作为规划输入复用，但应与个人 Utility 评分/选优入口分开。合作等级决定启用哪条决策路径，两条路径共用底层执行器，不能同时争夺成员控制权。紧急身体反应仍按明确执行规则处理，不偷偷调用个人评分器。

### 4.5 情报上报与发布：协调器统一入口

已核实的旧实现：`EnemyContext._update_cooperation_evidence()` 调用区域 `enemy_cooperation.gd::publish_visual()` 上报，再由各成员直接调用区域 `evidence()` 读取他人报告；区域 `_publish_visual_coordination()` 另外转交协调器线索。因此旧实现不是“个人上报小队协调器，再由协调器统一广播”。

重写后的职责：

- **个人感知**负责真正看到/听到什么，记录目标、来源成员、观察位置、原始时间和实际观察到的运动；本人观察保持为本人事实，不依赖广播往返才能成立。
- **协调器情报入口**接收报告，检查来源身份、所属队伍、通信资格和时效，维护带版本的团队情报，并发布给有接收资格的成员。转发保留原始来源和时间，成员不能把收到的消息再当作新目击上传，不能循环刷新情报寿命。
- **区域服务**继续提供敌我关系、通信隔离和必要传输/存储；成员不再绕过协调器直接拉取区域共享板。跨小队共享仅沿用原本合法的通信关系，通过协调器入口收发，不自动扩大情报范围，也不让一个小队指挥另一个小队。
- **仅视野共享**也运行情报收发部分；成员读取协调器发布的信息后自行 Utility 决策，协调器不生成岗位、队形或战术任务。普通/强配合使用同一情报源，由协调器进一步生成全员任务。
- **发布实现**可以使用版本通知和只读快照，不要求每帧深拷贝所有报告。具体接口名在实现中确定；入口和数据归属必须唯一，不能保留两套各自维护的共享事实。
- **共享信息的权限边界**：收到队友报告不等于本人已看见，不直接授予穿墙开火、精确追踪或已搜区域标记。实际射击仍经火控校验；失视后冻结最后合法位置，随后信息过期与搜索目标续接分别处理。

## 5. 指挥权与等级

| 情况 | 决策权 | 行为差异 |
| --- | --- | --- |
| 仅视野共享 | 个人 Utility AI | 启用原个人评分与选择；合法共享信息和基础空间安全保持。 |
| 普通配合 | 协调器，停用个人 Utility | 持续分配接敌、搜索、支援、站位和通行任务；不强制所有任务都等待全员集结。 |
| 强配合 | 协调器，停用个人 Utility | 同一指挥协议，额外使用确有必要的集结、同步推进与共同放行；一人有问题由协调器调整全队/相关成员，不能永久拖死全队。 |
| 普通/强配合只剩一名活成员 | 仍由协调器，停用个人 Utility | 取消需要其他成员的集结、掩护和通行依赖，改为该成员能完成的任务；保留合法目击记忆与搜索进度，不切换决策系统。 |

暂时换弹、翻越、受击硬直或被堵不等于小队只剩一人。成员真正死亡、移出小队或离开运行区域时，按实际成员生命周期处理；小队整体停用/场景退出则清理，不借停用偷偷触发另一套团队 AI。

紧急反应由明确的执行规则授权：实际近战、自保、不可打断身体动作可先采取最小必要反应并立即上报；原任务标记为中断或占用，战略目标仍归协调器。不能用一个泛化 `urgent` 标签恢复任意个人搜索或包抄。

## 6. 队级目标与证据分离

协调器单独维护“这支队伍当前要完成什么”：接敌目标、最后可靠目击、未核实区域、已经真实观察的区域和当前搜索方向。

- 目击/声音证据保留原来源、获取时间与身份；不读取隐藏玩家实时位置，不用重规划刷新证据时间。
- 精确情报过期后，不再支持精确瞄准、压制或把当前位置当作已知事实；但不会因此删除“仍需搜查最后已知区域”的队级目标。
- 搜索目标可以基于已经获得的历史记忆继续存在，随时间扩大不确定范围。任务计划有自己的有限有效期，计划到期由协调器续接/重排，不能等同于完成搜索。
- “队形失败”“无法到位”“等待超时”“未观察到”分别处理。前三者不计入搜索覆盖，也不证明玩家不在目标附近。
- 只有真实视线/观察满足条件，才能记为已搜。重新发现玩家时统一撤销过时搜索分工，切回接敌任务。
- 搜索终止必须有明确队级条件，例如所选可达区域已完成观察且无新线索、目标失效、区域重置；不能因一次找不到兼容方案就结束。

## 7. 接敌规划

协调器先建立队伍当前目标及可执行任务集合，再做全员分配：

1. 读取本场默认分工模板与已保存的成员能力档案，再读取当前目击者、成员位置/朝向/身体半径、生命、弹药、换弹剩余、可用武器与动作、真实移动/受阻状态；按能力硬条件过滤，按模板提供初始分工偏好。
2. 从静态地图选出可接近位置、可用射击位置、掩体及通行连接，排除不可达或明显互挡的组合。
3. 让已有有效射界的人承担接敌/压制/掩护，让缺视野者获得可达的接近/侧向观察任务；不能以“观察”标签让被墙挡住的成员无限原地站着。
4. 需要换弹、退避或重新占位时，明确安排自身任务与相关队员的支援，按各自实际能力验证。
5. 同时检查目的地间距、路线交叉、站位是否挡通道/枪线、预期到达先后，选出全员可执行组合。
6. 延续仍有效的岗位，只修复被新信息、受阻或成员变动影响的部分，避免每次重评全队换位。

成员数量超过一次完整昂贵查询预算时分批准备能力数据，但全员任务所有权持续存在。缺少某种能力应改分工，不应自动放弃指挥该成员。

### 7.1 接敌战斗示例：一人目击、两人缺视野，随后换弹与失视

以下用于说明机制，不预设用户当前三名队员已经具备这些配置。假设本场档案确认 A 有远程支援能力且弹药充足，B 有侧向机动训练，C 有基础远程接敌能力；地图有正面射击点、左侧可通行路线和互不重叠的支援位置。默认模板偏好 A 支援、B 机动、C 接敌/替补，实际分工仍取决于现场。

| 现场变化 | 协调器如何选择与下达 | 队员实际执行及反馈 |
| --- | --- | --- |
| A 首先看到玩家，B、C 被墙遮挡 | 接收 A 的真实目击并发布团队情报；验证 A 当前射界，生成 B 左侧接近、C 到另一个可达射击点的全员方案。排除三人同点、穿越 A 枪线或未训练战术的方案。 | A 在火控允许时接敌；B、C 按各自路线移动以恢复观察，不能因为共享报告而隔墙开火，也不能把盲站称为支援。 |
| 左侧机动与直接推进都有可行方案 | 比较完整方案能否维持真实火力、取得新增射界，以及路程、暴露、等待和改派成本。若左路不通或风险过高，协调器改派 B 到其他合法接近点，模板不强迫其包抄。 | 每人收到明确目标点、路线、动作与完成条件。移动者无需等全队排成队才开始有意义的接敌任务。 |
| B 的路径需要穿过 C 正在占据的窄口 | 联合安排 C 去经验证的让路点，B 待通道腾空后通过，C 再去射击位；A 的有效接敌任务继续。 | C 报告实际腾空后才放行 B；受阻反馈指向具体身体/位置，超时由协调器换顺序或路线，不让三个人各自挤。 |
| A 弹药不足需要换弹，C 已到位并实际获得射界 | 核对 C 的武器、弹药和真实射击能力，安排 C 接替火力，A 在可执行位置换弹；B 是否继续推进由可用支援与风险决定。若 C 尚无射界，不能算接替成功，协调器可暂停 B 的暴露推进并给其合法掩护位置。 | A 空匣时不能为了等支援而虚假开火或无限等候；没有接替者时协调器仍给出可执行换弹/掩护安排。换弹完成上报后重新评估，未必换回初始分工。 |
| 玩家突然接近 B | B 上报真实近身威胁；允许已授权的最小身体反应，协调器改排退距、火力或其他已训练动作，并校验友军枪线。 | B 不启动个人 Utility 接管；没有近战能力不能因为危险临时获得近战动作。 |
| A 失视但 C 仍看得到玩家 | 使用 C 的新报告继续接敌，调整 A/B 的具体任务；不因某一人失视让整队进入搜索。 | 目击者变化不清空有效岗位。只有实际失效的任务需要替换。 |
| 全员失视 | 保留最后合法线索，统一进入搜索；分配观察入口、接近位置和通行顺序。无法形成队列就选其他可执行布局，目标仍然存在。 | 每人继续有协调器任务；搜索推进依靠真实到位和观察，不依靠刷新任务时间或共享标签。 |

普通与强配合都由协调器决定上述任务。普通配合允许各自可执行的步骤异步推进；强配合可在确需共同暴露/突入的步骤设就绪屏障，但仅约束参与该步骤的成员，不让无关的正在接敌者停火等待。屏障失效或成员缺位必须重新规划。

具体任务除了“支援/机动”等名称，还须携带目标/证据身份、指定位置与路线、执行动作、攻击限制、开始依赖、结束条件和受阻回报；状态机按这些条件推进。方案评分发生在协调器，实际开火、命中、碰撞和身体动作仍由底层验证。

## 8. 搜索规划与组队失败后的续接

失视时由协调器冻结共同线索，并按地图决定先查哪一处：遮挡物两侧、最后目击点、可能通过的通道或未覆盖区域。

- 先分目标区域，再结合默认搜索分工和每人实际训练/动作能力分配任务与站位。未装配搜索模块者不能收到搜索执行任务，由协调器安排其具备能力的相关职责。队列只是一种执行布局，不是搜索能力的前提。
- 有可行整队布局时，分配每人的准备位置、检查位置、路线及通行优先关系。
- 无法成队时，保留同一队级搜索目标，由协调器改用可行的单侧、分组、先后通过或不同入口/观察点方案。所有成员仍收到明确任务，不退回各自搜索。
- 动态拥堵导致失败时，依据实际占位重排；静态不通时改入口/子目标；不能反复下发同一条已经失败的路线。
- 一段调查没有重新发现玩家时，协调器根据真实覆盖继续分配相邻未搜区域；按地图连接和线索方向推进，避免三人不断走回同一个点。
- 某成员暂时没有可达搜索位置时，分配有意义的入口观察、封控、让位或等待任务，同时调度其他成员推进；不能把不可行岗位写成已接受再让执行层自行补救。

## 9. 拥堵、站位与通行重排

这是协调器的正式职责，不依赖三个身体互相侧让来碰运气。

1. 对整个候选方案验证全员终点间距、静态可达性、入口宽度、路线相交和到达后是否挡住别人的必要通路。
2. 使用有界的完整分配搜索，同时考虑成员与岗位的对应关系、出发顺序和必要的中间让路位置。不能只在一个贪心顺序失败后判定整队无解。
3. 为窄口和相交路段建立通行依赖；独立路线可以并行，冲突路线按实际腾空情况放行，不能预约整条长路线把全队锁住。
4. 每名成员单独记录进度和等待对象，检测两人互等、三人循环等待及“已到位者挡住未到位者”。第三人在移动不能掩盖另外两人停滞。
5. 出现死锁时选择明确让路者、经验证的临时位置、先通过者和返回岗位条件；一起提交相关成员的新任务，不能只改一个人的终点。
6. 每次修复要改变造成失败的条件。禁止重复下发同一路线、仅刷新计时器或无止境换队列布局。
7. 真实物理空间完全不允许通行时，记录具体不可达原因，由协调器改搜其他可达区域或保持有条件的观察任务。不能穿人、穿墙，也不能声称已解决物理上无解的局面。

## 10. 新任务与反馈契约

使用集中定义的数据结构，避免各脚本随手拼接不同字典。必要字段包括：

| 数据 | 必须表达的内容 |
| --- | --- |
| 成员能力档案 | 兵种、最终装配动作、任务资格、装备/训练的生效参数与本场档案身份；来源可核对。 |
| 默认分工模板 | 本场全队名单及能力档案身份、各阶段优先/备选职责、执行动作、替补关系、能力缺口与分工依据。 |

## 11. 调度与性能边界

- 沿用区域统一时钟，不新增每个 Squad 自己的独立物理循环。
- 建议常规团队规划从现有约 5 Hz 调度节奏起步；新接敌、失视、成员变化与实际死锁事件触发提前重评。这是实现初值，按实际场景结果调整。
- 位置/移动进度可按原物理节奏更新，昂贵导航、扫掠、候选搜索分预算进行；等待计算时保持已有有效任务。
- 静态地图查询缓存按地图/导航版本失效；身体占位、弹药和动作占用必须实时复核。
- 限制完整布局/分配搜索次数，记录实际消耗；不能通过删掉必要冲突检查追求速度，也不能把大范围找路塞进每名成员每帧的 `_process`。
- 验收同时看计划生成耗时和全体 AI 实际帧耗时，沿用既有适用门槛。只为本次出现的性能问题补测，不开展无关性能矩阵。
