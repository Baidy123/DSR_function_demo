# 地图观察与团队战术实施计划

依据 [指定设计](../specs/2026-10-23-squad-tactical-search-design.md)及本次“按照设计修改优化维护代码和项目”的实施指令。用户追加明确：覆盖所有配合档位，不限强配合。普通/强配合保持队级指挥；仅共享情报档保留个人选优及原搜索参数语义，核对共用观察和协作边界。

以当前本地工程为基线，直接在本会话顺序实施。保留用户场景、训练、武器、插件及已有修改；不拉取或合入远端。

## 阶段与接口

1. `squad_map_coverage.gd` 保存区域/楼层面积样本、真实观察时间、监视者、局部地图版本与失败原因；`enemy_visual_observation.gd` 提供严格视角及站/蹲藏身高度的环境检查，排除近距离全向警觉捷径。`squad_search.gd` 编排线索与覆盖，hint 不清除观察历史。协调器验证任务身份及真实身体后接收观测，巡逻/接敌同样贡献记录。
2. `squad_search_route.gd` 产生有界多段观察路线与预计收益；任务合同声明观察样本、执行方式、未来步骤及版本。动作分别执行移动和朝向，协调器决定续接；已完成的未来样本跳过，失败不伪造观察。强配合仅关键入口使用屏障，普通路段按队伍距离调速，普通配合异步分工。
3. 现有整队候选加入训练允许的掩体岗位与可持续火力/暴露/等待/改派评价，保持真实射击和压力避险；完善只读覆盖与未来路径显示。
4. 维护 README、结构、敌人接口、测试说明及待办。必要检查覆盖真实遮挡/局部观察、持续搜索、所有档位、屏障与队列、接敌/换弹/减员/重载及既有时间/性能门槛。新增地图用实例夹具，不写回用户布局。

以上文件名、预算及采样参数为实施选择，不改写为用户指定算法。阶段结果由实际验收记录更新；未通过或未运行不记作完成。每个可独立验收阶段审查完整文件集合后普通提交并推送 `origin/main`。

## 实施记录

四项工作作为同一可运行阶段集成：观察证据由协调器核实，路线和任务合同同时接入动作；整队搜索与掩体候选在约2.5毫秒预算内续算。共享静态地图保留原职责，各小队拥有独立观察历史；0级不增加任务指挥。当前接口与默认参数见 [enemy-ai.md](../../enemy-ai.md)，逐项行为、性能、结构及图形验收见 [enemy-tests.md](../../enemy-tests.md)。测试仅修改独立实例输入，开始工作前的用户文件经过哈希核对保持原样。

原设计中的算法和数值建议仍与用户目标区分。当前实现采用离散面积格、有限未来步骤和基于实际相对运动的行进调速；复杂多层、大地图及更大队伍是后续试玩/扩展验证范围，本阶段不声称已穷尽。
