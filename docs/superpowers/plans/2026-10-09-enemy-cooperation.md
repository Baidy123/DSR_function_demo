# 敌人协作实施与验证记录

日期：2026-10-09。依据：[已授权设计](../specs/2026-10-09-enemy-cooperation-design.md)。

下文先保留首版实施及验证历史。用户同日追加的堵路与压制修正见文末；当前运行行为不再包含出口射击。

## 范围与实施顺序

用户已要求实施共享情报、交叉火力、侧向推进、换弹／撤退掩护、双侧出口封锁，并将分工搜索、主动协调换弹加入本轮。后续只保留多方混战与新增兵种后的协作优化。训练预设不是本功能前提。

本轮最多三名 agent：主 agent 负责公共接口、资源迁移与集成；搜索／换弹 agent 负责原动作扩展及专项；战术 agent 负责统一压制、协作站位及专项。Godot 回归分时运行，避免并发影响运行时预算。

1. 战斗区拥有 `EnemyCooperation` 服务；Context 提供权限过滤的值快照，Actor 仅增加阵营与通信组身份。默认情报共享不依赖高级训练。
2. 通过原行为目录解锁 `cooperate`；搜索与换弹复用自身执行，分工任务在动作提交后认领。保留默认行为和未训练单人流程。
3. 统一 `suppression` 的可见、点与出口方案；保留旧脚本 UID 和资源加载，旧训练 ID 解析为单一行为，旧显式出口参数兼容读取。
4. 普通接敌与压制使用同一公共支持收益；协作等待、转移、枪口方向、弹药、真实射线与时限均参与判断。不给尚未就绪的承诺抵扣路线风险。
5. 同步训练检查器、默认示例训练、结构文档及验收说明；审查仅本轮变更后提交并普通推送。

## 接口和边界

- 每个战斗区一份服务；报告带目标、来源、原始时间、期限和代际。个人目击字段不会被共享报告改写。
- `faction_id` / `communication_group` 为身份；`is_hostile`、`can_share_intel`、`can_cooperate` 分开判断。当前攻击仍只面向玩家，不声称已完成多方混战。
- 任务有互斥岗位、原子提交、有限占用、取消与死亡清理。候选枚举不抢占、不改变导航、不续时。
- 搜索仅共享 `can_observe_position` 实际通过的地面样本。世界对齐采样用于多人复用，负证据不计本人已查百分比；新目击后旧负证据不能阻碍追查。
- 非空匣主动补弹只在余弹比例低、可补装、队友火力真实可用时进入候选。共享名额防止两人同时自愿断火，空匣必要换弹保留。
- 协作参数初值属于实现默认值，可在 Training 调整，不是用户指定常数。

## 验证计划

- 情报：同区默认共享，异区／异组隔离，来源与期限不被转发刷新，个人视觉独立，关系与区域重置撤销旧授权。
- 任务：候选无写入、同岗竞争只有一个成功，超时／取消／死亡／撤权释放；重复评分不抖动支持收益。
- 搜索：两人正常 Utility 选择不同调查点，墙后地面不因队友观察而被排除，负证据过期可复查。
- 换弹：正常 Utility 发起低余弹补装，两人错开、真实计时与补满；独处、无有效火力及空匣回退。
- 战术：可见压制遵守反应与射速；共享失视压制冻结证据；双侧几何与真实射击；真实支持中断后的推进重评。
- 兼容：旧训练 ID、旧参数、检查器原生撤销；原模块化、近战、低墙、射击、搜索和性能回归。

## 实施结果

本轮功能已接入。分工搜索和主动协调换弹属于当前实现，协作后续功能只保留多方混战与新增兵种后的优化；训练预设可在确有复用需求时保存为 Training 资源。独立出口压制入口已合并，左右出口与单人轮换仍是统一压制的方案。

侧向协作限定为严格可步行的短路段。其他动作保留原翻越能力，但协作候选不能把步行支持窗口复制给翻越，也不能绕过等待阶段。支援收益使用实际时间交集：移动途中受掩护与抵达后的交叉火力取较大值，超过队友需求期限的支援不获信用。只读评分批次共用快照，提交与执行恢复实时校验。岗位快照与请求各自持有字典，生成目标压制请求不会改写原位置岗位。

## 同日试玩反馈后的修正

用户报告友军堵路、共享坐标引发无效盲射，并明确选择移除左右出口及单人轮扫。随后补充：本人看见玩家消失时可以向原暴露位置扫射一波；玩家近身、掩护队友或自身撤退也可以压制，目的是让玩家暂时不敢露头。因此不能把所有压制都收紧为“必须有队友请求”。本轮沿用最多三个 agent，改动限于既有移动与压制流程。

- 身体局部让行：原导航目标和行动计时保留，在实际友军阻挡时检查有限短路段；同向跟随、站定者让位及迎面会车均通过真实身体移动。关系接口 `can_share_space` 与通信组分离，仍限定同区域同阵营／显式友军。实际避让进入移动开火与支持快照判断。
- 有目的的有限压制：真实失视保存可见且枪口可达的身体样本；脚底坐标继续用于调查。个人事件只开一波，共享报告须对应真实未满足的支援请求。请求周期拥有稳定 ID，新报告不重开同一波；下一次真实换弹／支援拥有新周期。
- 完整射界：候选、开始、运行及底层记忆射击均核实完整弹道；不能仅凭枪口前半米畅通就向硬墙后开枪。可见近身压制及自身移动撤退沿用原反应、转枪、武器节奏和移动射击权限。
- 移除出口方案及其协作信用；保留旧资源、UID 和训练迁移，参数仅保留序列化兼容。搜索对出口的调查、普通掩体探头及几何接口不是出口射击，继续保留。

以本地 `c0a9ab3` 为修前基线，保存用户已有文件哈希与共享文档原文；独立副本只投影本轮差异，不拉取远端，不上传用户现有资源调参或交互删除。有效修前新专项分别为友军导航 **8/13**、压制目的 **13/21**，明确复现堵路和无效射击；压制测试前两次有类型声明／旧接口引用错误的诊断日志单独保留，不作为有效基线。

用户随后要求同时处理此前未通过的性能检查并清理冗余。优化集中于同一同步评估批次的重复环境射线、身体占位和枪线查询，以及友军射线检查中不需要的团队任务深拷贝；不改变候选采样、评分、选择频率或16／50毫秒门槛。完整执行仍查询实时物理状态，保留原阵营／通信组资格检查。

缓存专项最初两项失败来自测试在物理步前移动运动体后立即查询，而引擎仍保留其当前服务器姿态；移到真实物理回调也复现。保留原诊断，最终用可即时同步的静态胶囊验证同帧占位变化，运动体则经过真实移动与物理步同步后验证玩家排除／纳入，未更改生产占位语义。墙与枪线同帧改变、嵌套清理及查询次数断言保留，专项15/15通过。一次过早整合尚未落盘的团队新接口产生脚本错误，补齐准确文件后重新验证，不计作行为通过。

## 同日第二次试玩反馈：包抄可见性与前线保持

用户反馈协作开关体验相近、敌人聚集、掩护过程不明显，并进一步明确：同组、同目标的敌人全在一侧时，最多 `floor(N/2)` 人去另一侧，其余保留前线压力。此要求扩大了首阶段“有限侧移、不保证去另一侧”的范围；前文首阶段结果保留为历史，不能用曾出现一次 `cooperate` 或旧测试通过代替这次实际包抄验收。

本轮保持原动作装配、个人 Utility、身体／武器执行及区域服务的职责划分，不调整用户现有场景、武器、训练开关或全局评分权重。基础情报共享仍默认启用，只有高级协作受训练开关控制。

### 实施内容

- `enemy_cooperation.gd` 增加同目标冻结轮次与名额。首次认领冻结已知锚点、正面轴和截止时间；后续成员不能转动参照、续期或改写原任务最终目的地。真实已越侧身体与有效包抄认领取并集计数，到位后切回普通行为仍占用名额；成员减少时撤销超额任务，不瞬移身体。
- 新 `enemy_flank_route.gd` 只负责有限左右转向弧线、检查点和逐段严格步行校验，拒绝穿入已知目标周围1.5米区域；首段对友军身体保留0.75米路径净空，避免中间成员跨过前线队友争抢名额。路线基于合法目击锚点，不读取隐藏玩家位置，也不扩大为全队地图寻路框架。
- 原 `cooperate` 增加 `opposite_flank` 和 `overwatch` 内部方案。包抄按短段取得真实支持并执行，到检查点重新评分；前线保持响应实际队友请求，沿用原稳枪与开火管线。普通交战继续可提供真实掩护，移动候选不能领取推进所需的站定掩护信用。
- 枪械候选建立另一侧射界；近战继续受掩护接近，以实际攻击范围、高度和遮挡判断威胁，不套用枪械远端环绕半径或通过接近绕过人数上限。分工沿用身体与武器能力，不按兵种名称特判。
- 原地掩护初案与保持续案只预测实际剩余保持时间内的射击，纳入连射停顿、冷却、反应、稳枪及当前枪线／友军线；不能在本案结束后才开火却提前领取信用。Context 的即时支持也复核实际枪口方向，新增窄墙边期望方向畅通、当前弹道被挡的执行合同负例及恢复正例。
- Context／Fire 将 `target` 实际火力射界与 `position_lane_id` 位置预约分离；区分当前 `ready` 与合法连射暂停的 `support_cycle_valid / support_resume_seconds`。暂停保持零实际支援，不把恢复意图算成已开火。稳枪、弹药不足、换弹、真遮挡和失视不冒充正常周期。
