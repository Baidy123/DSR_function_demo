# 小队节点与调度器实施计划

依据：[2026-10-13 结构设计](../specs/2026-10-13-squad-node-coordinator-design.md)。用户于 2026-10-14 要求按该方向优化现有 AI 代码和结构。本计划记录实施选择，不扩大原有战术及多阵营功能范围。

## 基线与边界

- 以当前本地工程为基线，保存修改前副本和文件清单；保留已有地图、导航、武器、感知及插件改动，不同步远端内容。
- 掩体发现、地图增量准备和候选几何继续沿原区域／个人查询入口更新。小队不另存地图缓存。
- 保留三档权限、个人 Utility、身体与 Fire 执行及全部原期限、安全检查和性能门槛。
- 本次授权实施小队节点方向；原设计中的默认节点类型、最近祖先归属及区域统一推进作为本次实施选择。

## 实施阶段

1. **抽出队级运行状态**：从 `enemy_cooperation.gd` 提取计划、建议、岗位、支援交接及相关队级认领到 `services/squad_coordination.gd`。区域保留成员关系、情报、地图与公共预约。旧区域接口兼容转发到同一实现，不复制规划算法或计划字典。
2. **节点、身份与生命周期**：新增 `world/squad_controller.gd` 和 `scenes/world/squad.tscn`；独立运行身份、最近小队祖先、配置单一来源。Context 分别绑定区域和小队；同区换队保留个人记忆、身体与出生点，旧任务和预约失效。区域以同一时钟推进各队，复位每个身体一次。
3. **编辑器与本地场景迁移**：检查器显示所属小队并跳转节点配置；保留个人 Training。按本地场景实际成员分组，保持世界变换、内部路径及资源 UID。已迁移成员退出旧绑定路径；未迁移场景使用兼容实例。
4. **验证与文档**：新增队间隔离、地图公共性、配置与生命周期专项；保持原行为断言，更新仅因节点路径变化受影响的夹具。运行受影响专项、完整敌人组、必要战斗回归及人数／分队性能对照，保留修改前失败与所有首次结果。同步入口说明、结构说明和测试记录。

## 验收重点

- 同阵营、同通信组和同配置资源的两个显式小队仍独立；可以合法共享情报和公共空间安全。
- 队级状态只有一个所有者；区域不读取队级内部计划来决定预约有效性，不重复规划。
- 三档均保留实际执行路径；单人、无弹药、缺失配置有可执行退化。
- 加入、换队、离队、死亡、热切配置、跨区与区域复位不会遗留承诺或重复复位。
- 通过检查不等于性能改善；记录 1／2／3／6 人及 6、3+3、2+2+2 分队对照，个人和总耗时分开报告。

## 实施记录

已完成区域／小队状态拆分、显式节点和成员身份、Context 路由、生命周期及配置检查器接入。区域服务从2354行拆为1073行公共服务，队级状态集中在1791行 `squad_coordination.gd`；这不是减少总代码量或重写规划算法。区域只推进同一时钟，节点每帧至多推进一次，地图缓存仍只有一份。

当前本地场景的 Enemy3、Enemy2、Enemy4 原位置及资源保持，增加无偏移 Squad 并使用原强配合模板；提交仅记录小队分组变化，不上传用户其他地图／资源修改。旧成员继续由同一实现的兼容实例运行。共享模板只共享参数，节点身份、岗位、认领和运行计划独立；区域公共占位跨队生效。

同区换队保留个人记忆、健康、弹药、Training 和世界出生位置。跨区重新连接区域；死亡／释放撤销名册及预约。补充拒绝其他小队直接认领、跨队换弹互不否决、同值 Profile 替换失效、普通 Node 容器出生点和跨队身体／预约快照测试。原行为断言与性能门槛保持；枪线专项按已给定的跨通信组友军安全边界拆开情报与身体保护。

运行结果及性能限制如下；这些阶段组成同一个需要一起接入的结构迁移，按完整文件集合审查后提交。日志和验证副本保存在 Git 忽略的 `movement_demo/logs/squad_node_20261014/`。

最终验证记录（Godot 4.7.2，串行 headless；用户编辑器仍打开）：

- 完整首轮敌人 **71/112套**、战斗 **26/26套**，保留 `full_114049`；后续定向结果不拼成一次完整全绿。
- 核心定向复核 **16/18套**（`final_targeted`）；新增小队生命周期 **40/40项**、场景 **26/26项**、三档实际行为 **55/55项**。七场景支援本次 **32/32项**，转移支援者实际移动约1.40米并等待火力后补弹；首轮及原始副本31/32的结果保留，不把复测通过概括为普遍稳定性改善。
- 原始副本对照 **39套相关失败**，其中 **34套仍失败**（`baseline_failed_enemy`、`baseline_late`）；七场景支援另行对照。旧自主堵路、低墙、搜索持久性、共享接敌及空间预算等失败保留。本次场景整合的通过不替代这些历史运行问题。
- 拆分后发现旧成员路径存在重复祖先查询；通过实时父节点判断缩短直接区域成员查询，保留实时身份校验和原有限时间预算。修改后 `direct_area_queries` 中小队节点、board、枪线、提前换弹和团队搜索通过；旧威胁用例另行查明人数问题，不将时序复测结果概括为所有旧回归均已修复。
- 两项剩余行为差异查明了夹具前提：当前保存地图含三个成员，但旧威胁用例只关闭一人 AI，其他成员持续提供新目击；原始和候选均观测到 `team_visual_contact=true`、威胁年龄反复归零，原始也复现32.62秒躲藏。双人搜索同样混入未控制的保存成员。两项改用既有单人夹具，搜索再自行添加第二人，全部原断言保留；候选 **2/2套**、原始运行时 **2/2套**（`population_candidate`／`population_baseline`）。未改保存场景或运行逻辑来迎合这两个测试。
- 自主堵路夹具在替换导航后明确声明测试出生点，保留全部行为断言；普通同区域重连按新生命周期保留原出生点，不能继续拿重连模拟重生。
- 只包含本任务补丁的本地 HEAD 副本导入通过，核心 **10/10套**（`commit_preview_checks`）；没有把用户未提交的地图、武器、插件或删除项带入提交。
- 检查器新增保存重载、独立模板与原生撤销重做共 **40/40项**通过。自定义编辑器 SceneTree 退出仍有 RID／资源清理报错，原始副本也复现；不能计为无错误退出。新保存夹具的空根节点名报错已修正。
