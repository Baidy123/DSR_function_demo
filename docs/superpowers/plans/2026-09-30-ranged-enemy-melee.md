# 远程敌人近战接入记录

用户已要求按照既有近战设计先实现远程敌人，并说明敌人武器中的体力参数是否生效。本轮由当前代理直接在原工作区完成，保留现有资源调参，不扩展近战兵战术或新的专用武器类别。

## 实施边界

1. 敌人共用自己的基础近战能力；玩家与敌人攻击实现仍严格分离。`enemy_melee_controller.gd` 管阶段和请求，`enemy_actor.gd` 管资格、冷却与实际命中。
2. 通过原动作协议增加可选 `melee` 意图，原 AI 仅转交、取消及清理。选择器和统一评分公式不增加动作 ID 分支。
3. 在现有远程接敌 `enemy_tactics.gd` 中增加近战推开方案（`id = engage`、`plan = melee`），不增加默认行为、战术行为或训练勾选项。候选根据已看见的目标、距离、遮挡、冷却与估计推开收益参与 Utility；攻击后交回选择流程，恢复原射击／退让方案。近战兵仍维持原装配，后续可复用敌人执行能力。
4. 玩家自身增加独立近战受击、准度清零和物理击退；两槽精度记忆一并更新，防止切枪绕过受击。原体力、射击与换弹规则继续保留。
5. 敌人表现适配器接入可选近战动画和短暂剑光；动画不决定伤害。敌人没有体力系统，武器该字段标为“仅玩家”。

## 验证要求

- 敌人基础执行使用受击替身测试，无需玩家 Combat；覆盖单次命中、前摇躲避、范围、遮挡、冷却、射击／换弹互斥及取消。
- Utility 实测近距候选和实际选择、远距排除、退让接续、移除发起行为时取消、近战兵不自动启用、复位和暂停；检查同一行为内方案可区分、挥击阶段不能提前切换，以及关闭近战后原方案仍可用。不降低既有性能门槛。
- 玩家受击覆盖两种准度模式、切槽、移动合成、墙体阻挡、死亡和原体力消耗。
- 执行完整敌人回归及相关玩家、表现回归，维护说明随最终结果更新。

## 完成与验证

- 已接入既有行为、意图、服务与身体执行链。远程模板保留原四个默认行为，原战术目录和训练选择保留；近战模板、场景摆放和武器参数没有因本次敌人功能改写。
- 敌人不使用体力消耗字段，检查器显示“近战体力消耗（仅玩家）”，WeaponData 悬停注释和玩法文档明确说明。
- 独立受击替身验证敌人执行24/24项通过，包含可选动画同步、空模型特效、前摇与收招、快照、冷却单一推进入口、权限撤销及死亡复位。
- 层级修正后 Utility 专项15/15项通过：近距退路受阻时按统一代价选中 `engage / melee` 方案，真实推开玩家，之后交回决策拉开距离；远距、失视和冷却排除，删除／恢复接敌行为正确。同一接敌行为内原方案与近战方案可区分，前摇停止主动移动，整个挥击期间停止开火，并遵守中断边界；武器关闭近战后保留原方案。开阔场地原退让候选可能比挥击更优，没有为固定近战赢家改评分权重或绕过选择器。
- 玩家受击专项15/15项通过：伤害、两种准度模式、两槽记忆、30／60／120 Hz 击退、普通移动与锁定横移、受击途中切换瞄准、墙体、对话及死亡清理。补充测试发现普通移动留下的外力可能被下一帧锁定分支当作惯性，已在两个移动入口分离主动速度与当帧外力后复验通过。
- 完整敌人37/37组通过（包含原35组及两组新增）；玩家战斗14/14组通过；表现接口、移动兼容和区域清理3/3组通过。玩家移动边界修正后，玩家整套和敌人 Utility 近战专项再次通过；未重复无关敌人测试。
- 默认行为合同保持原4个，新增断言挥击没有登记到默认／战术目录；没有放宽预算、旧射击或退让测试门槛。测试运行只在内存中配置场地、替身和武器，保留用户当前主副武器与敌人资源调参。

## 2026-09-30 层级纠正

初次实现误将基础挥击登记成独立默认行为；用户指出后，提出移到战术目录仍不符合要求。最终以现有射击调用链为依据纠正：移除误加的 `melee_strike.tres`、`enemy_melee_strike_action.gd` 及其 UID，把近战推开候选与请求接回现有远程接敌行为。底层近战控制器和 actor 接口继续与射击并列，既不是默认行为，也不是战术行为。协调器、选择器与统一评分公式无需增加具体行为分支；文档中的旧装配说法一并修正。

修正后完整敌人回归37/37通过，其中基础执行24/24、Utility 近战15/15；原装配、射击、换弹、退让及性能门槛继续通过。本次未修改玩家运行代码，未重复玩家整套回归；上述玩家14/14结果属于前一阶段。

验证为真实 Godot 主场景的无头运行，未宣称本轮已完成人工手感试玩。日志沿用 `movement_demo/logs/enemy_regressions/` 与 `combat_regressions/`；操作说明见 [近战](../../gameplay/MELEE.md)。近战兵完整循环和专用武器继续留待下一阶段。

## 2026-09-30 正常贴近不出手修复

用户反馈正常靠近时敌人没有近战。新增原场景追近复现：先让敌人正常交战并生成退路候选，再用真实玩家移动输入持续追近。修复前即使长期处于合法近战范围，挥击次数仍为0。旧专项只覆盖堵住退路后胜出；本次最初的临时复现也只在初帧没有退让候选时出手，两者均不足以验证正常交战后的比较。

根因是近战估计按挥击后继续站立计算，还用整个时间窗口的追近量扣除击退距离，退让候选却能获得后续移动收益。修复在现有接敌模块增加带已验证退路的近战方案：前摇停步，出手后收招期间即可退让。空间服务的原路径估计增加可选开始时间，统一计算前摇、移动和火力恢复。协调器、选择器、评分权重、行为资源及训练选择没有因本次修复改写。

新增 `enemy_melee_approach_test.gd` 的5项检查通过，覆盖自主出手、实际命中和击退、收招退让、前摇停步及禁射；已加入正式回归运行器。原 Utility 近战15项与贴近退让专项继续通过，未放宽原有断言。

本次修复后完整敌人回归38/38通过，包含实际追近5/5、近战执行24/24及 Utility 近战15/15，空间查询预算与持续运行性能检查通过；编辑器导入无脚本／资源错误。本次未修改玩家运行代码、场景摆放、武器或训练资源，未重复玩家整套回归。验证仍为真实主场景的无头运行，手感由后续试玩确认。
