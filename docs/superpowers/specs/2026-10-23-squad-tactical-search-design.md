# 团队战术、地图观察覆盖与连续搜索设计

状态：供用户审阅的设计稿，尚未实施，也不代表新增方案已获最终确认。

依据：[协调器完整重写计划](../plans/2026-10-23-squad-coordinator-rewrite.md)、用户随后关于搜索、接敌、队伍推进和抗压避险的反馈，以及“标记 AI 看过的地图面积，由协调器规划尽量覆盖全地图的路线”的最新补充。当前运行接口仍以 [enemy-ai.md](../../enemy-ai.md) 为准；本稿不得作为功能已经实现或验证通过的说明。

## 1. 用户目标与保留边界

用户提出的目标：

- 团队执行应具有细致观察和战术灵活性，范围包括搜索、接敌、掩体利用及队伍推进，不能只补一个掩体朝向问题。
- 队伍记录真正看过的地点和面积，以尽量观察完整地图区域为搜索目标，由协调器据此规划连续路线，沿途查找。
- 搜索先考虑最后合法目击位置，并结合已有合法线索；强配合尽量保持队列，但不能为队列外形而僵硬停走，也不能让先到者抛下后到者。
- 压力过大时保持团队指挥，由协调器及时改派避险任务；抗压值可在训练配置中设置。

沿用已确认的原设计边界：

- 普通、强配合和单人幸存者均由协调器持续指挥，不恢复个人 Utility 选择或旧协调器回退路径。仅情报共享档保持个人决策。
- 训练与装备能力在本场装配时冻结。职责资格是硬条件，默认分工是偏好，具体任务根据现场改变。
- 感知、导航、身体、火控、近战执行仍各自验证真实条件；保留场景节点、引用、UID 和用户修改。
- 目击记忆、声音与不确定 hint 各有来源和时间。隐藏玩家位置仅在已授权 hint 机制的一次采样中使用，不能供覆盖、规划评分、观察目标生成或开火使用。

本稿以下的地图范围定义、数据组织、路线和队形机制属于待审阅设计，不是用户指定的算法或参数。

## 2. 当前实现与问题依据

| 环节 | 当前代码事实 | 对行为的影响 |
| --- | --- | --- |
| 命令移动 | `enemy_action.gd::execute_command()` 在失视移动时将朝向覆盖为移动方向。 | 任务观察方向不能指导沿途检查。 |
| 命令搜索 | `enemy_search.gd::command_work()` 主要在到达单个终点后累计观察。 | 缺少沿路径持续观察、检查盲区与平滑续接。 |
| 区域覆盖 | `squad_search.gd` 围绕线索中心生成有限半径网格，完成一轮后清空重建；区域点的观察目标等于站位本身。 | 缺少长期地图观察记忆和有意义的观察方向，容易重复局部搜索。 |
| 个人搜索 | `enemy_search.gd::facing_direction()` 已区分调查关注点和行进方向；个人覆盖服务已有视角、距离、遮挡校验。 | 存在可借鉴的执行和几何能力，但不能把个人选优入口接回团队。 |
| 强配合同步 | 当前屏障围绕准备点和本轮观察完成建立。 | 能阻止提前换点，但未形成行进中的共同进度与速度协调。 |
| 接敌规划 | `_contact_role()` 大部分时间沿用默认岗位；一般候选以目标周围圆环为主，评分主要累加行程和改派成本。 | 原计划要求的掩护、射界、暴露、信息收益及岗位替补尚不充分。 |

当前 `can_observe_position()` 含近距离全向警觉规则。它适合原感知用途，但不能直接把背后近处算成“朝向正确地看过”。地图覆盖需区分真正视觉检查与近距察觉，复用底层遮挡查询时不能改变原个人感知语义。

已有测试覆盖运行与任务交接，不足以证明地图盲区被细查或战术选择合理。本轮需补充相应行为证据，不能用先前通过数字替代。

## 3. 方案选择与外部参考

建议保留当前队级指挥边界，增加地图观察记忆、连续调查步骤、柔性行进和实际战术收益评价。

单纯把多个现有终点拼成长路径，仍缺少观察内容、覆盖依据和接敌选择。全面更换为通用 HTN 框架会扩大接口迁移及回归范围，目前没有必要。选定方向是在现有职责内提供更完整的规划输入和执行契约。

参考资料与本项目的推导分开：

- Guerrilla 的 [Killzone: Dynamic Procedural Tactics](https://www.guerrilla-games.com/media/News/Files/gdce05_killzone_ai.pdf) 说明战术选位应综合掩护、射界、距离等因素，并把暴露和穿越友军枪线纳入路径代价。本项目据此补足整队方案评价，不复制资料中的权重或新增盲射权限。
- 开发者撰写的 [Hierarchical AI for Multiplayer Bots in Killzone 3](https://www.gameaipro.com/GameAIPro/GameAIPro_Chapter29_Hierarchical_AI_for_Multiplayer_Bots_in_Killzone_3.pdf) 将分层计划与专用选位、路线和具体执行结合，并利用可能藏身的位置辅助搜索。本项目借鉴分层职责，仍保持用户确定的团队决策所有权。

以下共享覆盖与连续路线是面向本项目的设计，不声称上述游戏采用了完全相同的算法。

## 4. 搜索地图与观察记忆

### 4.1 全地图范围

“全地图”拟定义为本次激活战斗区域所辖地图内可供调查的空间，依据现有战斗区、导航和碰撞数据建立；不跨场景、不越过区域权限去搜索其他地图。

搜索由最后目击附近开始，按通道连通关系逐步扩大到剩余区域。团队搜索中的现有 `search_radius` 拟作为初始重点调查范围，不再作为整场搜索的永久边界；仅共享情报档的个人搜索参数含义保持原样。这是显式的团队参数语义调整，实施时必须同步训练说明及相应用例，不能悄悄改变。

导航只用于寻找可站立、可通行的观察位置。覆盖记录需要包含从这些位置可检查的藏身空间和障碍背面；不能只统计导航路径经过的点，也不能把墙体内部当成待走到的目标。

可观察性与可到达性分别记录：不能走进去但能够从外面检查的区域可以产生真实覆盖；既无法到达也无法观察的区域保留未核实原因。临时堵路不减少覆盖率分母，静态不可检查区域单独展示，不能以删除难点的方式声称全图查完。

### 4.2 记录什么

小队持有共同坐标和身份的面积单元，按地图/楼层区分，障碍边缘使用更细的检查样本，避免一个点代表跨墙的整块空间。数据至少包括：

| 数据 | 用途 |
| --- | --- |
| 地图、楼层、单元身份及面积 | 去重并计算覆盖，地图改变时局部失效。 |
| 尚未观察、部分观察、近期已观察、需要复查 | 表达搜查程度；单元局部被遮挡时不能整格完成。 |
| 最近有效观察时间、观察者、累计有效时长、已覆盖部分 | 保留真实检查依据，支持队内共享及后续复查。 |
| 当前是否有人监视 | 区分“曾看过”与“现在有人看着”。 |
| 调查优先级及来源 | 来自最后目击、声音、不确定 hint、未查通道和观察年龄。 |
| 可达/可观察情况及失败原因 | 区分暂时拥堵、导航失配和确实无法检查。 |
| 计划中的调查责任与短期预约 | 减少队友重复工作；预约不算已观察。 |

面积覆盖与“怀疑玩家在哪里”分开。新 hint 改变优先调查区域，不能凭提示清空历史观察，也不能把提示位置标为已看见。

覆盖记录由本小队协调器统一接收。跨小队记录仅能沿既有合法通信关系共享，保留来源与原时间；不同小队仍各自持有计划，不因为使用同一地图就自动共享所有观察或合并指挥。

### 4.3 何时算看过

由成员的真实位置、姿态、朝向、视距和环境遮挡计算，并在有效观察持续达到条件后上报；行走、减速和停留时都可积累。接敌或巡逻中产生的有效观察也能贡献带时间的记录。

检测针对环境中的可藏身空间，不读取隐藏玩家身体作为探针。看见墙面、墙顶或露出的地面不能自动证明其后站姿/蹲姿藏身空间已查清。部分可见单元只记录可见部分，后续路线补查剩余盲区。

观察报告携带成员与任务身份、地图版本和原时间；协调器拒绝失效、重复计数或与真实执行不符的报告。普通成员不能靠报一个 `observed=true` 完成覆盖。视野共享也不授予个人开火权限。

### 4.4 看过以后

已观察记录保留，不在每轮搜索结束后整图清零。玩家可能经未受监视的通道返回，因此“近期查过”不等于永久安全。

拟结合观察年龄、新声音/目击、相邻未查通道及当前监视情况提高复查优先级。先推进重要的未查区域；已有区域只有在新的风险或检查老化确有意义时才重新竞争，避免全队困在高频局部循环。

当前可检查区域完成一轮且没有新线索时，按既有持续警戒方向进入低频复查和出口观察；报告本轮完成，但保留历史记录，不把无法检查的部分说成已清空。

## 5. 从观察地图生成连续路线

规划单位是“能看清一片区域的观察位置与路径段”，不是“每个格子都必须走到”。

协调器在已查与未查交界、拐角、掩体两端、出入口及其他合法观察位置生成候选，估计新增覆盖面积、线索价值、行程、暴露、等待和重复检查成本。先满足训练资格、可达性、身体间距等硬条件，再比较完整小队方案。

从候选中串接多个有意义的调查步骤，形成较长的区域巡查路线。优先顺序受最后可靠线索和连通关系引导，再向地图其余未查区域扩展。路线包含具体观察内容，不能仅按直线距离串最近的格子。

路线提前规划多段，但只预约即将通过的短路段和必要站位。后续步骤可根据新观察、动态障碍或新线索修订；有效的当前段保持连续，避免每次更新都让全队掉头或重置观察进度。

每个步骤至少包含：

- 移动路径、有效任务身份及其地图/线索版本。
- 应观察的区域、随进度变化的观察目标和必要姿态。
- 正常通过、边走边查、需要减速或短停检查的执行方式。
- 实际观察结束条件、必要的队伍条件及失败反馈。
- 下一步骤与中断后的恢复条件。

规划中的预计覆盖只参与比较；正式覆盖只由真实观察更新。后续区域已被队友查清时，协调器跳过或替换相应步骤，避免重复走完整条过时路线。

重新目击玩家时及时转入接敌；受压、换弹、近战和让路保留原有执行规则。身体占用结束后由协调器判断续接、修订还是废弃旧段，不能直接恢复已经失效的长路线。

## 6. 行进与细查执行

移动方向与观察目标分别下达。沿墙前进时注意可能出现人的边缘，绕过拐角时随着视野打开逐步扫查后侧；前后成员可以分担前方、侧面和后方观察，减少全部看向同一点。

具体执行复用现有身体转向、移动、姿态和火控。个人搜索中成熟的关注点和几何计算可提取为无决策权的共用能力；团队不能调用个人 `collect_candidates`、评分、选优或自主调查流程来完成任务。

短暂停留由待核实盲区和真实观察条件决定，不能每经过一个导航拐点就停一次。因为转向过快、墙体遮挡或队友挡住观察而未查清时，保留该部分进度并请求调整观察位置，不用停留计时冒充观察。

## 7. 强配合的柔性队列

协调器维护共同路线进度及各成员相对前后位置。领行者按队伍间距调节速度，后方成员沿可行路径跟进；不能仅因自己完成一个观察点就独自转入远处下一段。

开阔位置可错位展开，狭窄通道收成纵队；实际身体间距和可通行空间是硬条件，理想队形位置是软目标。临时偏离槽位完成必要观察后归队，槽位被障碍占据时换位或调整队形，不强行挤到指定坐标。

共同检查入口、需要协调暴露的拐角等步骤仍有明确的参与者与就绪屏障。普通沿途扫查使用连续进度与队伍距离协调，不对每一个面积单元设置全员屏障。早到成员可以在本步骤允许的范围继续观察或担任有效警戒，不能跨越尚未放行的关键步骤。

有人受阻时区分正常通行等待与无进展：调整前员速度、通行顺序、观察责任或路线；修复必须改变造成失败的条件。换弹、避险及无关接敌者不因为队形而被迫停火，缺员后重新计算分工。暂时没有有用观察/射界者不得以“掩护”标签无限盲站。

## 8. 接敌与掩体战斗同步补足

战斗候选除了当前有效射击位置，还应包含训练允许的掩体边缘、低墙站蹲位置、接近通道、侧向射界及安全换弹位置。候选数量和查询开销有界，不能只扩大圆环采样数量。

整队方案比较至少表达：有效射界和可持续火力、推进收益、暴露时间、身体与枪线冲突、行程与等待、弹药/换弹、压力与改派成本。模板提供初始岗位偏好，实际人员可替补；不能用“支援”名称替代真实视野和火控就绪条件。

正常交战即考虑利用掩体；已有抗压机制负责危险升级后的优先避险，不作为使用所有掩体行为的唯一入口。探出、开火、撤回、换弹与队友接替构成有条件的执行过程，不能只给一个躲藏终点。

保持现有真实近战反应、受压请求、空匣换弹、不能打断的身体动作和信息权限。有效射手继续执行，避免因为其他成员路线更新而全队停止射击。

## 9. 代码职责与接口方向

| 位置 | 拟承担的责任 |
| --- | --- |
| `squad_coordination.gd` | 唯一团队任务所有者；目标、全队提交、异常重排及战斗/搜索切换。 |
| `squad_search.gd` | 搜索目标、合法 hint、调查优先级、覆盖与路线服务之间的编排。 |
| 新的独立地图覆盖服务 | 面积单元、真实观察记录、历史时间及地图变更；不控制身体、不选择个人动作。 |
| 新的独立搜索路线服务 | 基于覆盖、地图和队伍能力生成有限多段路线及预计收益；不直接下发任务。 |
| `enemy_team_planner.gd` | 比较完整且满足硬条件的全队方案，补足战术收益和动态职责匹配。 |
| `enemy_search_formation.gd` 与 `squad_traffic.gd` | 几何候选、柔性行进约束、必要屏障、短段通行和让路；不保存另一份搜索事实。 |

正式文件名和字段在实施计划中确定。服务依赖地图数据和纯值快照，实例由现有协调器持有；不新增另一套区域循环、全局团队指挥器或场景节点。

## 10. 性能、生命周期与调试

- 地图采样、可见性估计和多段路线分预算准备；真实感知和当前动作持续运行。沿用现有每成员候选准备约4毫秒、区域准备约0.5毫秒的实现预算作为起点，实际整队开销仍需验证，不能直接相加后宣称通过。
- 静态地图结果按版本缓存；当前朝向、身体占位、观察与枪线必须实时核对。预算耗尽时保留有效任务及未完成工作，不能算覆盖完成或放权。
- 成员死亡、离区、换队和场景重开清理相应任务、预约与监视身份；地图观察保留范围按当前战斗生命周期管理，不泄露到下一场。
- 地图几何改变局部失效相关可达性和观察结论；新的目击改变调查优先级，不凭空重建一份全部已知的玩家轨迹。
- 地面调试展示未查、部分查、近期查过、待复查、无法检查区域，以及未来路线和实际观察方向；计划覆盖与真实覆盖有不同显示。调试只读，不触发导航、补观察或刷新记忆。

## 11. 行为与结构验收

| 场景 | 必须验证的行为 |
| --- | --- |
| 实体墙与转角 | 背面仍未查；真实转向并获得视线后才更新。近距离背后不能仅凭警觉半径算看过。 |
| 部分遮挡、低墙及小藏身角 | 不因一个中心点可见或看见墙顶而整格完成；盲区进入后续检查。 |
| 长路线沿途检查 | 移动中确有朝向变化和新增覆盖；导航普通拐点不强制停步；必要盲区确实减速/检查。 |
| 当前战斗地图 | 从线索附近向远处未查区域推进，能够走出原 `search_radius`；覆盖以独立面积样本和真实遮挡核对，不只统计自身标记。 |
| 多人协作 | 不把预约当已查，减少同一区域重复分配；重排保留有效观察历史，hint 更新不清空整图。 |
| 强配合开阔处与窄口 | 队列随空间调整，有人落后时前员响应；关键步骤等齐且不丢参与者，普通路段不会逐点全队等待。 |
| 静态不通与临时堵塞 | 不伪造覆盖、不从统计中删掉困难点；明确标注原因，并在条件改变后重新检查。 |
| 玩家折返及新线索 | 曾看过区域可重新可疑，队伍不依赖隐藏玩家坐标决定复查目标；关闭 hint 后仍能持续推进。 |
| 接敌、换弹、避险、近战 | 实际射界者能战斗，盲站者改派；正常交战利用掩体，受压由团队改派，身体和真实命中规则保留。 |
| 普通/强档、减员与重载 | 个人 Utility 计数仍为零；训练能力、模板生命周期、情报来源和旧反馈隔离继续成立。 |

既有保存地图重新接敌8秒、整队 AI 与区域耗时 P99 <16毫秒/峰值<50毫秒等适用门槛保留。新增较大地图覆盖用例独立定义覆盖面积与连续进展要求，不能借扩大地图放宽原复现的限制。

旧“每轮所有搜索点都等待”的断言需按用户新的灵活队列要求调整验证对象：保留关键步骤全员就绪、早到者不能越过未放行步骤及受阻恢复，补充连续行进时的队伍距离与前后响应；不能简单删除等待检查。测试变化必须连同语义理由审查。

运行验证同时保留用户原场景与训练资源；新增地图场景用实例输入或独立夹具，不为了通过测试改变用户布局。只修改本阶段明确涉及的文件，维护 README、项目结构、敌人使用说明及验收记录时区分已实现结果与本稿建议。
