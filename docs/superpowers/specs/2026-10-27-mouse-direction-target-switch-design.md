# 鼠标移动方向换锁设计

日期：2026-10-27。状态：设计草案，尚未实施。本次仅整理文档，不修改运行逻辑。

目标：保留现有锁定与自动跟枪，让玩家在按住瞄准时，通过一次明确的鼠标移动选择另一侧的敌人，解决当前目标难以主动切换的问题。

## 1. 用户要求与建议边界

用户已明确的方向：

- 战斗仍以锁定目标为主，选中后继续自动跟踪。
- 多个目标存在时，读取鼠标的移动方向来换锁，不要求鼠标始终指在敌人身上。
- 改善一近一远时锁到远处敌人、又难以切回近处敌人的情况。
- 保持现有自动锁人的逻辑，只增加主动切换入口；不调整先锁谁、后锁谁的自动选择规则。
- 沿用项目现有职责划分，保持结构简单、接口清楚，不堆叠重复逻辑。

下文的一次拨动只切一次、触发距离、允许换锁的范围与方向夹角、鼠标捕获，以及换锁时精度如何衔接，均是本设计的建议方案和建议初值，不能当作用户已逐项确认的要求。本文也不表示功能已经可用。

## 2. 当前实现与问题来源

当前行为以 [player_combat_v3.gd](../../../movement_demo/scripts/player/player_combat_v3.gd) 和 [player.gd](../../../movement_demo/scripts/player/player.gd) 为准：

- `begin_frame()` 保留仍然有效的 `locked_target`，只有没有有效目标时才调用 `_find_target()`。这保证锁定稳定，也使玩家缺少主动切换入口。
- `_find_target()` 主要比较敌人与角色朝向的吻合程度。本次保持它现有的筛选、评分和平局处理，不加入近处优先或其他新排序。
- 目标仍须满足屏幕可见、武器锁定距离和身体可见点的视线检查。
- 锁定后角色自动朝向目标；未锁定时，现有移动逻辑影响角色朝向。当前没有用鼠标相对位移选择目标的输入链路。

[战斗说明](../../gameplay/COMBAT.md)、[游玩说明](../../gameplay/PLAY_GUIDE.md) 和开局介绍中涉及“鼠标方向瞄准”的文字，需要在实施时按真实行为统一。本文不提前把未实现的操作写进当前游玩说明。

## 3. 操作规则

建议仅在按住右键瞄准、已有有效锁定目标时识别换锁手势。鼠标小幅抖动不会换锁，明确向某个方向拨动才发出一次换锁请求。

方向以**当前目标在屏幕上的位置**为参照，比较其他目标相对于它的位置；不以玩家位置、鼠标指针当前位置或世界坐标轴为参照。

| 当前情况 | 玩家操作 | 预期结果 |
| --- | --- | --- |
| 锁住 A，B 在 A 的屏幕左侧 | 向左拨动鼠标 | 切到 B，随后继续自动跟踪 B |
| 锁住 A，B 在 A 的屏幕右下方 | 向右下拨动鼠标 | 优先选择右下方向内的合格目标 |
| 拨动方向没有合格目标 | 明确拨动一次 | 保持 A，不改选反方向目标 |
| 只有 A 一个合格目标 | 向任意方向拨动 | 保持 A |
| 玩家没有拨动鼠标，B 走得更近 | 继续按住瞄准 | 保持 A，不自动抢锁 |
| 已切到 B | 停下鼠标，随后再拨动 | 可以再发起一次换锁 |

“近处敌人”不一定在屏幕下方，实际仍按相机投影判断。例如近处 B 位于远处 A 的左下方，玩家向左下拨动即可表达切向 B 的意图。

鼠标移动不直接驱动准星自由游走，也不要求把光标拖到 B 身上；换锁成功后沿用现有准星和目标跟踪。滚轮原有切枪用途保留。

## 4. 手势识别与防误切

建议采用两个简单状态：允许识别、等待鼠标停顿。

1. 允许识别时，累积鼠标在视口坐标中的相对位移向量。使用净位移，不累加移动路径长度；触发前的反向抖动会相互抵消。
2. 净位移长度达到触发距离时，用其方向生成一次请求，并立即进入等待停顿状态。
3. 无论这次是否找到可切目标，都消费本次手势。继续沿同一方向移动不会一路扫过多个敌人，也不会在目标随后进入该方向时突然换锁。
4. 鼠标连续停顿达到重置时长后，清空累计位移，允许下一次拨动。未达到阈值的小手势在停顿后也清空，避免几次无关抖动拼成一次换锁。

停顿判断应容忍极小输入噪声，按实际经过时间计算。不同帧率下，同一鼠标轨迹应得到相同次数的换锁请求；视口缩放后的坐标单位应统一，不能把物理像素与逻辑像素混用。

鼠标事件只负责收集输入，请求在现有战斗帧流程内统一处理，安排在本帧射击读取目标之前。不要在每个输入事件中直接修改 `locked_target`。

以下情形清除累计位移和待处理请求：松开瞄准、首次取得锁定、目标失效或自动重获目标、切枪、暂停、失去窗口焦点、进入阻断战斗输入的界面、死亡或重开，以及现有逻辑已经中断瞄准的近战／翻越阶段。不要把开始瞄准前的鼠标移动带进第一下换锁。

换弹期间是否允许换锁沿用现有瞄准许可，不为这个功能新增取消换弹的行为。

## 5. 候选目标与排序

候选必须沿用现有合法性规则：仍在场景中、仍是有效战斗目标、位于屏幕内、处于当前武器锁定距离内，并通过原有身体可见点和视线检测。过滤当前目标、待删除目标及无效投影。

### 换锁范围：周围可切，每次只认一个方向

建议将“允许主动换锁的总范围”与“一次拨动的方向范围”分开：

| 范围 | 建议规则 | 参照 |
| --- | --- | --- |
| 主动换锁总范围 | 玩家周围 360°，仍受屏幕可见、武器锁定距离与原有视线检查限制 | 玩家与候选目标的空间位置 |
| 单次拨动方向范围 | 拨动方向左右各 45°，合计 90° 扇区；半角可调 | 当前目标在屏幕上的位置 |

玩家向左拨动时，只找当前目标屏幕左侧扇区内的合格敌人，不会因为总范围允许 360° 就选到右侧。方向内没有候选则保持当前目标，不自动扩大方向范围。玩家侧面或背后的敌人只要满足上述合法性条件，也可以通过明确拨动主动切过去。

主动换锁不额外套用首次锁定的角色朝向锥角。否则角色正朝向 A 时，侧面或背面的 B 可能一直被排除。360° 是本方案建议，不代表允许锁住屏外、超距或被墙完全遮挡的敌人。

**现有自动锁定入口保持原样。** 首次取得目标、当前目标有效时继续保持、失效后重新选敌，全部沿用原规则。以下方向排序只用于鼠标主动换锁，不写回 `_find_target()`，也不改变它的锥角或先后优先级。

方向计算使用同一台游戏相机，以及与锁定标识一致的目标瞄准点。令 `D` 为鼠标净位移方向，`V` 为当前目标投影指向候选目标投影的方向，二者夹角必须在允许范围内。屏幕纵坐标方向也须一致，不能出现向上拨却选中下方目标。

建议排序步骤：

1. 排除方向夹角超过允许半角的目标。
2. 找出最贴近拨动方向的夹角，再收集与它相差不超过小容差的候选。
3. 在这一组中优先选择离当前目标投影最近的敌人，减少轻微角度差导致跳过身边目标的情况。
4. 仍相同时，以玩家到敌人的距离和稳定的目标标识依次打破平局，避免依赖分组遍历顺序。

方向容差建议先用内部常量 5°，不立即扩展成一组检查器参数。真正写入锁定前再核对所选目标有效性；失败则保持仍然有效的原目标，不把旧请求套用到自动重获的目标上。

候选扫描只在首次选敌或一次换锁请求发生时进行。现有锁定有效性检查照常运行，不因新增功能而每帧重新对所有敌人做完整可见性检测。

### 一近一远与投影重叠

对于屏幕位置可区分的近远敌人，方向换锁可以直接解决切换意图的表达。对于投影完全重合或过于接近的两人，方向向量没有可靠意义，应忽略这种候选关系，避免随机跳锁。

这不能保证仅靠方向输入选中投影完全重合的远处敌人。第一版应明确这一限制，不为了覆盖该边界修改原有自动选敌优先级，也不自动增加轮换按键或复杂的深度选择模式。

## 6. 检查器与鼠标边界

建议将控制手感参数集中放在玩家 Combat 的“目标切换”分组，不散落到每把武器。保留三个主要接口：

| 建议显示名 | 建议初值 | 含义 |
| --- | --- | --- |
| 换锁触发距离 | 32 逻辑像素 | 一次净位移至少达到多长才发出请求 |
| 换锁方向半角 | 45° | 候选相对拨动方向允许的最大偏差 |
| 换锁手势重置时间 | 0.12 秒 | 停顿多久后允许下一次拨动 |

这些数值用于第一轮试玩，不是已确定的平衡参数。检查器帮助需写明单位、适用对象及手势重置含义。

武器既有锁定距离、首次锁定锥角继续使用原接口。主动换锁的周围 360° 范围先按规则实现，不再增加第二个角度配置；检查器中的“换锁方向半角”只控制单次拨动的方向范围。武器“跟枪免罚半角（仅玩家）”控制目标移动造成的精度损失，与这里的角度用途不同，不复用字段，也不互相覆盖。

为避免鼠标到达窗口边缘后无法继续向外拨动，建议在右键瞄准期间临时捕获鼠标，使用相对位移；退出瞄准时恢复原模式。暂停、菜单及失去焦点时应由现有界面输入流程决定鼠标模式，不能被战斗脚本抢回。恢复位置产生的合成移动不应触发换锁。

临时捕获属于待实施验证的交互建议，需要核对当前 UI 和窗口行为；不能将其扩大成全程隐藏鼠标或额外的镜头旋转控制。

## 7. 精度、射击与爆头衔接

建议第一版只改变目标选择，沿用当前精度的连续状态，不额外加入换锁奖励或惩罚：

- 切换时更新目标、瞄准点和目标移动跟踪基准，保留当前准度、精度恢复等待、射击间隔、弹药与换弹状态。
- 不调用会退出瞄准或限制精度的 `cancel_aim()` 来完成换锁。清理锁定与设置新目标的共用逻辑应只有一处，避免新旧路径各维护一份状态。
- A 与 B 之间的空间距离不算作“同一敌人的突然移动”，切换后从 B 的位置重新建立跟踪基准。随后 B 的移动、玩家移动和玩家受击继续按原规则影响准度。
- 爆头几率及菱形提示立即依据新目标和当前准度重算；A 的近战眩晕破绽不能带到 B 身上。换锁本身不消耗任何敌人的破绽。
- 按住开火时，后续射击使用当时已接受的锁定目标；换锁不额外生成一枪、不重置射击冷却。实际命中仍由原有弹道、遮挡与伤害逻辑决定。

保留精度有利于快速响应，也可能增强高准度下连续转火的能力。实施后的平衡试玩应检查这一点；如果确实需要换锁精度代价，应单独明确规则，不能在开发中悄悄清零准度或借用错误的目标位移惩罚。

## 8. 结构与职责

沿用 [项目布局](../../project-layout.md) 和现有玩家战斗职责：

- 玩家输入路径只收集鼠标相对位移及必要的输入状态，不自行计算爆头或伤害。
- 玩家 Combat 统一决定换锁时机、候选选择和锁定状态更新；复用现有可见性与瞄准点来源，不复制一套判定。
- 锁定表现读取同一个最终目标，不维护独立的“鼠标选中敌人”。本轮方案不要求新建 UI 层级或给敌人添加换锁组件。

手势状态与方向排序可先作为职责明确的小函数实现；只有现有文件确实难以阅读时，再抽出无场景依赖的小辅助模块。不要为这一个输入功能新增全局目标管理器、敌人广播、平行状态机或复杂的可替换策略层。

保留原有节点路径、脚本 UID、资源引用及已有本地调参。若实施后出现被替代的重复入口，应在核对所有调用方后移除，不能留下两套同时生效的选敌接口。

## 9. 实施验收清单

以下均是未来实现需验证的项目，本次文档提交不代表已经通过运行测试。

- **方向与空间：** 左右、上下、斜向、多相机朝向均正确；玩家周围包括侧后方的合法目标可以主动切换；默认单次方向半角为 45°，边界内外判定明确，没有候选时不扩大范围；近远敌人按投影位置可切，投影重合时不随机跳锁。
- **防误切：** 小幅抖动、未过阈值的往返不换锁；一次连续移动经过多个候选只切一次；方向无候选也须停顿后才能再试；分开的两次拨动可以连续切换。
- **原锁定逻辑：** 同一场景没有鼠标换锁请求时，首次选敌、保持锁定、目标失效后的重选结果与原实现一致；其他敌人变近也不会夺走有效锁定。已有相关测试继续成立，不能为新功能修改自动选敌规则或删除保持锁定的约束。
- **候选合法性：** 屏外、超距、墙后、死亡、移出场景的目标不能选；半身遮挡仍沿用原可见点规则；目标在输入后失效不会产生陈旧锁定。
- **输入生命周期：** 不同帧率与视口缩放、窗口边缘、暂停、界面、失焦、切枪、近战、翻越、死亡及重开均无残留手势或错误鼠标模式。
- **战斗状态：** 换锁保留建议约定的准度与等待时间；不把两目标间距算成移动惩罚；射速、弹药、换弹与实际遮挡不变；新目标的破绽和爆头标识同步更新。
- **结构与文档：** 只保留一个最终锁定状态和共用合法性来源；新增检查器参数集中且说明清楚，没有与跟枪免罚角度混用。

实施时按 [测试说明](../../testing.md) 选择已有玩家战斗、目标跟踪、可见性、武器切换及爆头相关回归，并补充能覆盖手势识别和实际换锁行为的专项。原自动选敌只做回归核对，不调整排序，不能通过放宽旧断言掩盖行为变化。

功能落地后同步战斗说明、游玩说明、开局介绍、涉及的新文件职责与测试入口。换锁范围、鼠标捕获和最终参数需据实际实现记录，不能把本文建议直接写成已完成事实。
