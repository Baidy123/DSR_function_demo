# 无效配置清理与可复用敌人场景设计

日期：2026-09-29

状态：已按用户澄清收敛为竞技场内复用；本设计待用户审阅，尚未开始实现。

## 1. 用户目标与约束

用户希望检查现有项目，清理没有实际作用的 Training 参数、接口和声明，精简代码结构，并将敌人制作成可直接拖入现有竞技场使用的独立场景，省去复制既有敌人分支或手工创建节点。

已确认的决定：

- 采用“清理遗留代码＋有限模块化”，保留当前玩法及统一 Utility 评分。
- 敌人只放置／生成在战斗区域内，区域默认提供导航。拖入现有竞技场即可使用，继续入场激活、离场复位。用户最新澄清替代此前“未绑定区域也默认运行”的设计。
- 必须避免误删正在使用的内容。引用少、没有直接函数调用、当前训练未启用，都不能单独作为删除依据。
- 当前工作区的场景、兵种、训练及搜索提示调整是迁移基准；不得用 Git 旧版本或脚本默认值覆盖。

本轮覆盖自有运行代码、配置资源、场景、自有检查器及测试。第三方插件依赖保持完整。近战伤害、多敌人协同、真实音频等新玩法仍按原待办处理。

## 2. 审查结果与删除证据

第一轮扫描覆盖58个自有运行脚本，并交叉检查场景路径、UID、资源属性、对话资源、编辑器插件和测试。下表是实施前需再次确认的候选清单，不是自动删除清单。

| 候选 | 当前证据 | 处理方式 |
| --- | --- | --- |
| `tactics.ranged_flank_weight`、`ranged_wall_support_weight`、`ranged_wall_probe_distance` | 仅声明、存储和覆盖记录，当前接敌算法没有消费点 | 删除字段、旧说明及资源中的对应存储值和覆盖键 |
| `selection.away_from_threat_weight`、`closer_to_threat_weight`、`cover_quality_weight` | 仅由未被当前运行流程调用的 `choose_cover()` 使用 | 连同旧评分入口清理；保留统一 Utility 风险、火力和信息权重 |
| `exit_suppression.target_radius` | 出口动作覆盖了区域选点及相关查询，当前按真实端部通道生成目标 | 只删除出口配置中的无效字段；普通压制的同名字段仍有效，必须保留 |
| `choose_cover()`、`get_reload_cover_candidates()`、`get_engagement_candidates()` | 当前运行改用预算化候选查询，未发现这些同步入口的消费者 | 确认动态调用及测试引用后移除，不删除仍被其他服务调用的底层算法 |
| `EnemyUnitType.has_action()`及其专用查询包装 | 未发现消费者 | 复核后删除；保留仍被身体使用的枪械能力查询 |
| `EnemyMemory._utility_rejection_threat` | 仅声明，未发现读取或更新 | 复核后删除 |
| Training 的旧拼接属性 `_legacy_key/_get/_set` | 运行脚本已使用资源接口，仍有测试通过旧字段名设置参数 | 先迁移全部调用，再删除兼容层 |
| UnitType 的旧 `combat_type` 设置接口、搜索中的旧证据转发 | 仍有正式或历史测试调用 | 先迁移到兵种资源／公共记忆，再评估删除；不直接断开有效测试 |
| 旧 `has_clear_shot_cone()`及专用缓存 | 当前射击使用 FireController 三维查询，两个历史测试仍调用旧入口 | 对照现行射界测试补齐有效断言，再删除被替代入口及重复测试 |

明确保留的例子：

- `GameState.help_choice` 等字段由 `.dialogue` 动态读写，不能只扫描 `.gd`。
- `get_attack_candidates()`、`assess_attack_point()`、调试查询等仍参与有效验证；若替换，必须先迁移这些消费者和断言。
- `shot_radius` 被公共近弹感知读取；即使移动组件上的同名转发可删，训练字段不能删。
- `track_sight_angle_degrees` 被感知服务读取；不能因搜索动作内部不使用其代理属性就删除配置。
- 基类动作协议、信号回调、工具脚本回调、`action_overrides` 等通过动态机制调用，保留其有效契约。
- 搜索提示的模式及当前覆盖值有明确使用需求；本轮不因某一模式当前未选中而删减。
- `NoiseData.audio_stream` 是原文档记录的音频预留且有资源保存测试；本轮保留并明确标注尚未播放，不能把它冒充当前已生效功能。

## 3. 防误删规则

每个删除项都需记录“定义、消费者、资源持久化、替代实现、验证结果”。删除依据如下：

1. 检查直接调用、继承覆盖、`get/set/call/has_method`、字符串方法名、信号连接和分组调用。
2. 检查 `.tscn`、`.tres`、脚本 UID、对话及自有插件；同名参数须区分所属配置组。
3. 确认当前资源、动作默认参数、训练覆盖键和编辑器保存都不再需要该字段。
4. 对只有测试使用的入口，先判断测试是否验证独有行为；有价值的断言先迁移，不能为删代码而删掉保障。
5. 有任何未查清的动态消费者时保留并记录原因。测试通过是补充证据，不代替调用链审查。

实施时将最终删除清单和保留原因写入维护说明。禁止依据静态扫描结果批量删除所有“零引用”符号，禁止为让回归通过而放宽断言或性能门槛。

## 4. 可复用敌人场景

新增 `res://scenes/enemy/enemy.tscn`，根节点继续是 `CharacterBody3D`，复用现有身体、兵种、训练、AI和导航组件。

```text
Enemy
├── UnitType
├── Training
├── AI
│   ├── Perception
│   └── Cover
├── NavigationAgent3D
├── Body
├── CollisionShape3D
├── FrontMarker
└── Label
```

保持 `UnitType.profile`、`Training.profile` 和根节点武器的配置入口，支持场景实例覆盖和保存，不新增另一份同义配置存储。敌人场景提供可用的默认配置，竞技场当前敌人的覆盖值在迁移时保留。共享编辑器资源及运行时深复制语义保持不变。

实际使用方式：在编辑器中将 `enemy.tscn` 拖到现有 Arena 下，摆放在 CombatZone 内且导航可站的位置；可以直接作为 Arena 子节点，也可以放进 Arena 下的 Enemies 容器。拖入后自动使用这个竞技场的战斗区域和导航，不要求为每个敌人重新配一套地图节点。

环境连接沿用现有上下文和区域控制脚本，不新增敌人 `Environment` 节点：

- 区域控制脚本提供本区域 CombatZone 和 NavigationRegion3D 的统一查询入口。
- 上下文初始化时向上查找最近的所属区域控制节点，取得并保存引用；各动作继续通过公共上下文使用。
- 敌人向所属区域注册，退出场景时注销，以便区域统一复位直接子节点和容器内的敌人。
- 缺少所属区域、区域导航未就绪或出生点无效时给出明确提示；不能自动改用全地图其他区域，也不能在每帧重复输出同一问题。

### 4.1 激活与复位

始终遵循所属竞技场的规则：玩家进入才启用，最后一名相关玩家离开后恢复该区域内敌人的出生状态。暂停、死亡、对话和配置撤销继续走原动作生命周期。不提供无战斗区域时的自由激活模式。

敌人持有自己的出生变换、运行状态和区域关联。同一区域离场可一起复位该区域内多个敌人，其他区域的敌人不受影响；各实例的血量、弹药、配置快照和动作进度仍独立。

现有 `shooting_range.gd` 统一负责区域对象复位，增加对已注册敌人的处理，避免依赖敌人必须是直接子节点；训练靶的原有复位继续保留，同一个对象不能被重复复位。区域被释放或敌人被移到不具备有效区域的层级时安全停用并清理动作。卸载场景导致的 `body_exited` 不应重新启动或复位已出树对象。

### 4.2 导航与掩体范围

导航来自所属竞技场，无需敌人扫描全地图寻找最近导航，也不增加逐个敌人手动选择导航区域的步骤。等待该区域导航同步后再开始相关行动；区域导航被移除或替换时取消受影响的行动、清理路径与空间缓存，然后等待本区域恢复。

巡逻、搜索、接敌、掩体、出口压制和调试预览继续使用本区域范围。保留当前导航投影误差、到达要求和掩体归属规则，不跨其他战斗区域选择目标。

出生位置必须位于所属战斗区域内且有可用导航；错误放置时提示并停用，不自动挪动敌人、不转成全地图活动模式。不在本轮新增刷怪器或随机生成机制；本轮实现的是可拖放、可实例化的敌人场景。

继续使用当前项目的玩家接口、`player` 组及 DebugSettings 等公共系统。没有玩家时安全待命，玩家及导航就绪后按区域规则运行。

### 4.3 现有竞技场迁移

用场景实例替换 `arena.tscn` 中的内嵌 Enemy 分支，保留名称、位置、朝向、武器、兵种、训练及 Utility 参数的当前有效值。实例自动使用竞技场提供的原战斗区域和导航；地图几何及玩家配置不因提取场景而改变。

保留脚本 UID及对外需要的节点路径。验证主场景嵌套实例、编辑器实例覆盖、保存重载和两个敌人复用同一场景的行为。

## 5. 有限模块化与配置可读性

### 5.1 搜索

保留一个搜索动作参与统一评分，内部拆为以下职责：

- `enemy_search.gd`：调查／追踪／搜索阶段，候选、执行、中断及证据事件。
- `enemy_search_hints.gd`：已有提示概率、衰减和误差位置计算；仅沿用配置允许的隐藏位置提示，不增加新的信息来源。
- `enemy_search_coverage.gd`：搜索采样、覆盖进度和下一目标选择。

两个辅助脚本放在 `scripts/enemy/services/`，由每个搜索动作独立持有；明确传入上下文和参数，不访问其他可选动作实例，不引入全局可变状态。动作保留对生命周期及阶段转换的唯一控制权。

拆分保留原提示调用频率、随机取样时机、覆盖目标、受阻恢复和中断边界。组件输出交给动作处理，不各自启动其他战术。通用导航投影通过环境／空间服务完成，不复制一套寻路规则。

### 5.2 Training与资源

仍有效的参数补齐单位、作用对象、生效条件及消费者说明。公共射击参数、近弹感知参数等不能因为位于某个历史分组，就被解释为仅在对应战术解锁后生效。

删除字段时同步清理资源存储值与 `overridden` 中对应键，其他覆盖值及顺序保持。保持训练显式覆盖、动作定义参数、默认值／调用回退的现行优先级，保持 `mark_override`、运行时配置刷新和资源深复制。

历史资源中的 `null` 值或与默认值相等的条目先核实实际加载结果和覆盖语义，不能按文本形式批量清除。本轮以当前仓库资源迁移为交付范围，不增加永久的旧字段兼容系统；确有当前消费者时先迁移。

### 5.3 其他模块

逐项清理确认无效的声明和包装，避免只为减少文件大小合并身体、武器、感知、记忆和动作。保持独立动作、共享服务、配置资源的现有边界，不重写选择器和评分公式。

## 6. 测试与验收

现有正式入口为24套敌人回归、8套战斗回归及单独运行的检查器验证。历史脚本是否属于正式清单不是唯一保留标准；对使用失效旧接口的脚本，建立“迁移、已被覆盖后删除、仍有独有价值需保留”的逐项记录。

新增或迁移的验证要求：

| 方面 | 必须验证的行为 |
| --- | --- |
| 配置清理 | 删除字段不再显示／保存；有效值、覆盖优先级、动态扩展和保存重载保持 |
| Training调用迁移 | 测试辅助改用资源接口，保留原断言，不靠兼容转发继续通过 |
| 独立场景 | 直接拖入现有竞技场后自动取得区域和导航，入场后能感知、寻路和实际开火 |
| 区域绑定 | Arena直接子节点和Enemies容器、入场激活、离场复位、再次入场及场景卸载；同区一起复位、跨区隔离 |
| 导航与放置 | 使用本区域导航、延迟同步、缺失／移除导航、出生点在区域外或不可站立时安全停用 |
| 实例隔离 | 两个敌人的配置快照、动作、射击及复位互不串扰 |
| 场景迁移 | 原竞技场摆放与有效配置保持，嵌套场景及实例覆盖保存后正确恢复 |
| 搜索拆分 | 真实目击证据、提示衰减、静止玩家、覆盖完成、卡住恢复及调查不中断 |
| 既有行为 | 两种压制评分与出口通行、掩护撤退、换弹及玩家战斗保持 |
| 性能 | 保留空间查询预算和现有20毫秒门槛；检查环境绑定不造成每帧全地图扫描 |

结构迁移完成后运行完整敌人和战斗回归，并核对检查器结果；编辑器模式现有退出资源警告按已知基线单独记录，不与断言通过混淆。

文档同步更新 `docs/enemy-ai.md`、`docs/enemy-tests.md`、`docs/project-layout.md`，补充独立场景接入步骤、有效参数说明及删除清单。交付时区分自动回归、编辑器验证和人工试玩结果。

## 7. 实施边界与完成标准

实施按“保存基线与审查证据、迁移测试消费者、清理确认无效项、提取敌人场景和环境连接、拆分搜索、综合验证”的顺序分批进行。每批具备独立可检查的差异，发现有效消费者时撤销该删除候选或先补迁移，不通过修弱测试解决。

完成标准：敌人场景可直接拖入现有竞技场，在战斗区域内摆好位置后沿用本区域导航和激活规则，无需复制既有敌人分支或手工重建节点；有效配置仍生效；已删除项都有无用证明或已验证的替代路径；正式测试和有独有价值的历史保障已维护；用户当前配置改动完整保留。

本设计审阅通过后再编写实施计划并确认执行方式，当前文档不代表运行代码已完成修改。
