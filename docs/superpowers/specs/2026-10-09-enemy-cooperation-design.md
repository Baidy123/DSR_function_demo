# 敌人协作、情报共享与战术压制设计

日期：2026-10-09。

状态：用户已授权按本方案实施，并追加分工搜索和主动协调换弹。实现与验证状态见 [实施计划](../plans/2026-10-09-enemy-cooperation.md)；本规范本身不是测试通过记录。

同日后续修正：用户明确要求移除左右出口和单人轮扫，保留本人真实失视点的一波扫射，以及近身、掩护队友和自身撤退时的压制；共享坐标本身不构成盲射理由。本页下方出口能力是首版设计历史，已被这一明确指示取代。当前规则见 [敌人 AI](../../enemy-ai.md#评分与射击节奏)，修复与验证记录见实施计划末尾。分工搜索、主动协调换弹及未来阵营／兵种扩展方向继续保留。

## 1. 已确认方向与本文性质

用户提出并在讨论后认可的方向：

- 同一战斗区内，敌人的基础情报共享默认具备；个人仍独立判断真实视线与攻击资格。
- 预留分组／阵营关系接口，为未来多方混战隔离情报和合作；新情报及任务关联具体目标身份。
- 高层合作包含分散站位、交叉火力、换弹／撤退掩护、部分推进部分掩护、牵制包抄以及掩体出口分工；高级合作沿用训练解锁。
- 压制允许在目标可见时参与 Utility 竞争；评分应认识帮助队友的价值。
- 合并出口压制的独立行为入口，保留可靠出口识别、选点和封锁能力。
- 近战与远程通过接近、牵制和射界互补合作；未来按能力与局势分工，不维护兵种两两配对表。
- 沿用兵种提供行为、训练解锁、个人 Utility 选择、身体执行的结构，引入轻量协作服务。

下文的具体数据契约、评分表达、迁移策略和验收分层属于实施设计，不代表用户逐项指定了接口名称、公式或默认数值。原文档中的现行行为在代码迁移完成前仍然有效。

## 2. 现状与本次范围

当前每个敌人有独立 Context／Memory，所谓共享记忆主要供本敌人的行为共用。竞技场已有成员登记与区域复位。普通压制及出口压制都要求失视或合法近距准确情报；目标可见时被候选、提交和执行检查排除。出口压制由单人轮流射击两端，尚无多人认领。现有掩护撤离是自身边射边撤。

共同评分目前由个人火力缺失、暴露、信息损失及已有显式情境偏好组成。近战掩体接近、短程突进、枪械射击、导航与空间查询可作为合作的执行基础。

本规范定义基础协作机制及首批战术，不把以下内容一并宣称为已设计完成：完整多方选敌、阵营友伤规则、复杂指挥官系统、整队全局路径规划、救援／复活，以及新枪械兵种本身。

用户最新确认将分工搜索与主动协调换弹纳入本次。前者认领不同调查点并临时共享实际检查过的地面样本；后者在低余弹且友军确有可用火力时增加可评分的提前补弹方案。原有单人搜索和空匣换弹保持独立可用。

## 3. 结构与职责

采用战斗区内的共享情报和任务服务，个人行为继续自主产生候选并参与统一评分。纯个人反应容易重复选择同一射界；整队指挥器需要额外的调度与失败恢复。本方案用有限任务认领协调重复工作，保留原决策结构。

| 部分 | 职责与边界 |
| --- | --- |
| 战斗区宿主 | 沿用成员注册、注销、激活与复位；拥有本区域协作服务的生命周期 |
| 关系接口 | 查询敌对、情报共享与协作资格；不决定具体动作 |
| 区域协作服务 | 保存报告、友军公开状态、短期请求与认领；过滤权限、去重、释放；不向身体发送移动或开火命令 |
| 每个敌人的 Context | 保留个人证据，提供经过权限过滤的共享快照与协作接口；不暴露友军动作实例 |
| 行为模块 | 生成分工候选，选中后申请任务，执行本人的移动／射击等意图；失败后交回原决策 |
| 共同评分器 | 按共同时间窗比较个人代价和可验证的协作收益；不按具体战术 ID 指定赢家 |
| 身体／武器／感知 | 保持原射界、弹药、姿态、近战、碰撞与真实目击规则 |

基础情报共享是公共服务的默认能力，不作为抢占接敌或搜索的 Utility 动作。高级协作通过兵种战术目录和训练装配；禁止用全局协作服务绕过训练限制。

新运行服务放入现有 `scripts/enemy/services/`，新战术放入 `scripts/enemy/actions/`，配置遵循现有 `config/` 与资源目录。保留场景节点路径、现有脚本 UID 和已保存资源引用；不重排既有模块。具体拆分在实施计划中落实。

## 4. 区域、阵营与目标接口

共享首先要求双方属于同一有效战斗区，然后通过通信资格检查。初始规则为同阵营允许共享及合作；跨阵营默认不共享、不合作。敌对关系由独立查询决定，不能用“不同阵营必定敌对”推导中立或结盟行为。

概念接口为 `is_hostile(observer, target)`、`can_share_intel(sender, receiver)` 和 `can_cooperate(a, b)`。阵营标识属于实例身份，现有敌人缺省归入同一敌方阵营。小队／通信组可在未来缩小合作范围；首批不增加独立的小队编辑、无线电距离或完整外交系统。

所有报告、请求、认领和支持状态包含稳定的 `target_id`。目标身份可关联弱引用以检查对象有效性，但不能通过它读取未经感知授权的实时位置、姿态或换弹进度。共享快照只携带已获授权的数据。

运行身份与战斗区复位代际共同防止旧任务误关联重生对象。甲目标的情报、射界占用和压制事件不能覆盖乙目标。改变阵营、共享资格或战斗区时，立即退出不再合法的协作域，释放认领并撤掉来自该域的共享授权；自身真实观察仍属于个人证据。

当前 Context、感知和开火链路仍以唯一玩家为主要对象，实际敌人子弹也有面向玩家的命中处理。本阶段的多目标数据结构与关系过滤不等于完成多方混战。后续还需改造目标选择、感知对象、攻击目标及伤害关系。

## 5. 情报与友军状态

### 5.1 报告内容

基础视觉报告包含：目标身份、原始观察者、原始事件／序列、观察时间、有效期限、当次已观察位置与可用运动信息、证据类型及可信度。转发保持原来源和时间；同一事件不会因为接收、候选重评或再次转发续期。

至少一个合法友军保持真实目击时，可以发布更新的观察快照。所有观察者失视后，已有报告保留最后快照并衰减，禁止继续跟随隐藏目标。新的有效观察可以替换旧报告；接收顺序不能让旧报告覆盖新报告。

首批共享真实视觉及从该视觉合法取得的短时观察事实，例如观察到的换弹动作。声音、概率搜索提示和低墙近距准确事件维持原证据等级；本阶段不把这些来源广播升级为团队视觉报告。后续若共享其他证据，须独立声明其调查、压制和直接攻击权限。

原观察者真实看到换弹结束或取消时，发布同一目标较新的失效事实，接收者撤销对应机会；晚到的旧换弹报告不能恢复已被否定的事件。仅仅失视时继续按原短时观察证据衰减，不读取目标隐藏的剩余换弹时间来宣布结束。

### 5.2 个人观察与间接情报

共享报告不设置接收者的 `sees_player`、个人 `has_visual_memory` 或真实 `last_seen`。个人真实观察与队友报告分别保存，行为通过明确的已知目标查询取得当前可用证据及来源。

直接瞄准可见身体点和近战出手仍要求本人的感知与执行复核。共享报告允许规划、调查和基于已知射界的压制；接收者不会自动获得穿墙射击资格。共享精确位置也不能授权读取隐藏的目标身体采样。

本方案建议合法团队目击报告使接收者进入交战警戒；用团队接敌证据记录原因，不伪造个人目击。沿用接敌后持续搜寻方向，区分持续警戒与有限位置可信度：报告变旧后仍可搜索，但不能无限续接精准压制。仅有声音或模糊提示的普通调查保留原结束规则。

报告者离场不使其过去的真实观察变成虚假，但停止产生新报告；旧快照仍按原期限与来源规则使用。死亡、区域刷新等清理沿用相应生命周期；暂停冻结任务和证据使用的活跃时间。

### 5.3 友军公开状态

友军可以主动发布自身的换弹、撤退／转移意图、当前目标、位置、可用射界和预计支持窗口。通过公共状态接口取得这些事实，不访问友军可选动作实例或控制器私有阶段。

友军公开的自身换弹与敌对目标的换弹证据分开：后者仍须真实观察，不能因为未来目标也使用同类 Actor 就读取其隐藏内部状态。

## 6. 请求、认领与有效支持

任务描述至少包含战斗区代际、协作域、目标、任务类型、受益者（如有）、射界／位置槽、有效期限和版本。支持请求表达“谁需要在何处获得多长的帮助”，不直接命令其他敌人切换动作。

认领必须满足以下协议：

1. `collect_candidates` 和空间预评估只读任务快照，不创建请求或抢占岗位。
2. Utility 选中方案后，在提交／开始阶段重新校验资格、目标、路线与版本，再原子认领对应名额。
3. 同一互斥岗位的并发申请最多一个成功。申请失败者不执行未获授权方案，交回原决策；有限轮转或稳定仲裁避免某一实例永久占优。
4. 认领只承诺有限时段。候选刷新不重启执行进度；有效执行可在规则允许范围内报告剩余状态，但不得无限延长同一旧证据的压制窗口。
5. 取消、结束、死亡、离场、关系变化、目标失效和撤销训练时释放；服务持有的旧实例引用不妨碍显式注销。超时清理作为失联回退。

同一任务的候选身份由行为、方案、目标、射界／角色、支持请求共同确定。已经认领的左侧岗位不会仅因本轮采样顺序改变就变成右侧；沿用个人保持时间与切换优势。任务有效期不替代身体对换弹、近战和翻越的中断限制。

支持分为请求、已认领、已就绪／执行和结束／失效。只有枪械资格、弹药、瞄准、真实枪线及当前执行满足时，才发布可用的射击支持；近战威胁使用自己的接近与攻击资格判断，不冒充枪械支持。

推进动作可在自身安全位置选中有限等待方案，再发起支援请求；等待、建立射界和后续移动都计入共同时间窗。尚未建立支援时，不凭对方承诺降低自身路线风险。等待到期或支援失败后，重新比较独立移动、搜索或其他合法行为，不无限互等。

支持者换弹、射界被堵、改换目标或受到中断时发布失效并请求相关成员重评。推进者根据当前位置决定继续到安全点、停留或撤离，不能瞬移回起点，也不能强行取消已经进入原子执行阶段的身体动作。

## 7. 首批合作行为

| 行为 | 方案与成立条件 | 失败／结束 |
| --- | --- | --- |
| 分散站位／交叉火力 | 比较已有攻击位及有限侧向候选；计算实际新增射界、可达性、暴露和拥挤；已有有效正面射界的人可保持 | 路径、射界或目标证据失效则重评，不为角度好看强行移动 |
| 换弹／撤退掩护 | 围绕真实友军需求，选择有意义的目标或射界；正常接敌火力也可履行支持 | 需求完成、支持失效或自身紧急状态时结束 |
| 交替推进 | 有效射界保持者提供短时支持，推进者移动到下一处有效位置；到位后再比较是否交换职责 | 不强制按固定顺序轮换；无人支援时保留独立行动与有限等待 |
| 牵制／侧向包抄 | 通过有限可达侧向位置形成与现有射界互补的攻击方向；计真实路线和到位后的效果 | 首批不保证绕到背后；无收益、过远或过险时放弃 |
| 掩体两侧分工 | 对可靠识别的出口分别认领；监视与开火分开，按需要选择压制或等待观察 | 出口堵塞、归属不明或证据变旧时结束封锁，再由原候选竞争 |
| 分工搜索 | 既有搜索认领调查点；共享真实视角、距离与遮挡检查通过的地面采样 | 取消、超时、失效释放；负证据短期过期，不计为本人覆盖或永久排除区域 |
| 主动协调换弹 | 低余弹、可补装、有实际支持窗口时由 Utility 比较提前补弹；提交时原子占用非紧急换弹名额 | 支持失效时重评，已开始的真实换弹遵守原中断规则；空匣紧急换弹不受名额禁止 |

首批使用现有位置查询与分帧预算；不为包抄同步搜索整张地图。高墙出口与低墙同点蹲起规则保持区别，不能为了双侧合作给低墙虚构侧向 Peek 点。

近战与远程通过同一任务系统协作：远程压力为近战接近创造机会，近战迫使目标改变位置后，远程重新评估射界。近战已在有效威胁范围时可为远程换弹争取时间，远离目标时不因掩护请求强制冲锋。

持续掩护主要看弹药、射程、有效射界和持续时间；推进看路线、暴露、移动能力及到位后的攻击效果；出口观察看观察与反应条件。未来手枪、步枪、霰弹枪兵复用这些条件，具体武器名称不作为任务调度分支。

协作路线与射击意图检查友军占位／枪线冲突，必要时换位或暂缓射击；本设计不引入新的友伤玩法。避免挡枪也不授权子弹穿过友军身体。

## 8. 压制与共同评分

### 8.1 压制候选与执行

统一压制提供可见目标、合法已知区域、左出口和右出口等方案。可见性决定证据和瞄准方式，不再统一否决整个行为。合法武器、训练、枪线、射程、弹药与有限证据仍是硬条件。

可见目标方案遵守本人视觉授权和正常开火反应；不能通过把普通交战改名为压制绕过反应、机械射速或连射停顿。压制可表达维持某一射界的火力意图，火控对稳枪与开火的比较需纳入该意图并统一验证。

失视方案使用冻结证据。保留每个失视／准确事件的有限窗口，普通重评、可见性切换和切换动作不能重启旧窗口、清空连射计数或刷新换弹进度。队友持续真实观察可以提供新快照；重复传播同一报告不产生新机会。

自己主动躲藏导致的失视，不自动制造新的目标失踪证据。若另有真实、有效的支援请求与授权情报，可以生成独立合法的支持方案；它不能借用这次自身失视无限续时。

压制以实际弹道、持续威胁及出口封锁产生作用。玩家已有近弹准度损失，墙体隔开时不触发；不新增强制蹲伏、减速或“正在压制便必定削弱目标”的状态。

### 8.2 协作收益的提案

保留现有个人三项代价和已明确的情境偏好，增加公共定义的协作收益项。下式的原个人代价仅指火力缺失、暴露和信息损失的加权和，不包含偏好信用。概念公式为：

`共同代价 = 原个人代价 - 原情境偏好 - 协作权重 × 有效协作收益`

有效协作收益以共同评估窗内的“有效支持秒数”表达，限制到该时间窗；由需求剩余时间、预计可执行的支持时间、有效射界质量、证据可信度及该需求尚未被满足的比例共同限定。具体权重和响应曲线属于实施调参，不能写成用户指定值。

该收益是可比较的战术支持估计，不是假定玩家必然停止还击。支持候选可以预测自己到位后提供的帮助，但必须扣除转移、转枪、换弹和建立支持所需时间；接收者在支持实际建立前不能将预测当成已生效保护。

普通接敌、压制及其他能完成同一支持任务的合法候选使用相同收益口径。原地正常开火已足够时，不强制切成压制。没有实际受益需求或新增有效射界时，收益为零；单位独处时保留合理的个人行为竞争。

同一目标、受益者、支持目的、射界范围和重叠时段内的同一效果只计一次。左右两端若都是必要射界，分别计算各自尚未满足的需求，左侧已有支持不能吞掉右侧需求；合计仍遵守共同时间窗的收益上限。不能既扣掉同一份队友暴露代价，又完整领取该效果的支持收益，也不能按队友总人数无限叠加。

评估某个候选的边际收益时，先从已有支持中排除该敌人本人的贡献，再估计选中该候选后新增或继续保留的效果。这样正在履行任务的支持者不会因为自己的火力已满足需求，就在下一轮把自身收益清零并无故撤走；其他敌人仍只得到剩余需求对应的收益。

弹药不足、预计即将换弹、已覆盖射界和路线冲突减少实际可支持时长或候选资格。动作只提交结果估计；统一评分器结算，不在动作内添加任意最终分数，也不伪造个人暴露和信息事实以强制合作。

调试记录分别显示个人代价、协作收益、受益任务、目标、射界、证据来源和当前支持状态，便于解释“为什么这次掩护比移动更值得”。

## 9. 出口压制合并与配置迁移

保留 `enemy_cover_selection` 中可靠归属、完整身体通道、动态阻挡、射程与枪线检查。普通区域压制和出口方案继续使用公共环境推断参数，不把几何职责放回可选出口动作的参数资源。

统一行为可以在多人数情况下分别认领左右射界；单人仍可选择守单端或有限轮换。监视某一出口不等于向该出口持续开火，两者以具体需求和共同代价比较。

迁移设计：

- 旧 `suppression` 与 `exit_suppression` 的显式解锁合并为统一压制并去重；保留其他兵种的隐藏显式选择。兵种目录及相关 `includes` 同步迁移，去掉合并产生的自包含，维持原通用装配协议。
- 本方案选择让统一压制解锁包含所有合法选点方式。因此旧普通压制独有的配置将增加合法出口候选，这是明确的能力范围变化；不会强制选择出口。旧出口压制配置继续拥有原有点压制和出口能力。
- 保留点压制的 `target_radius`、`low_cover_point_preference`，出口每侧枪数作为单人轮换方案参数保留。共同环境推断仍归 Selection。
- 若旧点压制与出口压制的持续时间配置不同，保留为统一动作内部各方案的持续时间设置；不得任取一组覆盖另一组。旧动作定义中的模式默认和训练显式覆盖分别保留。
- 保留参数覆盖来源及 `overridden` 语义，沿用已有 `action_overrides` 优先级；默认值不改写为用户显式覆盖。打开检查器或预览本身不自动保存迁移。
- 现有 `arena.tres` 显式启用出口压制、普通压制靠包含取得，两组持续时间均未显式覆盖。当前保存的连射枪数和停顿属于原 Tactics，必须保留；“每侧几枪换端”与武器／训练连射节奏分别处理。
- 运行装配可读取旧格式并生成兼容的有效配置，序列化迁移通过明确的资源更新完成；迁移应幂等。确认引用与兼容入口后再移除独立运行实现，保留继续使用的脚本和资源 UID，不批量删除旧测试。

迁移阶段同步更新现行 AI 使用说明、训练面板说明和对应测试；本设计阶段仅登记未来方向，不把当前说明提前改成已实现的新行为。

## 10. 生命周期、性能与回退

区域服务在原成员注册／注销和复位处接入，禁止借全局单例跨战斗区传播。共享资源只存静态配置，任务、证据缓存、执行计时和认领保存在区域／敌人实例。

状态变化触发有关成员重评，避免每帧广播全部候选或把每个敌人与全部地图位置做笛卡尔积。共享静态几何可复用，但射界、目标身份、证据版本、成员姿态与动态占位须进入适当缓存键或复核条件。沿用原分帧查询与真实执行复核。

服务不可用、无可合作对象、任务已满或目标证据过期时，个人接敌、搜索、换弹和已授权战术继续竞争。协作任务失败不能清空原导航系统、重置全体敌人，也不能恢复已经撤销的行为。

保持既有运行与查询门槛，按实测记录多敌人总帧耗时、共享传播和任务评估开销。现有文档仍有性能波动记录，本设计不将单敌人历史通过等同于多人性能已合格。不得通过增大既有门槛或减少有意义断言掩盖回归。

## 11. 验收分层

以下是设计验收边界，不是编码实施计划，也不是已通过记录。

| 层次 | 必须证明的结果 |
| --- | --- |
| 共享与关系 | A 真实目击、B 隔墙时，B 得到可调查报告但自身视线仍为假；同区不允许共享的双方、不同区的同阵营均不串数据；不同目标互不覆盖 |
| 证据 | 所有人失视后移动隐藏目标不改变共享快照／压制点；转发不续期；旧报告不能覆盖新报告；共享换弹后真实观察结束可撤销机会，旧包晚到不能复活；各证据类型不越级授权 |
| 认领与生命周期 | 候选收集无认领副作用；同槽并发只有合法名额成功；重复评估不重启动作；死亡、离场、暂停、复位、撤权和阵营变更符合清理规则 |
| 支援真实性 | 尚未转枪、空匣或枪线受阻时不能声明有效火力；支持中断触发推进者重评；无人支援不会无限等待；支持者重评保留自身边际价值，新增者不重复领取全部收益；身体动作遵守原中断限制 |
| 压制 | 可见状态下通过正常 Utility 自主选中有价值的支持方案；普通交战也能贡献支持；失视后使用合法冻结点；保持真实子弹、反应、转枪、射速、换弹和停顿 |
| 空间合作 | 两人能取得互补射界且不抢同槽；无安全可达侧路时放弃；两端任务分别关联同一可靠掩体，堵塞或归属歧义时退出；保留隐藏位置隔离 |
| 近远程与扩展 | 远程支持后近战通过真实路线接近并实际出手；友军枪线冲突可恢复；同类兵也能合作，不靠具体武器名称配对 |
| 配置与结构 | 缺省身份、训练权限、资源深复制、覆盖来源、保存重载、撤销／重做、旧配置迁移与新动作扩展保持正确；主循环无具体战术分派 |
| 性能与回归 | 覆盖 1、2、3 及 6 名敌人的冷启动、持续战斗、失视与动态阻塞，记录总帧成本；运行必要完整敌人回归及受影响的玩家弹道／准度回归 |

首批可玩验收场景为三人协作：A 保持正面有效火力，B 向侧面有效位置推进，C 根据需求补射界或支援换弹；目标进入掩体后可以分担出口或继续推进。验证须由正常感知、候选、Utility 和身体执行完成，不能强选动作来证明自主合作成立。

另设打断场景：支援者被打断或出口动态封堵后，其他成员合理重评；保留单人场景作为回退对照。协作应有可观察的建立过程和真实弹药空档，玩家能通过改变位置、阻断路线或打断支援者破坏合作。

验证入口遵循 [敌人测试](../../enemy-tests.md)。涉及公共协议、装配与评分时按原要求完整回归，保存失败及基线对照；不改用户地图、训练与武器来迎合测试。每个可独立验收阶段完成并同步文档后，按仓库规则审查、提交和普通推送。

## 12. 后续扩展边界

协作后续方向只保留多方混战与新增兵种后的协作优化，见 [后续总待办](../../TODO.md)。分工搜索和主动协调换弹已纳入本次实施范围。训练预设只是保存战术勾选及参数组合的便利配置，现有 Training 已可直接配置，当前不列为必做扩展。
