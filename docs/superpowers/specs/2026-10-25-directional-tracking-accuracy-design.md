# 玩家跟枪精度：按目标横向移动计算

日期：2026-10-25。状态：**已实施并通过本轮必要验证，已移除文件名的 `_todo` 后缀。**

用户本次已授权实施这份待办。已完成原玩家跟枪流程的方向修正；爆头仍是独立待办，本次未实现。使用入口与后续方向见[射击说明](../../gameplay/COMBAT.md)。

## 1. 用户要求

敌人沿玩家瞄准方向靠近或远离时，不应因为自身移动持续扣除玩家精度；斜向或横向移动才带来跟枪困难。

这里的方向是**玩家到当前锁定目标的连线**，不是敌人的身体朝向，也不是屏幕固定的上下左右。

| 目标相对瞄准连线的移动 | 预期效果 |
| --- | --- |
| 直线靠近玩家 | 不产生目标移动精度损失；允许按原规则恢复 |
| 直线远离玩家 | 与靠近相同，不因反向而扣精度 |
| 大致平行，只有轻微路径抖动 | 应有小范围容差，避免一直阻止恢复到最准 |
| 斜向移动 | 只按横向部分计算；越接近横向，影响越大 |
| 左右横穿瞄准线 | 保留明显跟枪损失，左右对称 |
| 原地转身，位置不变 | 不产生目标移动精度损失 |

“不扣精度”只针对目标移动这一项。玩家自身移动、射击、受击、压制、换弹等已有影响仍生效；目标直线靠近不会让精度瞬间变满。

## 2. 修改前的问题根源

修改前的实现位于 `movement_demo/scripts/player/player_combat_v3.gd`：

- `_apply_target_movement_accuracy_penalty(delta)` 使用目标两次位置之间的完整三维距离，不区分前后与横向。
- 按该距离计算目标速度，在武器的慢速／高速每米损失之间插值，再逐米扣精度。
- 只要移动超过很小的距离阈值，函数便返回 true，即使目标只是直线靠近。
- `end_frame()` 根据这个返回值限制恢复：目标移动时，当前精度若低于跟枪下限，只能恢复到该下限；达到或高于下限则停止正常恢复。

因此需要同时修正**损失量**和**恢复资格**。仅将平行移动的损失乘零，却继续返回“目标在移动”，仍会阻止恢复到最准，不能算修复完成。

新锁定时已有位置初始化，解除锁定时已有清理；继续复用，不增设另一条跟枪时钟或目标跟踪组件。

## 3. 已实现的计算方案

以下按原方案实现。最初采用5°作为实现初值，随后用户要求15°。2026-10-27用户进一步要求25°并将接口加入枪械瞄准检查器，且明确仅玩家使用时有效；当前默认25°半角，由每把枪保存。

### 3.1 只提取目标自身的横向位移

以地面的 XZ 平面计算。用目标本帧与上次采样位置的差得到位移 `d`，用玩家到目标的地面方向得到单位向量 `u`：

```text
纵向位移 = u × dot(d, u)
横向位移 = d - 纵向位移
横向距离 = length(横向位移)
```

靠近与远离只改变纵向部分的正负，横向距离都为零。斜向移动只保留横向部分。不要按敌人面向计算，也不要使用相机的屏幕坐标来决定惩罚。

当前计算约定：以本次采样时的玩家位置为固定参考，使用目标前后位置的中点构造 `u`，减少取一端方向造成的偏差；投影后再更新目标位置记录。只计算目标自身位移，不将玩家位移减入目标速度或额外算作目标位移。玩家自身移动继续由原分支处理，本轮不改成双方相对速度模型。

用水平位置计算可避免目标站蹲的头部高度变化被算作横向跑动。本轮不另增垂直跟枪惩罚、距离倍率或视角角速度模型；原每米参数及瞄准点选择保留。

### 3.2 给“大致平行”留出小容差

纯数学投影会让很小的侧向抖动仍返回“需要跟枪”，恢复仍可能长期受限。现加入相对前后连线的免罚半角，**按用户最新要求默认两侧各25°，合计50°**。前后方向对称，角度范围外连续增加横向权重。

采用的连续映射：

```text
横向占比 = 横向距离 / 目标水平总位移
容差占比 = sin(免罚夹角)
有效横向权重 = clamp((横向占比 - 容差占比) / (1 - 容差占比), 0, 1)
有效横向距离 = 目标水平总位移 × 有效横向权重
```

这样容差内为零，超过边界后逐渐增加，纯横向保持原距离。免罚角为0时退化为普通横向投影。免罚角必须限制在远小于90°的合法范围，避免除零或让所有跟枪损失消失。

检查器入口：**武器资源 → 瞄准与散布 → 锁定 → 跟枪免罚半角（仅玩家）**，脚本字段为 `WeaponData.tracking_parallel_tolerance_degrees`，默认25°半角、范围0～45°。玩家三种枪械瞄准分支读取当前枪的配置；敌人不读取，敌人内嵌武器检查器及近战武器隐藏该项。原 Combat 导出项移除，已有武器未保存新字段时使用默认25°，不批量改写资源。0表示纯横向投影，数值越大，前后方向附近的免罚范围越宽。

### 3.3 扣除量与速度一致

使用**有效横向距离／实际有效帧时间**作为目标跟枪速度，再按原 slow／fast／fast_speed 插值；损失为有效横向距离乘插值后的每米损失。

不能已经排除了纵向距离，却继续用总跑速选择高速惩罚，否则一个快速迎面冲来、略微偏斜的敌人仍会受到不成比例的跟枪惩罚。相同位移的斜向目标损失应低于纯横向；由于速度插值，最终损失不必与方向夹角严格线性。

## 4. 恢复逻辑必须一起调整

原函数的布尔结果应表示**本帧存在有效的目标横向跟枪影响**，不再表示“目标位置发生过变化”。

- 平行／容差内移动、无有效位移或跟枪损失配置为零：不扣目标移动精度，返回无跟枪影响，让原恢复流程继续。
- 有有效横向影响：保留原跟枪下限与恢复限制；若精度已因受击等低于下限，按原规则逐渐恢复，不直接抬高到下限。
- 从横向转为平行后解除该项恢复限制；仍等待射击、受击等已有恢复延迟，不清空其他来源的等待。
- 玩家也在移动时，仍受玩家自身移动限制；只解除不再存在的目标跟枪限制。
- 更新调用处变量和注释，使维护者不会再将它误解为任意目标运动。原方向修正不要求新增武器接口；2026-10-27按用户要求将半角配置移入 WeaponData，仅玩家消费，AI 与协调器保持。

## 5. 生命周期、兼容与范围

- 无锁定、新锁定、换目标、失锁、切枪、对话、死亡和重置沿用原清理入口，首个位置样本不扣精度，不将两个不同目标的位置差算作移动。
- 零帧时间、重合方向和极小位移应安全处理；更新必要的位置基线，不除零，也不把无效方向变成任意一条轴后施加惩罚。
- 暂停不累计移动损失；恢复运行后不补算一段不存在的跟枪移动。测试传送／复位使用原清理入口，不将跨场景跳点当成正常跑动。
- 概率模式、散布锥模式与霰弹稳定度统一使用本次方向判定，各自的每米损失、下限和恢复速度继续通过原 `get_aim_settings()` 获取。
- 霰弹固定图样、每颗随机偏差、逐发装填、弹药与伤害均不在本次修正范围。
- 本轮针对**敌人移动对玩家精度的影响**；不顺带修改敌人瞄准玩家的精度、AI 移动策略、个人 Utility 或协调器。
- 保留原节点路径、资源引用、UID 和用户已有调参。参数说明应写清“玩家侧按有效横向距离”；共享资源不能误标为敌人也已改用该算法。
