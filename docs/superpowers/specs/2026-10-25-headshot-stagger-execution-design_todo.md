# 爆头扩展：低概率秒杀、防护训练与强硬直

日期：2026-10-25。状态：**设计待办，本轮只改文档，不实施以下运行规则。**

前置版本见[概率爆头](2026-10-25-headshot-mechanics-proposal.md)。当前运行代码仍是默认50%概率、2.5倍伤害、霰弹逐颗判定；没有爆头秒杀、防护训练开关或强硬直。本文件记录用户随后提出的新方案，实施后才替换对应规则，不能把两版叠加执行。

## 1. 用户最新明确的方向

- 保留玩家达到最准精度、真实弹道命中后才判定爆头的前提。不做身体部位分伤，不增加瞄准等待；先只作用于玩家对敌人。
- 爆头概率比当前值更低；触发后，支持爆头秒杀的敌人直接死亡。**具体概率尚未指定。**
- 敌人可以配置是否支持爆头秒杀。关闭时仍能触发爆头，但改为倍率伤害，**默认普通伤害的3倍**，不是爆头免疫。按用户最新补充，倍率也必须在武器资源外部可改，不能硬编码为3。
- 爆头对存活敌人施加强硬直，停止其动作；硬直时长可在武器中配置，后续可接动画。
- **秒杀开关放在敌人训练配置中**，用于区分小混混、戴头盔的特工等。用户也允许考虑战术配置，不放在每把攻击武器上决定敌人是否有防护。
- **霰弹改为一枪对每个实际命中的敌人只判定一次。** 同枪命中多个敌人时分别判定，未命中的敌人不参加。
- **武器侧相关参数必须可直接在武器资源文件中修改，并留外部脚本接口。** 包括开关、概率、秒杀选项、兜底倍率、硬直秒数及刷新规则；敌人防护仍由其训练配置管理。
- 本轮只更新文档。新参数、预设、秒杀、强硬直和霰弹判定次数均暂不改运行代码。

## 2. 结算顺序

1. 沿原开火门槛和弹药流程，记录开火前有效精度、武器爆头概率、强硬直时长等本枪快照。
2. 执行原射线。打空、被墙挡住、射程不足不产生该敌人的伤害或爆头；原“瞄甲打乙”按实际命中的乙结算。
3. 普通枪对这次实际命中判定一次；霰弹先查完所有弹丸并按目标统计，再对每个命中目标判定一次。只有最准时才掷爆头概率。
4. 未触发时按普通伤害处理，继续原命中干扰和减速。
5. 触发时结合武器是否启用秒杀与敌人实际训练防护分支；下表倍率按默认3倍举例，自定义武器使用其配置倍率：

| 敌人配置／结果 | 伤害结果 | 强硬直 |
| --- | --- | --- |
| 武器启用秒杀，且敌人支持爆头秒杀 | 经原死亡流程直接死亡，不受剩余血量影响 | 不进入存活硬直，死亡表现优先 |
| 武器关闭秒杀或敌人不支持，倍率伤害后仍存活 | 普通伤害×武器倍率，默认×3 | 使用本枪硬直时长 |
| 武器关闭秒杀或敌人不支持，但倍率伤害已经致死 | 正常伤害致死 | 不在死亡后追加硬直 |

6. 同一个目标只结算一次受击／死亡与表现通知。秒杀不得再补一次3倍伤害，不沿用旧2.5倍继续相乘；普通命中干扰、枪声、射速、扣弹和后坐不按倍率或弹丸数重复执行。

秒杀需要走原生命、死亡信号、波次减员和尸体流程，不能直接删除节点或用任意大伤害冒充完整死亡协议。训练靶仍只计数；测试靶的秒杀模拟方式留到实现时显式规定，不为训练靶伪造敌人训练。

## 3. 配置归属与操作入口

### 武器：概率与硬直时长

在原 WeaponData 的“精准爆头（仅玩家）”分组内扩展，不另做一套武器系统：

| 配置／拟用字段 | 约定 |
| --- | --- |
| 启用爆头 `headshot_enabled` | 延续原开关 |
| 爆头概率 `headshot_chance` | 每枪可调；新初值待定，检查器继续显示百分比 |
| 启用爆头秒杀 `headshot_instant_kill_enabled` | 武器侧开关；与训练允许值共同决定是否秒杀。关闭仍可爆头，走配置倍率与硬直 |
| 未秒杀时伤害倍率 `headshot_damage_multiplier` | 延续原公开字段，下一版默认3.0，允许外部修改；旧显式值的兼容处理必须明确，不能检查器写2.5而实际暗用3 |
| 爆头强硬直时长 `headshot_stagger_seconds` | 新增秒数；建议0关闭硬直，正值决定持续时间 |
| 连续爆头硬直刷新方式 `headshot_stagger_refresh_mode` | 导出枚举；可配置建议为保留较长剩余时间／按新时长重新计时。默认项待定，不把刷新策略写死在身体代码 |

硬直秒数未由用户指定；0.6秒可作为试玩建议，**尚未确定为默认值**。3倍是兜底倍率默认值，用户最新要求覆盖了先前固定3倍的文档表述。上述字段名是接口建议，并未全部存在于当前脚本；不额外加入破甲概率或第二次抽签。

### 外部编辑与接口要求

- 所有上述武器参数使用公开导出属性，保存到原 `.tres`；检查器、外部资源文件编辑和脚本设置使用同一份数据，不隐藏在 Combat 常量、私有变量、动画或训练资源里。检查器提供单位、合法范围、默认值和悬停说明。
- 外部脚本可加载／持有原 WeaponData 后读取或设置字段。修改一个武器实例时仍按原共享资源规则先复制或设为唯一；修改共享资源会影响所有引用者。保存到文件需显式保存，不因运行中修改而自动覆盖用户资产。
- 建议提供统一 `get_headshot_settings(stability)` 纯值快照接口；原概率／倍率查询可作为兼容入口保留。快照包括资格、概率、武器秒杀开关、兜底倍率、硬直时长及刷新方式，校验非法值并统一单位。
- 下一枪读取最新武器参数；本枪一旦开始便使用自身快照，受击回调或外部修改不能改变它剩余目标的倍率、概率或硬直。
- 敌人允许值通过原训练显式覆盖／装配查询取得，不由玩家访问敌人训练内部私有字段；身体提供统一执行入口和状态查询给个人AI与协调器。训练冻结规则仍有效，外部编辑武器不等于热更新整场训练。
- 硬直执行及反馈接口应接收已确定的结果和参数，不读取全局当前武器，也不让动画决定伤害／秒杀资格。原伤害与死亡接口应兼容，不能要求所有旧目标立刻实现新参数才能被普通子弹击中。

### 敌人：训练中的被动防护

建议入口为 **Enemy → Training → Profile → tactics → 爆头防护 → 支持爆头秒杀**。沿用 `enemy_training_profile.gd`、`tactics_settings.gd` 的配置归属与显式覆盖规则，不在身体、武器和动作实例各存一份开关。

| 训练示例 | 支持爆头秒杀 | 作用 |
| --- | --- | --- |
| 普通小混混 | 开启 | 爆头直接死亡 |
| 戴防护头盔的特工 | 关闭 | 爆头承受3倍伤害；存活则强硬直 |

这张表是用户举例对应的配置示意，倍率按默认3倍、攻击武器启用秒杀说明，**没有修改任何现有训练预设**；也不自动判定某名称、等级或模型“看起来戴了头盔”就有防护。默认值和具体兵种配置留到实施时逐项确认。

防护属于被动属性：无论个人Utility还是协调器控制，也无论此刻选中何种战术，都必须有效。无需创建一个需要评分、抢占和执行的“戴头盔动作”。若以后统一为可装配的被动能力，其生效也应由训练装配决定，不能依赖主动战术当帧被选中。

读取沿原训练模块显式覆盖和本场装配规则，个人模式与团队模式不能各自硬编码默认值。普通／强协作沿当前冻结配置约束，改训练后重新加载本场；本次不承诺运行中实时切换头盔或新增装备系统。仅换头盔外观不改变防护值。

## 4. 强硬直的行为边界

“停止所有动作”的用户目标包括自主移动、转向、瞄准、开枪、近战、换弹、突进及其他战术动作；硬直期间不能由个人Utility或协调器请求绕过。已经发出的子弹或已经结算的伤害不撤回。

以下是为落地提出的执行建议，尚未写入代码：

- **身体持有唯一硬直状态与时钟。** 行为只查询是否可执行；不要在每个战术脚本分别计时，也不要冻结整个Squad或区域。
- 进入时取消尚未出手的近战／射击请求，停止自主移动和转向，清理本动作执行占用。结束后按当前感知、冷却和任务有效性重新决定行动，不补发积压攻击。
- 换弹中断保留已完成的装填和原弹量守恒，不凭空返还或补入弹药；硬直期间不能继续后台装弹。
- 已开始的翻越由原身体运动组件安全中断或落到合法姿态，不能把角色悬停在墙中或半空。重力、碰撞、受伤和死亡继续更新；“停止动作”不等于关闭整个节点的处理。
- 冷却不被清零，身体状态、受击反馈及真实感知可以正常更新；协调器知道该成员暂不能执行，其余成员继续工作。是否立即重分派具体岗位，沿原任务中断／失效协议处理。
- 硬直结束信号仅通知表现，动画不能拥有计时或解锁权限。没有动画时，逻辑停止仍有效；将来可接开始、持续、结束动画。
- 连续爆头按武器导出的刷新方式处理。建议默认不累加总时长，而取“当前剩余时间、新命中时长”的较大值；默认项待定，同目标一枪只处理一次，防止多颗弹丸重复续时。
- 暂停冻结时钟；死亡、复位、退场清理状态，切换AI动作或武器不能洗掉硬直。对话停用与恢复需沿项目现有生命周期核对，不能让隐藏计时器提前恢复攻击。

普通减速只是限制移动，不能用速度倍率0假装强硬直；否则瞄准、射击、换弹和近战仍可能执行。

## 5. 霰弹一次判定

按用户最新决定，判定单位改成**每枪、每个实际命中目标一次**；与命中该目标1颗还是9颗无关。保持原多弹丸射线和遮挡，所有射线完成后才伤害结算，避免前面的死亡让后面的弹丸穿透。

例：每颗8伤害，某敌人实际中5颗，普通伤害为40。若爆头触发：武器与敌人都允许秒杀则死亡；否则默认3倍时受到120伤害，存活时进入一次强硬直。倍率可从武器资源修改，没打中的4颗不能计入伤害。

概率仅举例：若配置10%，一次命中对该敌人就是10%爆头，不会因9颗全中变成约61%的触发机会。这个10%**不是已经确定的初值**。同枪打中两个敌人，对两人各抽一次，不用一张全局结果让所有人同时秒杀。

下一版反馈应改为按目标显示“爆头击杀”或“爆头／强硬直”，不继续显示旧版“爆头弹丸 ×N”。画面不承诺概率一定触发，也不画成物理头部命中。

## 6. 性能与结构约束

- 不增加物理射线、额外碰撞体或逐弹丸节点；在原命中统计上处理。霰弹概率抽样次数降为命中目标数。
- 同目标每枪一次伤害、一次硬直请求和一次反馈；原敌人身体集中更新一个状态，不新增每敌人独立Timer节点或AI循环。
- 不重写Utility、协调器或波次控制器；执行资格必须在原最终入口生效，也同步给提案／任务查询，避免AI持续提交无法执行的动作。
- 保留原资源引用、节点路径、UID、用户调参与本场训练装配边界。新增能力不能只做到“字段可读”，却未接入实际受击和行动约束。
