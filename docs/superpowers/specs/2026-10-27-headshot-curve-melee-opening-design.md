# 爆头概率曲线、近战眩晕破绽与视觉反馈

设计日期：2026-10-27。状态：**已按用户后续要求改为破绽门槛倍率；当前规则见第1～9节，初版记录见第10节，本次倍率验证见第11节。**

本设计以用户当前本地工程为基线。运行规则见[射击说明](../../gameplay/COMBAT.md)、[近战说明](../../gameplay/MELEE.md)及[已有爆头状态设计](2026-10-25-headshot-stagger-execution-design.md)。保留原要求与建议的来源区分，第10、11节分别记录初版与倍率修改，不追溯改写旧阶段的用户要求。

## 1. 目标与要求来源

目标是让爆头在正面战斗中成为可以争取、但不必每次依赖的收益。继续保留目标横向移动、玩家移动、射击、受击和压制对精度的影响；普通射击、近战和走位仍各有用途。

### 用户明确提出的要求

1. 基础准度进入一个可配置的高精度区间后，爆头概率从0%逐渐增加；以90%作为初始讨论值，100%准度时实际命中必定爆头。
2. 玩家近战命中敌人后，可给**被命中的敌人**增加爆头破绽 debuff。状态不属于玩家武器，不提升玩家自身精度，也不影响其他敌人。
3. 在现有武器近战的命中反馈、命中减速时长附近配置这项效果；后续补充要求将这组参数中的减速时间等描述调整为“眩晕时间”一类表述。
4. **玩家不能获得这种提高其被爆头机会的破绽 debuff。** 玩家原有的近战伤害、减速、精度损失和击退仍保留。
5. 敌人受这次近战效果影响后，头顶出现眩晕状特效。
6. 爆头概率大于0后，沿用原有爆头标识，像瞄准收拢一样由大变小；达到100%基础准度时呈现类似发光的效果。
7. 用户担心固定处决连招被滥用，对“近战敌人挥空即额外获得爆头破绽”提出异议。本设计不加入挥空触发，保留原攻击收招。
8. 检查器结构与参数分组需要整理清楚；被新机制替代、已经不用的接口应删除，包括旧固定“爆头概率”，不能只隐藏后继续参与计算。
9. 眩晕敌人的爆头条件必须提供可保存、可调整的公开配置，放在**武器近战**参数中。初版用70%绝对门槛作为建议初值；用户后续明确改成倍率，不再显示绝对起始准度，例如普通80%乘0.8后为64%。
10. 项目保持整齐、可读和简单模块化：职责清楚、公式共用、状态归属唯一；不为本功能堆叠重复逻辑、无用兼容层或通用框架。
11. 用户最新明确：**爆头概率只用线性公式，不需要曲线选择或增长指数接口。** 非线性瞄准收敛仍由原瞄准系统负责。

### 已确定的选择与建议初值

| 项目 | 本文方案／初值 | 来源与状态 |
| --- | --- | --- |
| 普通爆头起始准度 | 90%，允许逐武器修改 | 用户给出的起始讨论值；可配置是明确要求 |
| 概率公式 | 只用线性，不提供公式／指数选项 | 用户最新明确要求，取代此前可调指数建议 |
| 破绽效果 | 普通门槛×敌人保存的倍率，默认0.8 | 倍率语义由用户明确；默认值采用用户示例，不是任意精度下一枪必爆头 |
| 破绽持续时间 | 复用该次近战的“眩晕持续时间” | 对用户要求的具体落地建议，不另添第二个时长参数 |
| 破绽次数 | 首次有效玩家枪击后消耗，不论是否爆头 | 防止一次近战支持多枪连续获益的建议 |
| 连续近战 | 当前眩晕期间不延长、重置或重新授予破绽 | 防止连续刷新破绽的建议；原普通近战减速刷新规则保留 |
| 额外抗性冷却 | 首版不加，先观察实战结果 | 尚未确认的扩展不提前纳入实现 |

上表保留设计阶段的来源区分。用户随后以“弄吧”授权实施，本轮采用表中初值、共用时长与一次消费方案；这些仍是可调默认值及具体实现选择，不代表用户逐项指定了所有数值。后续调整时同步规则与验收。线性公式、旧接口删除和近战破绽准度可调是用户明确要求。

## 2. 当前实现与本次变化

实施前 `WeaponData.get_headshot_chance(stability)` 只有基础稳定度达到100%时才返回固定 `headshot_chance`；不足时为0。本轮已替换为第3节线性公式。实际射线命中后按目标判定，霰弹每枪每个实际目标一次。未防护且武器允许时秒杀，否则按倍率结算并可能进入原“被爆头状态”。

本设计把固定概率改成高精度区间曲线，并为受近战影响的敌人提供局部的门槛修正。它不改变实际弹道、身体部位判定、秒杀开关或防护语义，也不增加额外瞄准蓄力按键。

必须区分三件事：

- **玩家基础准度**：决定本枪弹道与正常爆头概率，仍由原 Combat 管理。
- **敌人近战眩晕与破绽**：近战命中后保存在该敌人身体上的有限状态；其中破绽只影响该目标受到玩家枪击时的爆头计算。
- **现有被爆头状态**：爆头后存活者已有的移速／精度上限效果。它不自动制造或续期新的近战破绽。

## 3. 普通爆头概率曲线

令 `a` 为开火前基础准度，`t` 为爆头起始准度，二者均使用内部0～1的比例存储：

```text
p = clamp((a - t) / (1 - t), 0, 1)
```

- `a <= t` 时概率为0；`a = 1` 时概率为1。
- 概率相对于当前准度只做线性映射，不增加二次、指数、曲线资源或模式开关。
- 起始准度必须小于1，建议检查器范围0%～99%。
- 对非法／非有限输入使用统一校验；非有限准度不获得爆头资格。100%判定可沿用现有1e-6浮点容差，不能以界面四舍五入后的“100%”代替真实状态。
- 沿用 `headshot_enabled` 总开关；关闭时任何目标都不触发玩家爆头，眩晕破绽不能绕过总开关。
- 使用基础准度，不以蹲姿缩小后的准星半径或散布角代替；蹲下本身不能抬高爆头概率。

| 基础准度 | 起点90%的爆头概率 |
| --- | --- |
| 90% | 0% |
| 92% | 20% |
| 95% | 50% |
| 98% | 80% |
| 100% | 100% |

这是“准度→概率”的线性关系，不要求“时间→概率”也线性。使用非线性瞄准收敛的武器，`a` 随时间变化的速度不同，概率随时间仍受原收敛曲线、恢复等待与受击／跟枪影响；不再叠加第二套概率曲线参数。

“100%准度必爆头”表示**实际命中后必定进入爆头结算**，不表示自动命中、不受遮挡或无条件秒杀。原最小散布仍可能使子弹打空，防护敌人仍按原倍率与存活状态处理。

原固定概率 `headshot_chance` 按用户最新要求删除：移除导出属性、检查器控件／标签／提示／过滤登记、固定概率计算分支和无用调用；不能仅隐藏，也不能作为新公式最大值或额外乘数。否则旧0.6仍会使满精度只有60%，违反新要求。需要清理的是固定概率配置，不是运行时计算所得的概率结果。

迁移规则：先盘点脚本、资源、场景内嵌资源及测试中的引用，再对确实含废弃键的数据做定向迁移；旧正值直接删除该键，旧值0所表达的禁用意图转换为 `headshot_enabled = false` 后删键，已有关闭开关继续保留；其他武器参数、引用与UID不动。不把旧字段作为常驻运行兼容属性保留下来。测试配置改用新开关和准度门槛，旧数据夹具与历史说明可明确保留。本轮实际发现并删除4份玩家武器资源的旧正值，没有发现保存为0的资源；原禁用测试已改用总开关。外部未纳入仓库的旧资源若使用0表示禁用，应按同一规则迁移。

## 4. 近战参数改称眩晕反馈

配置继续位于原 **Player → Equipment → 当前武器 → 近战 → 命中反馈**。对这组受击效果采用“眩晕反馈”的描述，优先修改显示名称与提示，不为改名重排场景或迁移已有资源保存键。敌人自身武器仍使用原 WeaponData。

| 现有字段或建议新增字段 | 建议显示名称 | 含义 |
| --- | --- | --- |
| `melee_slow_seconds`（现有） | 眩晕持续时间 | 保留现有秒数；用于该次近战减速及敌人近战眩晕状态的初始时长，0关闭持续状态 |
| `melee_slow_multiplier`（现有） | 眩晕时保留移速 | 保留原受方速度损失倍率计算，不是无条件禁止移动 |
| `melee_accuracy_loss`（现有） | 眩晕命中精度损失 | 命中瞬间扣减受方精度，仍乘原受方倍率；不改成整个眩晕期间的精度上限 |
| `melee_knockback_distance` / `melee_knockback_seconds`（现有） | 击退距离／击退时长 | 继续独立描述外力，不混称为眩晕持续时间 |
| `melee_headshot_opening_enabled`（建议新增） | 眩晕爆头破绽（仅玩家近战命中敌人） | 控制是否附加敌人专属破绽；建议初值开启，需结合资源配置验收 |
| `melee_headshot_threshold_multiplier` | 眩晕破绽门槛倍率（仅敌人受方） | 放在武器近战中，可保存的0～1倍率，默认0.8；射击武器普通门槛乘它，0将门槛降至0，1不降低门槛；不增加玩家准度 |

### 检查器结构与接口清理

沿原 WeaponData 分组安排参数，不把破绽倍率配置重复放到 Combat、敌人身体、Training 或 ShotgunSettings。敌人身体只保存本次命中的运行快照。以下为同组阅读顺序，不要求增加嵌套 Resource 或新的管理节点：

| 配置位置 | 参数阅读顺序与职责 |
| --- | --- |
| 命中效果 → 精准爆头（仅玩家） | 启用爆头 → 普通爆头起始准度 → 秒杀开关／未秒杀倍率 → 原被爆头状态参数；没有固定爆头概率、增长指数或公式选择 |
| 近战 → 命中反馈 | 眩晕持续时间 → 眩晕时保留移速 → 眩晕命中精度损失 → 眩晕爆头破绽开关 → 眩晕破绽门槛倍率；击退距离／时长相邻排列并明确独立含义 |

普通起始准度字段为 `headshot_accuracy_threshold`，按0%～99%显示；近战破绽字段为 `melee_headshot_threshold_multiplier`，直接显示0～1倍，默认0.8，支持原资源保存、复制为唯一、原生撤销／重做与外部脚本读写。提示给出80%×0.8=64%的例子，不增加玩家准度。旧绝对字段 `melee_headshot_accuracy_threshold` 从声明、快照、检查器映射和保存键删除，不留下两种可选算法。越界倍率夹到0～1，非有限值按1处理，不授予额外优惠。

复用原检查器的模式／使用方过滤规则：只显示当前用途有效的项；关闭破绽时对应倍率置灰或隐藏，重新开启仍保留保存值。纯敌人武器面板不能把仅玩家近战制造的爆头破绽显示成可增强敌人攻击玩家的能力；直接编辑共享资源时标签要完整说明作用对象。

旧接口清理要同时覆盖声明、读取、写入、字典快照、检查器映射和当前使用说明。`get_headshot_chance()` 这类仍被使用的查询可以改为唯一的线性计算入口；计算结果中的 `chance` 仍有用途，不因与旧字段名称相近而误删。只删除本次被替代或核实无调用的内容，不能根据名称猜测后删除其他系统仍依赖的接口。

普通枪击仍使用原“枪击与压制”参数，不随本次命名调整改成眩晕。近战伤害、范围、体力、前摇、收招、间隔与击退不自动调参。

本稿沿用原受击能力边界：“眩晕”是这些受击效果的展示名称与视觉提示，**不据此额外禁止射击／近战／换弹，不取消 AI 动作，不暂停 Utility、感知或小队协调器**。若以后需要完全失去行动能力，应另行明确，不从名称推导出新的控制规则。

## 5. 敌人专属破绽规则

### 触发、归属与隔离

- 由玩家真实近战命中、目标仍存活且属于合法敌人时触发；保留现有单次近战最近单目标、距离、角度和遮挡检查。
- 玩家近战 A，只让 A 获得状态；B、玩家自身、共享武器资源与其他持有同一资源的角色都不改变。
- 敌人近战玩家仍造成原伤害、精度损失、减速与击退；即使双方引用同一 WeaponData，玩家也不创建该破绽、不显示这项敌人专属头顶提示，敌人子弹不增加玩家爆头判定。
- 普通枪击、近弹、调试扣血、敌人挥空、翻越推人及已有爆头效果均不触发这项破绽。没有敌人破绽接口的训练靶继续原行为。
- 近战开始时冻结本次攻击参数，命中后把时长与倍率存入受击敌人。之后攻击者切枪、修改资源或受击者换武器不改写这份倍率；实际射击时使用该枪自己的普通门槛计算。

### 如何影响命中

使用该枪自己的基础准度与正常门槛；只在实际被命中的敌人持有可用破绽时，使用：

```text
本目标门槛 = 本枪正常爆头起始准度 × 该敌人保存的破绽门槛倍率
```

再按第3节同一公式计算概率。不直接加概率，不回满准度，不修改武器资源；倍率范围0～1，不会把普通门槛提高。0倍表示门槛为0，此时概率等于当前基础准度，不表示任意准度必爆头；1倍不提供门槛优惠。

例如正常起点80%、倍率0.8：破绽起点为64%，玩家82%准度射击 A 时50%爆头，射击无破绽的 B 时10%；100%准度时都必定爆头（仍须实际命中）。默认普通起点90%配0.8倍时，破绽起点为72%。同一敌人换用普通门槛50%的枪射击时，仍用保存的0.8倍得到40%，不沿用近战时的绝对门槛。破绽不绕过敌人原爆头防护。

### 时长、消费与重复命中

1. 敌人近战眩晕记录保存剩余时间、门槛倍率和“破绽是否可用”；剩余时间从近战实际命中开始，初始值复用该次“眩晕持续时间”。不增加另一套可编辑时长。
2. 头顶眩晕表现跟随这份近战眩晕记录。破绽到期后失效；持续时间为0时不创建状态或头顶效果，原近战伤害、瞬时精度损失和击退仍执行。
3. **首次有效玩家枪击命中即消耗破绽，不论是否爆头、概率是否为0或该枪是否关闭爆头。** 打空、被墙截断、近弹和近战命中不消费枪击机会；时间仍正常流逝。
4. 消费破绽只移除后续枪击的门槛优惠，不提前清除原移动减速、剩余眩晕显示或其他受击效果。
5. 在这份近战眩晕记录到期前，连续近战不延长它、不替换倍率、不重新授予已消费的机会；普通近战伤害、瞬时精度损失、击退与原减速刷新仍正常执行。到期后再次真实近战命中才可新建一轮。
6. 普通枪击刷新原减速计时不能续期近战眩晕或重新授予破绽。共用一个**配置时长**不等于借用会被其他来源覆盖的普通受击计时器。
7. 暂停冻结状态与动画；死亡、敌人复位、区域回收、对话清理和场景卸载清除状态。玩家切枪与 AI 动作切换不清除或刷新敌人状态。

### 单发与霰弹的顺序

沿用先查实际射线、再按目标汇总、最后受击的顺序。每枪使用开火前的玩家准度快照；对所有实际命中目标读取各自的有效破绽／防护快照，在任何伤害回调前完成本枪全部目标的概率与伤害结果。

霰弹命中 A 和 B 时分别判定各自的概率，每目标只判定一次、至多消费一次破绽；不能每颗弹丸掷骰，也不能把 A 的门槛优惠传播给 B。“瞄准 A、实际打中 B”以 B 为准。破绽消费与伤害交付应保证本枪一次性，并与目标身份／复位代际核对，不能由回调重复消费或清除新一轮状态。

## 6. 两种视觉反馈

### 敌人头顶眩晕效果

用户要求的是受该次近战影响后的眩晕状特效。本稿将其绑定到上述敌人近战眩晕记录，不扩展为所有普通枪击都显示眩晕。

- 建议用小星点围绕短环旋转，跟随头顶位置；颜色、大小与旋转速度属于美术初值，不是固定用户要求。
- 保持现有血条与状态文字可读；蹲起、位移和击退时跟随身体高度，保留场景遮挡，不借特效暴露墙后目标。
- 使用纯表现组件和可复用效果资源；空正式素材时也应有可见的程序化占位效果，便于先验收玩法。
- 状态结束、死亡或回收及时隐藏／回收；多个敌人使用同一素材时不能共享动画进度。
- 头顶星环表示仍处于这段眩晕时间，**不表示下一枪必爆头或破绽尚未被消费**。破绽是否可用通过准星对该目标的实际概率反映；消费后星环可继续至原眩晕时间结束。
- 这一版不要求给玩家新增同款特效，也不替换现有爆头命中文字反馈。

### 原爆头菱形的收缩与发光

复用 `scripts/ui/lock_reticle.gd` 中原金色菱形，不另建一套爆头准星。

| 当前瞄准目标的实际爆头概率 | 显示 |
| --- | --- |
| 等于0 | 隐藏爆头菱形，原瞄准圆正常显示 |
| 大于0、小于100% | 显示较大的菱形，随概率升高逐渐收小 |
| 100%基础准度且爆头启用 | 最小菱形，增加清晰可见的金色外光／柔和亮边 |

建议按 `size = lerp(最大尺寸, 最小尺寸, p)` 映射尺寸，两个尺寸可在原UI组件中配置。收缩由实际概率驱动，不是独立计时动画：受击或跟枪降低概率时应放大，降至0时隐藏；切换目标、破绽消耗或到期时立即重新取值，不能保留上个目标的优惠。

准星只读“当前武器＋当前基础准度＋当前锁定目标”的预测概率，与实际结算共用同一规则；查询不掷骰、不消费状态。原瞄准圆继续表现原精度／散布含义。

发光可用原 Control 绘制的多层透明描边等方式实现，不把效果可见性依赖于全局3D Bloom。发光代表命中后的爆头确定性，不代表无视防护的必杀。不能因为准度显示四舍五入为100%而提前点亮。

未瞄准、目标无效／不可见、失去相机、玩家死亡或对话时沿原生命周期隐藏准星；暂停时状态及相关动态效果冻结。已有实际爆头结果文字继续按原命中事件显示。

不把破绽写进共享 WeaponData、Equipment 槽位、玩家全局精度或 AI 训练资源；不新增全局状态管理节点，不重排现有节点路径、UID或资源引用。玩家与敌人的受击执行继续独立，不能因为武器数据共用而共用一条无对象限制的破绽施加路径。

### 可读性与简单模块化要求

- 参数定义与校验在武器数据侧，敌人运行状态在身体侧，概率／命中结果在结算侧，视觉呈现在表现侧；每个模块只承担清楚的职责，禁止互相回写状态。
- 普通目标和破绽目标共用一条线性概率公式，单发、霰弹与准星预览共用计算规则；差异只来自目标门槛，不复制三套算法或另加一套固定概率。
- 身体只维护一份近战眩晕记录，表现读取快照；不把相同状态分散保存到武器、UI、AI动作和全局单例。
- 在原结构内增加必要的小函数或身体私有辅助对象；只有出现独立、可解释的职责才拆文件，不按每个字段创建服务、工厂或事件总线，也不为了本功能搭建通用buff框架。
- 新函数名称、参数单位、输入输出与生命周期应能直接读懂；注释说明对象限制、快照和消费顺序等原因，避免把大段分支继续堆进原攻击／更新函数。
- 完成替代后同步删除无用分支、重复包装和旧检查器映射；保留确有调用的旧公开接口时，要维持其单一职责，不以多层转发维持已废弃的玩法。
- 结构审查与行为验证一并验收：既确认能正确运行，也确认没有重复公式、资源运行状态、失效配置项或无调用的新抽象；不扩大为与本功能无关的全仓库重构。

## 8. 风险与平衡验证

- 普通门槛90%并不保证实战中容易进入奖励区间。持续横向跟枪的恢复限制若低于90%，仍不会获得普通爆头；需要观察真实战斗的高精度停留时间。
- 满准度从旧固定概率改为100%，本身就是明显强化。不能仅凭采用线性或提高门槛就宣称玩家不会依赖爆头。
- 当前近战默认减速时长0.5秒、收招0.25秒只是脚本初值，用户资源可能不同。共用眩晕时长后，要检查收招结束是否还有可兑现的枪击窗口，不能在武器仍禁止射击时就让效果过期。
- 一次消费与不续期可限制连续收益，但不能防止每个敌人都使用“近战接枪”的固定套路。实测应比较接近风险、体力、近战耗时、补枪命中与直接射击的击杀时间。
- 保留原攻击后精度损失，检查自动武器是否能长时间停留在高爆头率区间；霰弹不得用弹丸数放大触发概率。
- 不为使本方案看起来平衡而自动修改用户武器伤害、敌人生命、眩晕时长、地图或训练。若实际形成稳定控制链，再单独讨论时长、门槛或抗性；本稿没有预先承诺增加强制冷却或重击系统。

## 11. 破绽倍率修订（2026-10-27）
