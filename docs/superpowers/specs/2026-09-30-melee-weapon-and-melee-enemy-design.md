# Fire Mode 近战选项与近战兵装备设计

日期：2026-09-30

状态：**用户已确认；实现按本设计完成。验证结果见文末。**

## 你最终会怎么用

打开一份武器资源，在原来的 **“共用参数 → Fire Mode”** 中选择：

| Fire Mode | 武器用途 |
| --- | --- |
| 单发 | 保持现有单发枪械 |
| 自动 | 保持现有自动枪械 |
| 近战（新增） | 专用近战武器，只允许近战兵种装备 |

**不在最上面增加 Weapon Type。** 继续使用现在的武器资源，不另建一套武器系统。

给现有近战兵的 Weapon 填入这份资源后，它沿用现在的接近方式，走到攻击范围内便可以挥击、伤害玩家。近战兵行为优化暂不做。

## 选“近战”之后，面板怎样变化

用户希望远程属性不能继续打开、修改。本方案建议**直接隐藏不适用的远程参数**：

| 参数 | 选择“近战”后 |
| --- | --- |
| 武器名称、Fire Mode | 保留，仍可修改；可以切回单发／自动 |
| 近战伤害、距离、角度、高度容差 | 保留，作为这把武器的攻击参数 |
| 近战开关、前摇、收招、间隔、击退 | 保留，继续控制基础挥击 |
| 弹药类型、弹匣容量、换弹时间 | 隐藏，并且运行时不能射击、消耗子弹或换弹 |
| 子弹伤害、射程、射速、枪声 | 隐藏，对近战无效 |
| 锁定、准度、散布及枪械恢复参数 | 隐藏，对近战无效 |

隐藏只影响编辑界面，**不删除原来填好的数值**。切回单发或自动时，原参数重新显示，保存、重开和撤销操作也应保留这些值。

敌人目前没有体力系统；已有近战体力消耗字段继续注明“仅玩家生效”，不让近战兵突然需要消耗体力。

用户已确认本方案采用隐藏方式。新建独立近战 Resource 类只作为备用方向，本次不采用；如果确有无法解决的兼容问题，再说明原因，不擅自换方案。新增一份近战 `.tres` 配置仍然是现有 WeaponData 的实例，不等于新增资源类。

## 只有近战兵可以装备

这条限制针对 **Fire Mode 选择“近战”的专用武器**：

- 现有近战兵种：允许装备，并使用里面的近战数值。
- 远程兵种：不允许装备这类专用武器。
- 玩家：不允许装备这类专用武器。

玩家按 V 和远程敌人近身推开的功能继续保留：它们仍装备单发／自动枪械，使用枪械原来的“近战参数”。枪械附带近战不等于装备了专用近战武器。

建议的错误配置处理：出生时误配专用近战武器，按未装备处理并提示原因；运行时尝试换上不允许的武器，拒绝请求并保留当前有效装备。玩家初始槽误配时，沿用空槽规则选择另一个有效槽，两槽都无效则不装备。运行时更换兵种后若失去资格，取消未完成挥击并禁止继续使用该专用武器。

限制在装备和实际执行入口生效，不能只隐藏参数，却仍让玩家或远程兵用它攻击。

## 近战兵只补上“能够攻击”

沿用已有的 `resources/enemy/units/melee.tres`，不新建兵种。

它已有巡逻、搜索、近战接近三个默认行为。本次只让**已被 Utility 选中的近战接近行为**在条件合适时请求基础挥击；挥击期间保持必要的停步、冷却和互斥。停止距离要落在武器实际攻击距离内，避免走近后永远够不到。

实际前摇、命中、伤害、准度清零、击退和收招继续由已有敌人近战控制器与身体执行。玩家用自己的受击代码处理伤害；双方攻击代码继续分开。现有动画和剑光接口照常使用，没有模型或动画也能命中。

**本次不改接近策略，不增加战术，不调整 Utility 评分、候选方案或训练参数。** 不做掩体迂回、突然冲刺、连招，也不增删地图敌人。

装备入口保持原样：

| 位置 | 配置 |
| --- | --- |
| 现有敌人的 `UnitType → Profile` | 已有近战兵资源 `resources/enemy/units/melee.tres` |
| 同一敌人的 `Weapon` | 一份 Fire Mode 为“近战”的 WeaponData，例如 `resources/weapons/enemy_test_melee.tres` |

## 实现时必须守住的边界

这部分供后续实施核对，不要求用户阅读代码：

- `FireMode` 保留单发0、自动1，追加近战2；删除先前试加的 `WeaponType / weapon_type` 及其引用，不留下两个分类入口。
- 在现有武器检查器中处理参数显示；WeaponData 只保存配置，弹药模块负责禁用纯近战弹药与换弹。
- 沿用兵种已有的能力标识机制，建议只给现有近战兵增加专用近战装备资格；这不是默认行为、战术或训练开关。玩家和敌人的装备入口分别校验，不合并攻击代码。
- 近战接近脚本只提交意图，实际挥击仍是与移动、射击并列的基础能力。不新建挥击行为资源，不让 AI 主循环按兵种强制出招。
- 保留原文件路径、节点结构、资源 UID、用户数值和无关改动。依据 [AGENTS.md](../../../AGENTS.md)、[项目结构](../../project-layout.md)、[敌人 AI](../../enemy-ai.md) 与 [验证说明](../../enemy-tests.md) 维护。

## 怎样算完成

1. 在原 Fire Mode 下拉框里能选择近战，没有额外 Weapon Type。
2. 选择近战后远程参数不可编辑；切回枪械后原值仍在。
3. 近战兵能装备；玩家和远程兵误配时确实不能使用。
4. 现有近战兵能自主走近、实际伤害并击退玩家，冷却后能够再次攻击。
5. 纯近战不能射击或换弹；玩家持枪 V 近战、远程敌人推开和原枪械功能仍正常。
6. 模型、动画留空也能攻击；兵种行为清单、Utility 评分和项目结构保持原有组织。
