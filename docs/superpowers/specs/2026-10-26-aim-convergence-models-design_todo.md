# 武器瞄准收敛公式与蹲姿最大散布调整草案

日期：2026-10-26。状态：**准备实施的设计文档，尚未修改收敛或蹲姿代码，尚未完成新机制验证。**

目标是在较短时间内获得可用的射击精度，同时让等待最准状态具有成本，形成“现在开枪”与“继续瞄准争取爆头”的取舍。武器资源检查器提供可切换的函数公式；蹲姿单独降低最大散布，不再直接把稳定度补满。

本轮用户授权先写文档准备做。下文区分用户方向、当前实现和实施建议；字段名、默认数值、兼容方式与跨模式范围不视为用户已经逐项确认。本文不授权自动开始开发，也不改写当前武器、场景或训练调参。

相关说明：[射击与现有蹲姿规则](../../gameplay/COMBAT.md)、[霰弹配置](../../gameplay/SHOTGUN.md)、[爆头接口与边界](2026-10-25-headshot-stagger-execution-design.md)、[目录结构](../../project-layout.md)、[测试维护](../../testing.md)。

## 1. 用户方向

- 收敛前段较快，较快进入能进行普通射击的状态；接近最准时可以放慢，增加追求爆头资格的等待成本。
- “模型”指线性、二次或指数等实际函数公式，不是只有快慢几档的数值预设。每把武器可在自己的资源检查器中切换候选公式。
- 界面采用容易理解的“收敛公式”和“收敛时间”；不先增加此前解释不清的“耗时倍率”。
- 蹲姿方向以用户最后的说明“让最大散布减小，不影响后续”为准：最大散布按 `1-n` 缩小，`0 ≤ n < 1`；最小散布以及后续采用的公式、时间和恢复限制不因蹲姿另行改变。不继续使用稳定度直接加25个百分点的方式。
- 用户以CS2帮助说明想要的感觉；这里不声称复现CS2内部公式、参数或完整射击机制。

“可用”需要结合交战距离、目标大小、散布与实际伤害判断，不能把界面80%稳定度直接当成80%命中率。爆头仍需真实命中及武器概率判定，满稳定度也不保证每枪爆头。

## 3. 候选函数模板

先用一段没有新惩罚、可以持续恢复的过程说明公式：`θ0` 为参考起始散布半角，`m` 为最小半角，`T > 0` 为这段参考过程的收敛时间，`t` 只统计原恢复等待结束后实际允许恢复的时间。

```text
x = clamp(t / T, 0, 1)
散布半角 θ(x) = m + (θ0 - m) × g(x)
```

| 检查器候选 | 剩余散布函数 `g(x)` | 过程 |
| --- | --- | --- |
| 线性 | `1-x` | 每单位时间收拢相同角度，作为原匀速行为的对照 |
| 二次 | `(1-x)²` | 前段较快，越接近最小散布越慢 |
| 指数 | `(exp(-k*x)-exp(-k)) / (1-exp(-k))`，`k > 0` | 前快后慢，`k`控制前后速度差异 |

三者均满足 `g(0)=1`、`g(1)=0`，并在区间内单调下降。达到终点时明确写入最小散布／完整稳定度，避免只无限接近终点而与爆头资格判断冲突。指数形式是有限区间的归一化函数，不是直接使用不断增长的 `exp(x)`。

`k`接近0时指数形式趋近线性；实施时需使用稳定的数值计算或回退线性，不能直接做接近0的除法。非法参数、零宽度散布区间及非有限值需有明确回退。指数强度的默认值和检查器范围尚未确定。

### 3.1 公式与总时间要分开比较

**相同参考起点和相同 `T` 下，三种公式到达最准的时间相同。** 二次或指数本身不能让这个终点更晚；它们可以把前段变快，再允许把总时间适当拉长，使普通射击的等待基本保持，而最准状态更贵。

以下只演示这种关系：起始6°、最小2°；用3.6°作为一个比较点，不把它规定为所有武器的“能打”门槛。

| 到达散布半角 | 线性，参考用时1秒 | 二次，参考用时1.6秒 |
| --- | --- | --- |
| 3.6° | 0.60秒 | 约0.59秒 |
| 2.4° | 0.90秒 | 约1.09秒 |
| 2.0° | 1.00秒 | 1.60秒 |

上述角度与秒数均为示例，不写回现有资源，也不是最终平衡参数。最终按普通命中、弹药消耗、爆头机会和暴露风险试玩比较。

### 3.2 实际恢复不能每次重新计满一段时间

玩家可能从射击、受击、换弹或移动造成的任意精度开始恢复。不能每次损失后都重新等待完整 `T`，也不能重启曲线时抬高当前精度。

建议以当前剩余散布反求曲线相位，再推进实际允许恢复的时间。以完整“最大散布→最小散布”区间建立参考，可覆盖比武器初始散布更差的受击状态；初始武器位于该曲线的相应中段。将每个移动／跟枪恢复上限当成新的“最准点”会改变原边界，应避免。

检查器的时间必须写清参考区间。**建议新字段显示为“收敛时间（最大→最小）”**，并在提示中说明当前状态只使用剩余时间；这是实施建议，不能悄悄把旧“初始→最准”秒数原样解释为新参考时间。若最终选择其他参考区间，应先统一字段提示、迁移换算和验证样例。

## 4. 蹲姿只降低最大散布

设站立最大散布为 `M`，最小散布为 `m`，蹲姿缩减比例为 `n`：

```text
蹲姿最大散布候选值 = M × (1-n)
合法蹲姿最大散布 Mc = max(m, M × (1-n))
0 ≤ n < 1
```

例如最大散布4°、最小散布1°、`n=0.25`，蹲姿最大散布变为3°，最小仍为1°。这里的4°是最大值，不把普通武器的“初始散布”和“最大散布”混为同一字段。

建议只替换弹道映射中的最大端点，沿用同一基础收敛进度。用当前基础散布得到剩余比例 `r`，再映射到蹲姿范围：

```text
r = (当前基础散布 - m) / (M - m)
蹲姿显示／实际散布 = m + (Mc - m) × clamp(r, 0, 1)
```

这是一种实现建议：改变最大端点，不把整条散布角度直接乘比例；基础稳定度、恢复延迟和曲线相位不被蹲姿写回或重置。站起恢复正常最大端点，并继续当前进度；连续蹲起不能累计缩减，不能给切槽状态写入永久加成。换弹、受击限制、翻越和临时站起越墙射击仍需按原资格处理。

注意 `n < 1`只保证候选最大值不因乘法变成0；当最小散布本来大于0时，候选值仍可能低于最小值。最大端点需钳制，`M=m`时不得除零。**端点钳制或姿态造成的散布变小，不应直接当成基础收敛已经完成而发放爆头资格。** 实施时需将实际散布效果与基础收敛完成条件核对清楚，准星资格提示和伤害入口必须一致。

“不影响后续”指不额外改变所选函数、收敛时间、恢复等待或基础状态，不承诺站蹲两种不同散布幅度在每个瞬间拥有相同的角度变化量。具体映射需在实际射击与准星中一起核对。

## 5. 武器资源入口与兼容建议

在原 WeaponData 检查器增加收敛配置，不另建装备或角色管理系统。建议入口为 **Player → Equipment → 对应武器资源 → 瞄准收敛**。

| 建议字段 | 显示与语义 | 状态 |
| --- | --- | --- |
| `convergence_model` | 收敛公式：线性／二次／指数 | 名称与枚举编号待实施核定；建议0为线性 |
| `convergence_seconds` | 收敛时间，秒；提示明确参考区间 | 时间范围和默认数值未确定 |
| `convergence_exponent_k` | 仅指数公式显示的曲线强度 | 是否作为可调字段、默认值与范围未确定 |
| 蹲姿比例 `n` | 最大散布缩减比例，0关闭且始终小于1 | 建议继续归玩家姿态配置；是否按武器独立配置尚未确认 |

“旧资源缺省选线性”是兼容建议，含义是新字段缺失时继续原匀速行为；不是用户要求某一类枪永久使用线性。选中其他公式后，该武器使用所选函数。

仅将枚举设为线性还不足以保证兼容。原散布模式使用“每秒收拢角度”，概率与霰弹使用各自的初始状态恢复用时，必须按实际速率换算参考时间。原恢复速度为0表示关闭恢复的配置应保留，不因除零改成瞬间满准；初始已经最准时，受伤后的恢复仍应有效。

实施时应明确哪套参数生效，避免同时让新总时间和旧速度字段共同驱动玩家恢复。旧字段还可能被敌人或其他入口读取，应保留必要的资源兼容，不直接删除共享字段或覆盖用户保存值。新字段的保存重载、检查器原生撤销／重做与切换公式后的状态连续性都需验证。

## 6. 实施范围与现有职责

- `scripts/weapons/weapon_data.gd`：沿现有资源扩展静态公式配置与必要的纯值换算；不保存当前玩家恢复进度。
- `scripts/player/player_combat_v3.gd`：沿现有恢复入口消费公式，保留移动、跟枪、射击、受击与换弹限制；蹲姿只改变散布上限的表现／弹道映射，不用旧加法提前补满基础精度。
- `addons/weapon_mode_inspector/weapon_inspector.gd`：沿原插件提供下拉选项、数值提示与相关参数显示，不新增独立插件入口。
- `scripts/ui/lock_reticle.gd`：核对实际散布、准星收拢和爆头资格的含义，避免准星显示可爆头但射击入口不合格，或相反。
- 原槽位保存、生命周期清理、资源引用、脚本UID和场景路径保留；不新增另一套瞄准计时总控，不调整武器伤害、爆头概率、射程或敌人训练来配合新曲线。

当前讨论聚焦玩家普通射击。玩家旧概率模式、霰弹以及敌人共用部分资源与工具，**不能因增加字段而自动改变敌人恢复或AI行为**。是否让旧概率模式同样应用候选函数，以及霰弹是否将蹲姿映射到最大随机扰动，需要实施前确认；霰弹固定图样不应因本功能整体收缩。最小半角不为0的武器仍保留其最小随机散布。

使用说明应等实现与验证完成后再更新为新行为。当前[射击说明](../../gameplay/COMBAT.md)仍描述现有线性恢复及蹲姿加法，本文记录下一阶段准备方向，不把未实施方案写成当前功能。

## 7. 后续验证与尚待确定项

必要验证围绕直接受影响的行为：

1. 公式起终点、单调性和有限时间到顶；不同帧率／大帧时间下结果一致，指数极限、零散布宽度与非法参数保持有限值。
2. 使用相同武器和实际交战距离，比较达到可用散布与获得爆头资格的时间；分别对照相同总时间与调整总时间后的效果，不以单次随机命中得出平衡结论。
3. 新惩罚从当前状态接续；暂停、移动／跟枪上限、换弹及完成帧、受击等待、切槽保存与死亡重开不被绕过。恢复延迟不重复计入或在低帧率下被提前吃掉。
4. 蹲姿只缩小合法最大端点，最小值与基础恢复不变；反复蹲起不累积，站起或翻越按原规则处理。未完成基础收敛时不能单靠蹲姿获得爆头资格。
5. 资源中切换公式及时间后能保存重载，真实检查器可编辑并支持撤销／重做；旧资源的线性对照保留原恢复速率，既有武器调参不被重写。

现有相关入口包括 `player_half_cover_test`、`headshot_test`、`headshot_execution_test`、`directional_tracking_test`、`aim_disruption_test` 及原检查器测试。按实际修改选择必要专项，不默认重跑全量项目。

实施前还需核定：新时间字段的最终参考区间和迁移方式、指数参数是否可调及其范围、各武器实际采用的公式与秒数、蹲姿比例归属、旧概率与霰弹的接入范围。用户已确认的是机制方向及准备文档，并未确认这些具体参数或授权本轮开发。
