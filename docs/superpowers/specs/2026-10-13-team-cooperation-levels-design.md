# 小队三档团队意识设计草案

2026-10-13。用户已明确三档协作、小队统一团队意识、个人 Training 独立，以及由调节器安排、个人执行的方向。本文中的配置载体、接口和策略比较方式是待审阅的实现建议；运行代码尚未修改。现有实现与验收结果仍见 [敌人 AI](../../enemy-ai.md) 和 [敌人测试](../../enemy-tests.md)。

## 用户要求

- 第一档仅共享视野情报。
- 第二档具备配合意识，分析当前局势，结合友军站位选择包抄。
- 第三档有训练有素的强配合：必要时等待队友到位，选择集中或分散站位，并为队友进攻、撤退和换弹安排掩护射击或火力压制。
- 调节器负责团队层面的安排，个人 AI 负责具体实施。
- 同一小队使用相同的团队意识。每个成员的 Training 保持独立，以支持不同兵种和不同战术；共享范围仅为团队意识的等级与协作参数。
- 小队不应在概念上限定为敌人，也不应把玩家身份写入新规划协议。友方 AI、多阵营与多目标战斗是后续扩展方向，本轮不把现有单目标感知描述为已完成通用化。

本轮取代原先基础／高级二档的目标设计，但保留原方案的合法情报、真实火力、有限期限、身体保护与性能预算约束。旧文档中的二档描述仍是当前运行实现，不应提前改成三档已实现。

## 当前实现与缺口

| 当前机制 | 对本轮的影响 |
| --- | --- |
| 每战斗区一份 `enemy_cooperation.gd`，调用纯值 `enemy_team_planner.gd` | 复用服务与规划器，不增加指挥官场景节点 |
| `cooperation_enabled()` 由个人是否解锁 `cooperate` 决定，快照只有 `advanced_enabled` | 需要把团队意识权限提升为小队配置，并增加中间档 |
| planner 能组合检查、前线／侧翼、地图搜索和支援岗位 | 复用候选与事务，增加整队局势判断和集中／分散位置组合 |
| 有岗位时 Context 收窄个人候选，board 管理接受、就位与释放 | 强配合可复用；中间档必须保留普通个人选项，不能直接套用该约束 |
| `_front_candidate()` 只在本人当前位置已具备实际火力时提供前线候选 | 需要允许先规划可到达的支援位置，执行时再等待真实火力成立 |
| 换弹、撤退和部分推进已有支援请求，压制动作独立选择 | 强配合要在中央关联行动者与支援者，并让原压制动作提供合法岗位候选 |
| 当前 Training 在成员启动时分别深复制 | 仅让几个人引用同一份原 Training，不能保证运行时团队意识一致；也不符合保留个人训练的要求 |

对应实现入口为 [Context](../../../movement_demo/scripts/enemy/services/enemy_context.gd)、[调节器](../../../movement_demo/scripts/enemy/services/enemy_cooperation.gd)、[纯规划器](../../../movement_demo/scripts/enemy/services/enemy_team_planner.gd) 和 [协作动作](../../../movement_demo/scripts/enemy/actions/enemy_cooperation_action.gd)。

## 配置与小队边界

建议在现有战斗区中按小队绑定一份团队意识配置，由调节器持有每队一份运行快照。个人 Training 继续管理反应、掩体、压制、近战等训练与战术解锁，个人执行进度仍归动作和身体。

两种可行的配置方式是：战斗区维护小队与团队意识的绑定，或每个成员分别引用同一份团队意识资源。采用前者可以在一个位置修改整队、避免漏绑成员，并使调节器获得唯一配置来源；后者编辑改动较少，但仍需处理个人深复制和成员引用不一致的问题。本文建议采用前者。

配置使用现有 `cooperation_settings.gd` 扩展三档枚举及团队参数，新增一个只保存小队匹配字段和配置引用的绑定资源。绑定由现有 `shooting_range.gd` 提供给调节器，不增加场景管理节点。现阶段以战斗区内的阵营、通信组明确小队绑定；同阵营需要分成两队时使用不同组。不同阵营的友方可以依原关系接口交换情报，但不会仅因友好关系就自动共用训练或共同指挥。

小队身份与训练模板分开：两队可以引用同一个配置模板，但分别持有计划、成员、期限和运行快照。同队所有成员只有一个有效协作等级，不能从首个注册者、最高等级成员或多数成员临时推导等级。相同小队键的重复绑定属于配置错误，应在检查器明确显示并停用该队战术指派；共享情报和个人基本行为仍可继续。

个人 Training 的“团队协作”选择迁为由小队配置提供的团队能力。检查器显示该成员所属小队及生效等级，编辑共享配置时明确影响整队；其他个人战术保持原有编辑入口。调节器只安排成员实际具备的动作：枪械成员可接射击支援，近战成员使用自身合法接近与攻击方式，未训练专门压制的成员仍可用普通射击掩护，不能获得压制动作的权限。

旧资源与 `cooperate` 动作 ID 保留加载兼容。尚未绑定的小队先保留旧行为，显示为待迁移的旧配置；不能把旧个人开关继续作为新绑定小队的第二个控制源。新绑定生效后，所有团队意识读取统一来自调节器，个人旧 cooperation 值不再覆盖它。迁移仅添加所需绑定，保留场景布局、武器数值、个人 Training 和已有用户修改。降档或更换绑定同步增加配置版本并撤销不再允许的团队任务；当前身体不可打断阶段按原合同收尾。

## 三档的行为边界

| 等级 | 调节器负责 | 个人 AI 负责 |
| --- | --- | --- |
| 仅视野共享 | 转发合法目击；维持原基础位置排重与通行安全 | 独立接敌、搜索、攻击和换弹，不接包抄、支援或同步任务 |
| 战术配合 | 根据已知目标、友军实际位置和有限候选，建议互补站位与包抄方向 | 在建议与其他合法个人方案间选择，可自主推进或放弃，不等待全队到位 |
| 强配合 | 选择集中／分散及行动分工，关联支援者与行动者，管理必要的等待、释放、接替和失败回退 | 在岗位合法备选中选具体点并执行，报告真实进度，保留自保与身体保护 |

第一档的基础让路、防止重叠和避免阻挡友军枪线属于物理运行要求，不授予战术分工。它不会为了照顾队友换弹而改变自己的行动，也不会接受统一搜索区域。

第二档建议必须包含具体可行方向和候选位置，不能仅把旧协作评分权重调高。建议不会锁住普通个人候选，也不会使其他成员把该成员当成承诺留下的火力支援。成员实际选择移动后才预约所需位置；拒绝、超时或转向其他动作应释放建议，不能因持续广播而永久占位。可以顺势利用正在发生的友军火力，但不预支未来掩护，不形成换弹排班或统一起步屏障。

第三档在接受合法岗位后保持当前执行段的连续性，不因普通分数波动频繁换位。关键依赖只覆盖本次配合需要的成员，例如两侧检查的两名队员，或推进者与其支援者；其他成员可以继续自己的任务。缺少合法完整组合时回到个人行为，不为表现配合而制造等待。

## 调节器与个人的职责

沿用现有调用链：

```text
小队团队意识配置 + 个人能力与合法情报
                    ↓
个人动作产生有限的可行候选与执行事实
                    ↓
区域调节器汇总 → 纯规划器比较局势与位置组合
                    ↓
第二档站位建议 / 第三档岗位与协同条件
                    ↓
个人 Utility 选具体方案 → 原动作、身体与 Fire 执行
                    ↓
真实到位、开火、受阻、完成与自保反馈
```

调节器决定目的、分工、互补位置范围与时机；纯规划器继续只处理值，不读取场景、全图寻路或控制身体。个人动作提供经过本地查询的候选，按原空间预算进行路径、射界和掩体评估；执行前再次验证。AI 主循环与选择器只扩展通用协议，不按具体战术名称增加分支。

小队配置改变时，各成员的有效配置版本同步变化。共享配置不保存成员的当前弹药、计时器、路径进度或动作阶段。单人小队保持正常个人行为，不产生虚构队友或等待任务。

## 集中与分散如何选择

规划器在原周期和事件触发边界比较有限的合法组合，使用真实已知目标、成员位置、可支援射界、弹药、换弹剩余时间、生命压力和路线风险摘要。

- 集中是靠近能够互相支援的不同位置，适合成员落单、可用火力不足、需要保护换弹者或共同通过窄路等情况。仍保持身体间距、入口通行与枪线，不能让所有人走向同一坐标。
- 分散是选择互补射界、不同掩体或侧翼通路，适合全队挤在同一侧、已有足够前线火力且存在安全侧路的情况。保留前线，继续遵守原半队包抄名额与实际身体占侧计数。
- 保持当前部署也是候选。地图无合法侧路、迁移暴露过大或当前射界已经互补时，不强迫改变队形。

这些是由候选可行性和团队收益支持的选择，不采用“人数多就散开”“血少就聚集”的固定命令。比较必须覆盖同一批成员、同一时间窗口，未获新岗位者沿用其个人方案估计，避免拿一个支援者的代价与多人包抄总代价直接比较。未来火力是有条件预测，当前已生效火力仍来自 Fire 的真实状态。

只对已有合法候选比较团队结果，不在中央重新采样导航。第二档消费位置建议，第三档才使用岗位约束和时序承诺。位置微调优先修复本岗位；队伍部署变化在真实执行边界发生，使用有限保持和切换条件避免反复聚散。相关阈值属于实施参数，不能写成用户指定数值。

## 进攻 撤退 与换弹的配合

第三档将行动与掩护关联成同一计划中的有限依赖，复用原岗位、请求身份和反馈机制。支援可以来自普通合法射击，也可以来自成员已解锁的压制动作。

| 情况 | 安排与实际释放条件 |
| --- | --- |
| 进攻或包抄 | 支援者到合法射击位置，行动者到本段起点；指定支援真实就绪后释放需掩护的路段 |
| 撤退 | 可用成员保持压力，撤退者沿真实安全路线转移；紧急自保立即执行并请求补上支援，不等待掩护而停在危险处 |
| 还有余弹的主动换弹 | 安排一人补装，保留其他可用火力；真实支援或安全遮蔽条件成立后开始，完成后释放依赖 |
| 空匣或全队无可用火力 | 允许必要换弹及寻找遮蔽，不用排班禁止基础换弹，也不声称存在有效掩护 |
| 支援者需要移动或换弹 | 有合法替代者时先完成真实交接，再释放原支援者；否则撤销依赖或降级任务 |

候选生成阶段允许提出“到达此位置后能够掩护”的方案，避免必须已经开火才能获得支援岗位。该方案只代表可行性；接受后可以发布有固定准备期限的支援需求，供支援者先行准备，不能把准备请求算成正在推进或已经获得火力。

`enemy_suppression_action.gd` 应提供自己的合法支援候选与执行合同，由调节器选择是否采用。压制仍受原合法冻结证据、弹药、射界、友军枪线和有限波次约束；普通掩护沿用 Fire 的点射及停顿，不承诺物理上不存在的连续开火。等待就位、Fire 就绪和实际射击分别记录，支援验收观察真实射击与受援动作的重叠时段。

等待沿用不可续期的阶段与整轮期限。队友受阻、死亡、换组、撤权或失去支援条件时，先尝试有限局部修复；无法修复就解除依赖并回到合法个人行为。正常短点射暂停可沿用现有有限恢复机制，但暂停本身不记为火力收益。

## 值接口的建议扩展

保留原岗位身份、版本、期限和准备／提交／回滚接口。增加的字段按以下职责划分，具体名称在实施计划中落定：

| 值 | 所属与作用 |
| --- | --- |
| 小队协作等级与配置版本 | board 持有的唯一团队权限来源；成员快照引用该版本 |
| 成员能力和当前状态摘要 | Context 发布训练资格、可移动性、弹药、压力与真实火力；不传动作实例 |
| 站位建议及候选键 | 第二档使用，带身份与固定有效期；没有强制岗位与同步承诺 |
| 部署意图及岗位候选集合 | 第三档计划使用，表达保持、集中或分散，以及每个成员的职责 |
| 行动者与支援者的依赖 | 引用真实成员、请求与岗位；给出准备条件、完成条件和固定截止时间 |

现有 `advanced_enabled` 仅在旧接口适配层保留，不同时充当新小队模式开关。新协议统一使用 member、ally、target 等概念和明确目标身份；当前 `sees_player`、玩家专用伤害与区域启停逻辑由原适配层提供事实，不进入新增纯规划接口。后续接入友方 AI 时更换目标与成员适配，不复制另一份团队决策。

## 结构与性能边界

配置放在现有 `scripts/enemy/config/`，调节器和规划逻辑仍在 `services/`；原 `enemy_cooperation_action.gd`、接敌、掩体、换弹、搜索和压制动作承担各自候选及执行。保留脚本 UID、场景路径、个人训练资源以及玩家执行实现。

新增部署比较、支援组合和第二档建议共用既有规划预算，不能为每种策略各自再消耗一套上限。保留有限 offer 数、组合次数和空间分帧额度；静态地图继续区域共享，提交和执行时恢复真实查询。当前文档记录的多人及部分单人性能尚未达标，实施后应保留基线对照和实际总耗时，不以局部耗时或功能通过代替原性能门槛。

## 验收要求

三档必须在同一组真实场景夹具中比较，不能仅检查枚举值或岗位字段。

1. 配置：同队不同兵种与不同个人 Training，团队等级始终一致，个人战术仍不同；两队共用模板但计划和运行状态隔离；保存重载、整队热切档、离场与重生均清理旧版本。
2. 第一档：真实目击能共享，失视不更新隐藏目标，个人照常移动和开火；不产生包抄建议、主动掩护任务、换弹排班或同步等待；原基础间距及枪线保护仍成立。
3. 第二档：改变友军站位能改变侧路或互补位置建议，并由正常 AI 循环产生真实移动；队友未就位不触发共同等待；没有安全包抄路线时继续合理个人行动。
4. 第三档部署：分别构造需要集中支援、适合分散包抄和应保持原位的场景，检查实际位置、可用射界和前线保留；不能只验证 `posture` 标签。
5. 第三档配合：实际推进、撤退和换弹期间有真实支援重叠；验证先到支援位再掩护、普通射击与已训练压制两种执行、接替支援和全部空匣回退。
6. 同步与异常：未就位或旧版本反馈不释放行动；断路、失视、死亡和降档在固定期限内修复或结束；紧急自保及身体不可打断阶段保持原合同。
7. 权限与复用：近战成员不被分配枪械支援，未解锁压制者不能执行压制；纯 planner 可接受不叫 enemy/player 的成员与目标身份，且不读取场景或隐藏目标。
8. 回归：运行现有完整敌人组、相关玩家／复位专项以及原性能与预算检查，另用 1／2／3／6 人场景验证三档。保留当前本地基线失败及候选差异，不调整用户地图或放宽断言来制造通过。

设计阶段只进行接口核对、文档自查与链接检查；上述运行验收属于后续实施，不作为已通过结果。
