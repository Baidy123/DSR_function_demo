# 半身掩体与角色姿态及翻越设计

日期：2026-10-08

状态：设计稿，等待完整文档审阅；尚未实施。用户已确认的要求列在下一节，其余技术方案和默认参数作为本稿的设计提案，不视为已实现或已完成试玩验收。

本阶段让玩家与敌人使用半身掩体完成蹲藏、起身交火、绕侧或翻越的战斗过程，并将所有角色的站立高度统一为 1.75 米。玩家直接控制姿态和翻越，敌人通过现有动作与 Utility 选择方案；双方使用一致的实体遮挡和通行规则。

维护依据：[项目结构](../../project-layout.md)、[敌人 AI](../../enemy-ai.md)、[敌人验证](../../enemy-tests.md)、[玩家战斗](../../gameplay/COMBAT.md)、[近战](../../gameplay/MELEE.md)、[弹药](../../gameplay/AMMO.md)、[声音逻辑](../../gameplay/HEARING.md)和[表现接口](../../gameplay/PRESENTATION.md)。本稿不覆盖这些文档已有的职责分层和维护约束。

## 用户已确认的要求

1. 先讨论计划与设计，最多使用 3 个 agent，分工覆盖掩体本身、玩家动作、敌人 AI 动作及优化。
2. 所有角色的站立高度调整为 1.75 米，包括玩家、全部敌人和 NPC。
3. 玩家手动蹲下、手动站起；只有矮墙挡住当前瞄准方向时，瞄准才临时请求起身。松开瞄准后回到手动选择的蹲姿；手动选择站起后保持站立。开阔处或背向矮墙可以蹲姿瞄准。
4. 起身空间不足时保持实际蹲姿，观察点与枪口跟随实际身体姿态。
5. 玩家按空格翻越矮墙，敌人也具有翻越逻辑。
6. 玩家和敌人翻越期间不能射击或近战，但仍会受伤；落地后恢复攻击能力。
7. 玩家翻越后朝当前观察方向，不强制转回原掩体。落地按手动姿态恢复，可继续蹲姿瞄准；不因仍按着瞄准而自动站立，也不恢复翻越前的掩体临时起身状态。
8. 蹲起和翻越属于基础执行能力，由原有行为选择使用，沿用兵种、训练和 Utility 分层。
9. 必须制作可见的蹲姿模型。用户选择沿用胶囊占位风格，提供明显变矮的蹲姿和姿态过渡。
10. 不破坏原有结构与框架，依据现有 MD 修改和维护代码，并同步相关说明。
11. 玩家蹲下后枪械精度提高 0.25，仅对玩家生效，并通过 export 提供可调参数。采用现有 0～1 精度值的加法，例如 0.5 变为 0.75，上限为 1。
12. 玩家蹲在半身掩体后，敌人接近应有发现机会。实施时先验证实际视线能否可靠发现；若墙体仍挡住蹲藏玩家，允许采用可配置的近距离准确位置情报兜底，不预先认定靠近就一定能看见。该情报提供触发时的准确位置，与原先只提供大概位置的“作弊”搜索提示区分。
13. 敌人通过近距情报获知准确位置后，或原本目击玩家而因玩家蹲下丢失视野时，都可以产生对半身掩体的压制候选。是否压制继续由现有 Utility AI 与其他行为比较，不增加随机概率开关。
14. 玩家和敌人的移动声音均采用倍率，各自可调；普通移动作为基准，蹲行约 0.5 倍、奔跑约 2 倍，数值可在试玩时调整。

## 必须保留的结构约束

保留原场景入口、节点路径、脚本 UID、资源引用和模块职责。新增半身掩体预设与必要辅助资源按现有目录归属放置，不迁移原场景、不另建统一角色框架。1.75 米身高与姿态造成的必要几何变化属于本任务，地图布局及其他玩法数值按用户当前本地配置保留。

敌人继续由身体执行、兵种与训练装配、独立动作、公共服务和 Utility 共同工作。新增执行意图应向后兼容，原动作 ID、默认行为类别、已有配置值和训练选择不因本任务重排。翻越段有明确协议，不能悄然把旧地面路径数组解释成可越墙路线。

公共几何只提供查询结果；玩家与敌人保留各自攻击、受击和生命周期，不把公共查询扩展成双方共用的战斗执行框架。实现前核对本稿与专项 MD；冲突按用户明确要求和原设计解决，不通过改写原文档或降低测试要求迁就实现。

## 当前工程基础

玩家、敌人和 NPC 的主要胶囊站立高度为 1.6 米。多处感知、枪口、瞄准点和近弹检查使用脚底上方 0.8 米。身体遮挡已有三维采样，真实弹道使用首次射线碰撞；增加低掩体时需要一起更新这些高度来源。

`cover_region.gd` 根据实际碰撞盒生成四面躲藏候选与两端出口，攻击区域主要位于四角。半身掩体需要增加沿墙面同一落点的蹲藏与起身交火方案。

当前敌人普通导航输出地面路径点，各行为按水平方向移动，尚无翻越路段的识别和执行。直接增加跨墙导航连接会让旧执行把跨墙段当作平地行走。本稿采用显式翻越路段，保留原普通导航的语义。

现有搜索已经包含快速追查和接敌后持续警戒。半身掩体接入必须保留线索年龄、提示边界、有限路段及持续搜索规则，不能重新引入搜索总时限解除警戒。

当前玩家普通移动声与奔跑声分别导出独立半径，默认 3 米／6 米；敌人普通／快速移动也为 3 米／6 米。默认效果相当于 2 倍，但尚不是以普通半径计算的倍率。声音系统目前只发出听觉事件，未播放实际音效。

身高调整本身不缩放武器射程、近战距离、声音半径、现有掩体推断距离或地图水平尺寸；移动声音另按本稿的倍率要求调整。尤其 `melee_range` 的 1.6 米是攻击距离，与旧角色身高无关。导航代理和烘焙所用的通行高度需匹配新站姿；导航重新烘焙基于用户当前本地地图。

增加复用现有掩体结构的低掩体场景，保留原 `CollisionShape3D`、`Mesh` 和表现节点路径。高度、厚度、旋转和缩放均依据实际碰撞盒；可翻越标识只允许尝试查询，不能保证可通行。原高掩体继续作为高掩体使用。

低掩体提供四面蹲藏位置、同落点起身位置、两端绕行出口和满足条件的翻越入口／落点。是否受到保护由真实射线和身体轮廓决定；被绕侧、被高处攻击或敌人靠近后越过墙沿看见头肩时允许实际发现与命中，实际开火仍需枪口射界成立。编辑器预览区分蹲藏位置、起身交火位置和可翻方向，运行时继续复核。

## 姿态与几何查询

身体分别保存姿态请求与实际姿态。实际姿态包括站立、蹲伏及切换进度；翻越有独立的执行进度与移动占用。各身体实例拥有自己的形状和运行状态，不能写回共享资源而影响其他角色。

| 查询内容 | 用途 |
| --- | --- |
| 当前身体形状与局部中心 | 碰撞、受击、通行检查 |
| 实际观察点 | 感知与目标可见性 |
| 实际开火点 | 子弹起点、枪口空间检查 |
| 身体可见采样点及选定瞄准点 | 发现局部露出的角色、自动锁定、准星和射击目标 |
| 假定姿态的身体形状及点位 | 只读评估将来到达、蹲下或起身是否可行 |
| 姿态请求结果和切换状态 | 输入反馈、动作接续和互斥 |

观察点、开火点和瞄准点分别提供，调用方不各自继续硬编码 `+0.8`。当前实际点位随过渡更新，起身完成前不能提前取得完整站姿高度。膨胀身体前检查新增空间，头顶受阻时停止起身，不把枪口单独抬到障碍上方。

敌人评估未来站姿位置时使用假定站姿查询，不能借用此刻的蹲姿碰撞体或低枪口。缓存应区分所用姿态、身体尺寸和几何版本，候选评估不得移动身体或切换实际姿态。

视线检查可以发现目标露出的头肩，射击仍从实际枪口向选定可见点执行首次碰撞。眼睛可见而枪口被挡时允许发现目标，子弹继续被障碍拦下。锁定准星与开火目标使用同一选定点，避免准星指向墙后的固定胸口。没有姿态接口的旧静态目标保留兼容瞄准方式。

## 玩家操作与动作衔接

手动蹲起的建议默认按键为 C，空格绑定独立翻越输入。输入从现有未处理输入入口接入，尊重对话和 UI 对按键的消费。蹲行接入原普通移动及锁定移动两条分支，保留原加减速、转向和横移语义。

| 手动姿态选择 | 瞄准输入与当前掩体条件 | 实际目标姿态 |
| --- | --- | --- |
| 蹲伏 | 松开瞄准 | 蹲伏 |
| 蹲伏 | 按住瞄准，当前方向被近处矮墙阻挡且站起可越顶观察／射击 | 临时请求站立，条件解除后回蹲 |
| 蹲伏 | 按住瞄准，开阔处、背向矮墙或没有上述掩体条件 | 保持蹲伏并正常瞄准 |
| 站立 | 任意瞄准输入 | 站立 |

手动选择站立会清除自动回蹲的意图。掩体辅助起身不覆盖手动选择；松开瞄准、转向不受该矮墙阻挡的方向或离开掩体时，恢复手动选择。辅助条件按假定蹲姿的观察／枪口高度和当前方向查询，不能因实际已站起、枪线变通畅而立即回蹲，造成反复起蹲。高墙不因枪线受阻就触发无效的起身尝试；实际起身仍受头顶空间约束。

翻越开始清理旧掩体辅助状态并暂停旧锁定目标对朝向的牵引。落地保留手动姿态，按当前观察方向重新评估普通瞄准和当前环境，旧锁定不能把角色立刻拉回原掩体方向；只有新环境再次满足上表条件才允许新的掩体起身。解除旧锁定引用与姿态转换不借用会清空扳机、改变精度的 `cancel_aim()`；瞄准输入和武器状态仍按原各自规则处理。

### 玩家蹲姿精度

配置放在玩家现有 Combat 脚本的蹲姿精度分组，拟定 export 字段 `crouch_accuracy_bonus`，范围 0～1、步长 0.01、默认 0.25，0 可关闭。该字段不放入玩家与敌人共用的 WeaponData，也不由敌人读取；不会因两方使用相同武器资源而把加成传给敌人。

保留现有基础 `accuracy` 与移动、连射、受击、恢复等待和切槽记忆。实际完成蹲伏且不在翻越中时，只读计算 `effective_accuracy = clamp(base_accuracy + crouch_accuracy_bonus, 0, 1)`；站立、开始起身或翻越时取消这项加成。不能对基础精度反复累加或把加成写入槽位记忆，因此连续蹲起不能把精度刷满。

旧概率模式用有效值作为中心命中概率，例如 50% 变为 75%；散布锥模式用有效稳定度走原最小／最大散布角插值，不将其解释为真实命中率增加 25%。基础值已为 1 时仍封顶为 1。实际射击、准星和状态显示读取同一有效值。

原换弹期间与完成帧的强制最低精度、近战受击强制清零及该次恢复等待，优先于蹲姿加成；不能在清零后立即通过加成显示或使用 0.25。该限制只跟随这些原强制清零情形，不把每次普通射击或移动产生的等待都当作禁用加成。蹲起、重新瞄准或切枪不能清除强制清零及其恢复限制。蹲在矮墙后临时站起射击时，按实际站姿取消蹲姿加成；在开阔处或背向矮墙保持蹲姿射击时可获得加成。

### 其他动作衔接

以下是配套默认规则，作为本稿提案审阅，不作为此前已有的用户要求：

- 蹲起和蹲行不额外消耗耐力，蹲姿限制奔跑；站起后继续原奔跑与耐力规则。玩家蹲姿枪械精度加成按用户新增要求接入，敌人不获得该加成。
- 蹲起不改变换弹方式、进度、半程记忆或切枪基础精度。换弹本身不触发站立或回蹲，姿态继续由手动选择和当前有效的掩体辅助条件决定。
- 有效翻越开始时沿用玩家原换弹半程策略中断换弹，翻越中不推进或自动续换，落地后按原规则恢复。失败翻越请求不改变换弹。
- 蹲姿按近战键时，先验证战斗资格、体力和起身空间，再请求起身；真正开始挥击前再次核对区域、武器、体力、生命和对话状态，通过后才扣除一次体力并开始前摇。等待起身期间切枪、开始翻越、离场或失去资格会取消请求，重复按键不排队。挥击结束按手动姿态及当前掩体／瞄准条件恢复。不能起身时拒绝攻击，不扣体力或冷却。
- 近战前摇与收招期间拒绝翻越；翻越中直接调用射击和近战入口也必须拒绝。姿态或翻越结束不重置原攻击冷却。
- 翻越期间忽略新的开火点击，不在落地时补发；自动武器只可继续翻越前已由未被 UI 消费的按下事件形成、且未被取消的扳机状态。松键、取消瞄准、换枪、换弹等原清理规则继续有效，不能仅根据鼠标仍按住而重建扳机。落地恢复攻击能力不等于自动补打一枪。
- 翻越期间保留原切枪能力及各槽状态规则，但换装和表现刷新不能解除翻越占用、推进换弹或自动续换；落地后再按原规则处理当前枪械。

对话冻结姿态输入并保留实际身体；死亡和重开沿原生命流程处理。玩家死亡目前暂停世界，翻越进度一起停止，重开由场景重载恢复站姿。普通受击保留姿态，不自动把蹲伏者拉起。

## 移动声音倍率

玩家与敌人分别在原身体脚本的“移动声音”分组配置，不改变声音资源、武器资源和感知的职责。保留普通移动基准 `movement_noise_radius`，默认 3 米；新增 export 蹲行倍率 `crouch_noise_multiplier`，初值 0.5；玩家奔跑倍率 `sprint_noise_multiplier`、敌人快速移动倍率 `fast_movement_noise_multiplier` 初值均为 2。字段名是本稿接口提案，数值按用户给出的试玩方向设置，倍率 0 可关闭对应模式的声音。

一次事件的无遮挡听觉半径为“本角色基准半径 × 当前移动模式倍率”。普通行走倍率为 1，蹲行与奔跑／快移互斥，不将 0.5 和 2 相乘。依据实际身体姿态和本帧有效移动状态选择，不能只看手动蹲姿请求或尚未执行的快移指令；起蹲过渡可随实际姿态进度在普通与蹲行倍率间插值。敌人因换弹等原因实际限速后沿用普通或实际蹲行模式，保留原快移判定语义。

以 3 米基准为例，普通行走、蹲行和奔跑分别为 3、1.5、6 米。此处倍率作用于敌人可听范围，当前不涉及音频音量。隔墙后继续乘 NoiseData 中原遮挡倍率，默认 0.4，对应 1.2、0.6、2.4 米；调试圆圈读取同一事件半径。真实水平位移与原发声间隔仍是触发条件，站着、原地蹲起、转向或完全顶墙不发脚步事件。姿态切换不额外重置发声间隔，避免连续蹲起重复发声。

倍率只作用于移动事件；玩家与敌人的枪声继续由各自 WeaponData 的 `shot_noise_radius` 决定，蹲姿不让枪声变小。声音事件继续记录发声瞬间的位置，敌人不会由一次脚步声持续获得隐藏玩家的实时坐标；来源过滤、听觉开关及声音调查权限沿用原规则。

旧 `sprint_noise_radius`／`fast_movement_noise_radius` 保留兼容读写入口，正常运行以基准和倍率作为唯一配置来源。基准大于零时按旧快速半径除以基准换算，保留用户自定义有效范围；基准与旧字段完整加载后再归一化，不受属性保存顺序影响。旧快速半径为零转换为倍率零。旧基准为零但快速半径非零时无法直接换算，应保留隔离的旧配置兼容覆盖，直至该实例明确改用倍率配置，不静默关闭原快速声音或打开原普通声音；纯倍率配置基准为零则关闭全部移动声音。当前主场景未保存这些半径覆盖，原默认 3／6 米可直接迁移为 3 米乘 1／2。兼容入口不再作为另一套可同时调节的正常检查器配置。

## 可见蹲姿与表现

玩家和敌人均提供胶囊风格的站姿、蹲姿和连续切换表现。站姿外观对应 1.75 米，蹲姿外观明显变矮、脚底保持原位，正面标记随有效身体高度调整。提供可复用的蹲姿网格或场景资源以及过渡驱动，不能只增加姿态状态、碰撞变化或调试文字。

蹲行保持蹲姿外观，并根据实际移动更新现有移动表现；顶墙停止时不得仅因按着方向键而播放持续位移。翻越提供清楚可见的撑起、跨过和落地过程，身体实际执行进度驱动表现。胶囊占位不要求骨骼、IK 或正式人物美术。

扩展现有表现状态快照和动画配置，表达实际姿态、姿态进度、蹲行以及翻越进度。已有模型挂点和适配器保持职责，动画不得直接改玩法根节点、碰撞、弹药、生命或执行阶段。

没有外部模型和动画时，内置胶囊仍完整表现蹲姿与翻越。接入外部模型后可配置对应动画；缺少蹲姿片段时，蹲伏期间回退到可见的胶囊蹲姿，站起后恢复原模型，避免用直立模型遮盖真实低姿态。暂停保留并冻结过渡进度，恢复后继续；死亡与复位按各自生命周期取消或重置，保留原死亡表现优先级。

相机继续跟随水平移动，过滤翻越造成的短暂垂直抬升，保留真实地面高度变化。通过现有相机配置或项目内适配处理，不修改第三方插件源码。

## 翻越的几何与执行

本阶段的翻越对象为可翻越矮墙。普通行走仍使用现有导航；翻越不是自由跳跃，也不把任意高墙作为攀爬对象。

玩家靠近墙体时，存在移动输入则以输入方向寻找墙面，静止时使用朝向。仅允许有限距离和小角度对齐，不能从远处吸附到入口；按住空格不连续发起翻越。站姿和蹲姿均可发起。

公共只读查询返回墙体引用、入口、翻越轨迹、落点、所需姿态与失败原因。查询核对真实墙高和厚度、起点地面、整个身体的越墙通道、头顶空间、落点地面和完整站立空间。只检查一条射线或最后落点不足以证明整段可通过。

玩家和敌人分别持有自己的翻越执行与生命周期，公共部分只提供几何结果和时间估计。碰撞形状扫掠覆盖抬升、越墙和下降全过程；不能关闭碰撞后直接搬到墙另一侧。起翻和落地前再次检查实际动态占位，真实身体校验不能排除对方角色。

翻越从接受请求起占用自主移动和朝向，射击、近战与换弹执行入口统一检查该占用。普通方向输入和 AI 重选不能在半空中覆盖轨迹。取消预定轨迹与结束身体动作分开处理：受阻或受推后进入安全下落，仍保持禁射、禁近战与禁换弹推进，直到真实安全落地；死亡、复位或卸载按各自生命周期终止，不能借取消轨迹提前恢复攻击。

| 情况 | 收尾规则 |
| --- | --- |
| 几何检查失败 | 保持当前动作，不扣翻越资源或中断换弹 |
| 普通枪伤 | 正常扣血和施加原准度惩罚，继续当前可行轨迹 |
| 近战推移 | 中断预定翻越轨迹，保留伤害与外力，经身体碰撞和重力安全落地；落地前维持攻击互斥 |
| 动态阻挡或墙体变化 | 停止不再合法的路径段，使用碰撞移动与重力处理落地，期间维持攻击互斥；不传送至入口或终点 |
| 暂停 | 身体、计时和表现同时冻结 |
| 玩家死亡 | 沿用死亡暂停，停止输入和执行请求，重开恢复场景初态 |
| 敌人死亡 | 停止主动路径并保留碰撞／重力收尾，按原死亡与复位职责清理 |
| 敌人普通重评或撤销发起动作 | 不启动新翻越；已离地的身体先完成安全收尾，再交回决策 |
| 战斗区复位或场景卸载 | 使用原复位语义清理姿态、轨迹、计时和引用，不恢复旧动作请求 |

建议初次试玩采用约 0.8 秒的有效翻越时长、无额外耐力扣除；这是设计默认值，待手感验证。路径估时必须使用身体真实配置，不能为了提高翻越评分给出更短的虚拟耗时。轨迹所需最小通行时间与空间校验优先于配置，明显无效的设置应拒绝。

## 敌人动作与路线选择

蹲起和翻越由身体及其服务执行，原动作只提交请求并查询结果。保留原协调器、兵种／训练装配、动作实例和共同评分；协调器可以转交新增执行意图，但不能按动作 ID 强制选择翻越或掩体。

现有远程兵与近战兵都接入翻越能力。能力资格可按原兵种机制表达，翻越不增加独立战术解锁项；原训练只控制它本来允许的战术及对应参数。

远程掩体动作增加同落点蹲藏和起身观察／射击的方案，保留两端探出。到掩体后换弹、移动途中换弹和原地换弹继续参与原决策，姿态与翻越互斥按身体规则处理。翻越开始前中断敌人原换弹执行，落地后由原换弹动作决定下一次请求，不套用玩家半程保留机制。

近战兵沿用基础躲藏、掩体接近、普通接近和短程突进的分层。矮墙可作为躲藏与接近掩护，移动方案比较绕侧和翻越；翻越落地后重新核实距离、真实可见性与遮挡，再请求原近战执行。突进与翻越具有各自时限，不能靠切换路线返还突进时长或冷却。

敌人蹲姿近战也采用先起身再挥击的提案。动作可以请求起身与后续近战，但资格查询和实际执行入口都要检查实际站姿、空间、距离和遮挡；未完成起身或头顶受阻时不能直接出手。起身期间目标失效或原方案取消时丢弃未执行请求，不能只靠某个战术的 `tick()` 限制。

公共路线方案有两类：普通地面绕行，或“地面行走到入口 → 单次翻越 → 落地后继续地面行走”。一份方案最多含一次翻越，落地后可重新规划下一段，不承诺跨多墙的全局最优路线。

选中动作持有路线与当前路段进度，共用服务只读。普通导航只执行当前地面段；到入口后由动作请求身体翻越，真实落地后再提交下一地面段，不能从一开始就让 NavigationAgent 直奔最终目标。动作取消后不恢复旧路线，身体安全收尾不回调其他动作实例来继续旧方案。

| 行为范围 | 翻越路线的使用方式 |
| --- | --- |
| 远程接敌和攻击占位 | 比较到达合法射击位置的绕行与翻越方案 |
| 掩体转移与换弹移动 | 比较到达安全落点的时间、暴露及换弹中断代价 |
| 近战接近与掩体推进 | 比较接近已知目标或掩体落点的绕行与翻越方案 |
| 追查和区域搜索 | 通往原调查目标时评估翻越，保留目的地和证据年龄 |

候选同时计入步行与翻越时长、越墙时的身体暴露、禁攻击时间和信息损失，再送原共同 Utility 评分。路线准备和候选查询沿用共享分帧预算；不在每个行为每帧穷举全部墙面。原普通地面方案始终保持自己的可用性校验，不能用翻越结果把不可行的地面路径标成可走。

正常翻越期间，原调查路段、突进时限、冷却和证据年龄继续推进；世界暂停时按原规则冻结。时限耗尽或撤权只使原方案失效，已离地的身体仍先安全落地，随后丢弃旧请求并重新决策，不暂停原计时以延长战术效果。

首版暂不向原导航地图直接加入跨墙连接。若后续改用带路段元数据的导航连接，需要一起更新所有路径消费者、估时和执行，作为后续独立扩展审阅。

### 对半身掩体的火力压制

沿用已解锁的普通压制与出口压制、有限时长和枪数规则。候选有两种明确依据：原本真实看见玩家，随后因其蹲下等遮挡变化失视，使用最后目击位置；或下文近距兜底报告了触发时的准确位置，即使该敌人此前未目击玩家，也可提供相应候选。是否采用压制仍由现有 Utility 与绕行、翻越、搜索等合法行为比较，不增加随机概率门槛，也不保证每次都压制。

玩家蹲下导致失视走原视觉由可见变为不可见的事件，不要求感知失败后再读取隐藏玩家姿态来确认原因。敌人自身执行躲藏方案导致的失视仍保留原排除规则，不能因增加蹲姿而把它也当作新的压制触发。未取得上述合法证据时，不能直接根据隐藏玩家实际上在墙后来提供候选；只有原模糊搜索提示也不构成新的压制资格。

在原公共上下文／服务内提供供压制消费的明确证据快照，包含来源、冻结位置、取得时间、有效期限与事件标识；普通压制和出口压制的资格、几何查询、信息收益及执行目标使用同一份依据。视觉来源保留原最后目击与失视年龄；近距准确情报使用自己的时间衰减，不能为获得新鲜度而改写 `last_seen_position` 或重置视觉年龄。两类依据都继续通过原武器、反应、射程和执行互斥检查。原搜索提示即使配置为零误差，也不能因坐标恰好准确而取得近距情报的资格；区别依据是来源。

普通压制除证据记录的目标区域外，可根据相关矮墙的实际高度和快照位置采样可能起身暴露的墙沿区域。出口压制继续针对两端可能绕出的位置，墙沿不冒充第三个出口，也不修改原两端信息收益公式。共同环境推断仍放在原共享服务中，不能让普通压制依赖可选的出口压制实例。

压制目标可以落在墙面、墙沿附近或合法出口，真实子弹始终在第一次碰撞处结束。枪口近处受阻、武器资格、弹药、反应和枪口转向仍按原射击执行校验。不能仅因正在压制就让墙后玩家扣血、增加准度惩罚或被视为重新目击；近弹影响继续按实际弹道、距离与遮挡判定。

复用原掩体推断距离、压制范围、时长、枪数与证据衰减参数，不增加“蹲在矮墙后必被压制”的强制分支。同一近距事件只提供一次有限压制机会，候选重评、普通／出口方案切换或反复消费同一事件不能重新开窗、返还枪数或续时。情报过期、缺少有效射击区域或武器条件失效时，由原规则结束并重新决策；实际露头重新被看见后，按原目击更新接敌。

## 感知与信息边界

真实感知可以用实际身体与姿态判断当前是否看见目标；只有真实可见时才写入目击。失视后的瞄准、移动候选和翻越评分只用已有目击、声音、配置允许的提示或下述近距准确情报，不能自行读取隐藏玩家的实时姿态和位置。近距情报是用户允许的准确位置来源，必须与真实目击、声音和原“作弊”搜索提示分别记录，不能混成同一种带误差的提示。

翻越期间仍从当前真实眼位进行感知；禁止攻击不冻结观察。重新目击可按原规则形成证据，但新的战术移动或攻击需等待身体到达允许切换的安全边界。

真实视觉继续复用原 `close_awareness_radius`，当前缺省 2 米且保存的训练配置优先。近身警戒放宽方向限制，保留遮挡检查；感知从实际眼位向头顶、肩部等少量真实身体样本检测。站立敌人接近时是否能越过矮墙看见蹲藏者，取决于墙高、厚度、双方离墙距离及地面高差，不能作为已保证的结果。看见头肩后更新原目击记忆，实际开火另行核对枪口到可见点的射界。

实施时先在目标墙高、蹲姿高度和合法贴墙位置下验证远近视线，并覆盖旋转、厚度与高差。如果常见近距位置仍全部被遮挡，按用户允许的方案启用可配置的低掩体近距准确情报；不为通过验收而抬高蹲姿、忽略射线碰撞或改变原近身警戒的含义。保留试验场景与结果，说明最终是否需要启用兜底。

兜底由感知层检查，提案限定为玩家实际蹲藏、双方在同一有效半身掩体两侧且都靠近该墙，双方相距足够近；高墙、隔层及中间额外实体阻隔不能触发。开关与距离放在原训练感知参数中，独立于视觉距离；初次视线验证时关闭，必要时开启，距离可从 2 米试调，该数值是建议初值。触发时只向该敌人报告玩家当时的准确位置、情报来源及时间，不加搜索误差、不重新抽样，也不广播给全部敌人。一次近距接触只报告一次，短暂蹲起或切换动作不重新触发；须离开略大的退出范围一段时间并经过冷却后才可重新报告，避免边缘抖动或持续贴墙形成实时追踪。接触状态由感知实例保存，复位清除，参数遵守原训练覆盖和保存机制。

近距事件作为非视觉的准确位置证据进入原记忆／上下文，供搜索和具备权限的压制候选使用，保留统一评分，不直接指定绕行、翻越或攻击。仅感知层在判定和触发时获准查询隐藏玩家，动作只接收冻结的位置快照；后续安静移动不自动刷新。事件可以按本稿形成自己的有限压制机会，但不能设置 `sees_player`／`has_visual_memory`、刷新最后目击时间或制造玩家运动及换弹观察。听觉开关只控制声音，不兼任近距情报开关；真实目击仍优先，原射界、近战遮挡及首次碰撞规则始终有效。

复用 `context.event_received → AI._dispatch_event → 各动作 on_event` 传递独立来源的近距快照，由搜索和压制动作按各自职责消费，不调用声音或受击入口冒充其来源，不新增搜索动作或公共状态枚举。搜索必须显式接纳该调查落点，不能只改 `last_known_position` 后仍被旧 `last_seen_position` 覆盖；调查仍使用原可达校验、有限路段和 Utility，并尊重当前执行的安全切换边界。仅有近距情报时获得有限调查与压制机会，不因此伪造永久视觉交战警戒；已有真实目击者保留原持续警戒。重复消费同一情报不能重置原搜索累计时间、搜索提示衰减或压制窗口。

翻越入口和出口来自静态环境几何。AI 规划阶段不以隐藏玩家的动态占位改变候选排序；实际身体执行前和过程中必须检测真实角色阻挡。执行碰撞只报告该路线不可执行，不能顺带制造目击事件或把碰撞查询坐标写入目标记忆。

看见头部可以发现目标，但换弹观察还需相关躯干或武器区域可见，不能隔矮墙读取被遮住的换弹进度。已形成的短时换弹证据继续使用原失视记忆与撤销规则。

搜索覆盖按保守的可藏身体高度核实墙后空间，不能因为站姿眼位看见矮墙上方就把可能藏有蹲伏角色的区域算作已调查。判定不读取隐藏玩家当前姿态。翻过墙本身不增加覆盖，也不刷新目击年龄、提示概率、快速追查时限或搜索总计时；实际观察到的地面才可计入覆盖。

## 文件职责与三名 agent 分工

以下为拟定修改位置，具体辅助文件由后续实施计划确定，不迁移原节点、脚本或 UID。

| 负责人 | 主要范围 | 交付责任 |
| --- | --- | --- |
| 主 agent | `scripts/world/cover_region.gd`、公共只读几何、低掩体场景、共享表现类型、场景与导航整合、文档 | 掩体和翻越几何；1.75 米尺度一致性；共享接口；联合验收与阶段提交 |
| 玩家 agent | `scripts/player/`、`scripts/ui/lock_reticle.gd`、玩家姿态与翻越执行 | 输入、姿态意图、碰撞与武器点位、动作互斥、玩家脚步倍率、表现适配及回归 |
| 敌人 agent | `scripts/enemy/`、相关兵种能力配置、敌人专项 | 姿态与翻越执行；公共上下文与路线接入；候选、近距感知、脚步倍率、射界、搜索与性能 |

`presentation_state.gd`、`animation_profile.gd`、`visual_presentation.gd` 和共用模型资源由主 agent 统一维护；双方适配器消费同一协议。`main.tscn`、`enemy.tscn`、`project.godot`、共享导航和训练资源由主 agent 统一整合，避免两个 agent 同时改同一保存文件。

玩家与敌人各自管理攻击、受击和执行阶段，公共几何不读输入、不选择战术、不替双方推进计时。动画只消费实际状态，物理状态不依赖是否有动画素材。

以当前本地工程为基线，保留地图、武器、训练和插件的已有修改。不拉取或合并远端；本地撤回无关内容产生的删除不能混入本阶段提交。

## 分阶段实施与验收

| 阶段 | 可独立检查的结果 |
| --- | --- |
| 一 | 1.75 米站姿、可见胶囊蹲姿与过渡、角色几何查询、低掩体预设；玩家和敌人各自的姿态可运行 |
| 二 | 玩家蹲行、自动起身／回蹲与翻越；敌人身体能安全执行同类翻越，执行互斥有效；双方脚步倍率与旧配置兼容 |
| 三 | 远程、近战、掩体转移和搜索自主使用路线；实测近距视线并按需接入情报兜底；候选比较、隐藏信息边界及动作接续符合原结构 |
| 四 | 主场景接入、回归与实机试玩；同步玩法、结构、表现和测试说明，按实际结果记录限制 |

共享接口先完成审阅，再并行推进双方适配。各阶段必要验证通过、相关文档同步后单独提交并普通推送到约定远端，提交仅包含本阶段核对过的文件。

验收至少覆盖以下行为和结构：

- 玩家、所有敌人和 NPC 的站姿外观与碰撞均为 1.75 米，脚底正确；蹲姿明显可见，多实例互不影响。
- 蹲藏、起身露头、侧绕和高处视线都遵循真实遮挡；实际枪口不能穿墙；锁定点、准星和真实射击一致。
- 先记录同一蹲藏位置在远近视线、双方离墙距离、墙体旋转／厚度及高差变化下的实际可见性，不把接近必然可见作为前提。全部样本受挡时仍不写入目击；可见但枪口受挡时不穿墙射击。
- 若启用近距情报，验证有效矮墙范围内报告的是触发瞬间的准确位置，没有旧搜索提示的误差；关闭或范围外不触发，高墙、隔层和额外阻隔不误报。持续停留、短暂蹲起和动作切换不反复更新，离开并冷却后才可重新报告。从未目击与已有目击者都能接纳准确调查落点，不被旧记忆吞掉；该情报允许压制候选，但不伪造目击、换弹证据或永久视觉交战警戒，训练保存重载与复位有效。
- 只有当前瞄准方向被可利用的矮墙阻挡时才自动起身，转向或离开后回到手动姿态；开阔处和背向矮墙能蹲姿瞄准，辅助起身不会反复起蹲。手动站起覆盖、头顶受阻仍按原规则处理。
- 翻越落地面朝当前观察方向、保留手动姿态，旧锁定和旧掩体状态不会使角色转回墙面或因按住瞄准无条件站起。
- 玩家蹲姿精度加成默认 0.25、封顶 1，export 保存重载有效；敌人不受影响。验证两种模式、射击／准星／显示一致、站起和翻越撤销、连续蹲起不累加，以及换弹／近战受击强制清零及恢复等待不被加成绕过。
- 玩家和敌人的脚步倍率分别可调，3 米基准下普通／蹲行／快速分别产生 3／1.5／6 米事件；验证隔墙衰减、调试圈、换弹限速、停止或顶墙不发声，以及蹲起不刷事件。枪声不受影响，实例配置互不污染。
- 保留已有声音模式、零值关闭、快速半径自定义与换弹限速的验证覆盖；补充倍率保存重载、旧半径换算和旧基准零但快速非零的兼容检查，不能删除这些行为断言来迁就参数改名。
- 站姿和蹲姿可发起合法翻越；厚墙、高墙、低顶、无落地地面及动态占位会拒绝或安全收尾，过程中可被实际击中。
- 翻越中直接调用攻击接口仍无法消耗弹药或造成近战伤害；落地后按原输入和冷却恢复，暂停、死亡和区域复位不留下执行占用。
- 受阻或受推转入下落后仍禁攻击，真实落地才恢复；原动作半空中到期或撤权，落地后不续旧请求。
- 真实 Utility 能在更合适时自主翻越，在绕行代价更低时绕行；远程、近战和搜索均有自主行为覆盖，不能通过测试强选动作代替验收。
- 选中翻越路线确实按地面段、翻越段、后续地面段执行；双方蹲姿起身后才可挥击，头顶受阻和等待期间资格失效均拒绝攻击。
- 固定已知证据且没有新的合法感知事件时，隐藏玩家的移动、蹲起和换弹不会改变不应知情的候选排序；近距兜底的合法触发单独验证。翻越和抬高眼位不会错误清空蹲藏区域的搜索覆盖。
- 分别验证“目击玩家后因其蹲下而失视”和“此前未目击、仅收到近距准确位置”两种情况下，原 Utility 能选择对低掩体墙沿区域或两端出口的压制，并可在其他方案更合适时放弃压制；不新增随机概率开关。敌人自身躲藏造成的失视仍不触发，只有旧模糊提示时也不新增压制资格，即使将旧提示误差配置为零也不能混用来源。
- 保持相同已知证据并移动或移走隐藏玩家，压制候选与采样不跟随隐藏位置变化。近距快照评分和执行使用同一位置与本来源的年龄，不修改视觉年龄；普通／出口重选和重复事件消费不续时、不返还枪数。验证真实挡弹、弹药或窗口耗尽后的退出及重新目击接敌。
- 高掩体、原近战／射击／换弹、训练装配与已有搜索规则回归；检查节点路径、UID、模块依赖和资源保存。
- 运行完整敌人回归、玩家战斗回归及必要的表现和资源保存专项；新增查询保留原单次 20 毫秒、完整 AI P99 16 毫秒／最大 50 毫秒等既有门槛，不通过放宽门槛或重设用户配置取得通过。
- 图形窗口确认胶囊蹲姿、蹲行、翻越、起身交火和镜头效果。自动测试通过与用户手感验收分别记录。
