# 第五关后续波次的组合规划漏解修复

日期：2026-10-27。

用户报告第五关第二、第三波出生后常显示警戒并停在原地。本记录说明已确认的组合规划问题、修复及验证边界；不是新的关卡或小队行为要求。

## 原因与现场

保存地图的第二波使用普通配合，第三波使用强配合，均为六人队。成员能收到一次性 `wave_spawn` 线索，导航出生检查有效。停滞快照中，整队规划器返回 `no_complete_layout`：已检查256个完整组合，搜索栈仍有22项，尚未触达包含安全警戒岗位的可行组合。对同一份纯值输入单独校验，存在23个“部分成员推进、其余安全留守”的合法完整方案。

原深度优先枚举按单项代价排序，大队伍的大量低价候选可能因通行、观察或岗位关联相互不兼容。在有限枚举结束前没有找到可提交方案时，协调器继续保留临时警戒任务；只有出生警戒标签并不证明已获得移动任务。

现场还存在另一类情况：已成功安排部分成员，但其他成员因候选或通道冲突长期警戒。用户另一个任务正在处理该恢复逻辑；本阶段不修改协调器、联合让路或接敌补点，不把规划漏解修复等同于所有长期警戒均已解决。

## 实现与职责

原 `enemy_team_planner.gd` 在全员都有合法警戒候选时，先用这些候选构成初始完整表，再逐成员试入已有候选，保存通过全部检查的可行方案，随后继续原整队全局比较。无警戒候选的输入继续走原枚举。

初始表的资格、岗位关联、目的地间距、枪线、完整通行顺序、强配合准备／离开路线和掩护依赖均复用原检查。尝试次数与节点数计入原256／2048上限，帧截止后保留游标续算；未提高预算、放宽几何或授予训练外动作。全员警戒表只作为无解时的安全后备，不用它的同分代价剪掉0权重下可推进的方案。协调器的联合让路仍取得真正尝试过的推进布局，而非全员警戒表。

未修改场景、出生点、导航、训练、枪械、波次开关、线索权限及成员执行接口。实际发布仍由原协调器对当前身体状态再次校验并整体提交。
