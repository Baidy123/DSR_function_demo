# 爆头扩展：秒杀、防护训练与独立被爆头状态

设计日期：2026-10-25；实施更新：2026-10-26。状态：**已按用户最新方向实施，移除 `_todo` 后缀。**

前置[基础概率爆头](2026-10-25-headshot-mechanics-proposal.md)保留为历史记录，当前使用本文件与[射击说明](../../gameplay/COMBAT.md#精准爆头2026-10-25)。本次不改写用户武器、图样、训练预设或地图。

## 1. 用户要求与本轮调整

- 玩家开火前达到最准精度，真实弹道命中后才判定爆头。不做身体部位分伤、不增加额外瞄准等待；敌人射击和近战不获得此奖励。
- 概率降低，武器启用秒杀且敌人没有防护时直接死亡；否则按武器倍率伤害，默认3倍。
- **Enemy → Training → Profile → 作战能力 → 爆头防护** 只提供一个正向复选框。开启免秒杀，但不免倍率伤害和存活后的被爆头状态。无需再套分组、子资源或“支持爆头秒杀”反向开关。
- `tactics` 只改检查器显示为“作战能力”；保留内部字段、模块键、文件名、资源引用和UID。
- 霰弹**每枪、每个实际命中目标只判定一次**；命中多个敌人分别判定，未命中者不参加。
- 武器侧所有相关参数必须公开导出、可保存到原资源，外部脚本可读写。

**用户实施中的最新调整优先于原“停止所有动作”方案：**用户担心强制接管影响Utility AI和协调器，要求独立“被爆头状态”，随后明确不要禁射，应复用近战已有的受击效果。最终仅通过现有受击出口限制速度与精度；不取消AI动作、不暂停AI、不注入协调器占用／失败，也不添加枪械禁射门槛。转向、姿态、换弹与近战保留原流程。用户另明确：状态效果参数同样由攻击武器资源决定，不能在身体里写死。

数值来源：用户先确认概率10%、0.6秒、连续状态保留较长剩余时间、防护默认关闭；随后提出1秒速度／精度归零的简化方案并明确采用该类限制。本实现以1秒作为新状态初值，其余已确认初值保留；各枪均可独立修改。没有把任何现有兵种自动改成“戴头盔”。

## 2. 配置与外部接口

所有武器字段都在原 WeaponData 的 **精准爆头（仅玩家）** 分组：

| 检查器／公开字段 | 脚本默认值 | 语义 |
| --- | --- | --- |
| 启用爆头 `headshot_enabled` | true | 玩家精准命中奖励总开关 |
| 爆头概率 `headshot_chance` | 0.1（10%） | 每枪每实际目标一次，0关闭、1必定触发合格命中 |
| 启用爆头秒杀 `headshot_instant_kill_enabled` | true | 还需目标没有爆头防护；关闭则使用倍率伤害 |
| 未秒杀时伤害倍率 `headshot_damage_multiplier` | 3.0 | 总伤害300%，不再额外叠加旧倍率 |
| 被爆头状态时长 `headshot_stagger_seconds` | 1.0秒 | 存活者状态时长，0关闭 |
| 被爆头时保留移速 `headshot_movement_multiplier` | 0.0（0%） | 0不能走动，1不减速，检查器按百分比 |
| 被爆头期间精度上限 `headshot_accuracy_cap` | 0.0（0%） | 不超过此精度，不抬高更差精度，不禁射 |
| 连续状态刷新方式 `headshot_stagger_refresh_mode` | KEEP_LONGER | 保留较长剩余时间；另一项RESTART按本次时长计时，不累加 |

旧资源显式保存的2.5等数值仍照常生效；未保存字段才使用脚本默认值。检查器数值和实际结算保持一致。修改单个实例时仍按原共享资源规则复制或设为唯一；运行时改值不会自动保存文件。

`WeaponData.get_headshot_settings(stability)` 返回经校验的纯值字典，包含概率、秒杀开关、倍率、时长、保留移速、精度上限与刷新模式；原概率／倍率查询接口继续可用。最准资格使用开火前有效精度，允许1e-6浮点误差，包含原蹲姿修正。非有限值、越界值和未知刷新模式统一处理，不在伤害执行层另写一套参数。

防护字段直接为 `TacticsSettings.headshot_protection`，默认false；true就是有防护。通过原训练显式覆盖查询，并沿个人实时读取、团队本场冻结规则；团队改训练后重载本场。身体通过Context注入的查询读取，不让玩家访问AI私有字段，不复制另一份防护状态。

检查器沿原插件提供中文标签、百分比、原生资源展开与撤销／重做；构造原生属性时跳过自身插件，避免递归。原 `Profile.tactics` 的外部脚本与存储接口不变。

## 3. 结算顺序

1. 原开火门槛／弹药流程，冻结开火前精度、伤害、武器爆头参数和命中效果。
2. 执行原射线；打空、墙挡、射程不足不产生补偿命中。“瞄甲打乙”结算真实被击中的乙。
3. 霰弹查完全部弹丸，按实际目标合并命中颗数；普通枪同样交给公共结算辅助。
4. 每个实际目标至多抽一次爆头概率；不合格、概率0不抽样，概率100%直接成立。
5. **全部目标的概率、防护、伤害和状态结果都在任何受击回调前冻结。** 回调改武器或另一个目标的防护不影响本枪，下一枪再读取新值。
6. 每目标一次受击。未爆头为原伤害；爆头按下表执行，死亡优先。

| 结果 | 伤害／死亡 | 存活状态 |
| --- | --- | --- |
| 武器允许秒杀且目标未开启防护 | 原生命与死亡出口直接死亡，不受剩余血量影响 | 不进入 |
| 武器不允许秒杀或目标有防护 | 实际命中普通伤害×武器倍率 | 存活且时长大于0才进入 |
| 倍率伤害已致死 | 原伤害死亡流程 | 不在死亡后追加 |

秒杀使用原死亡信号、波次减员、尸体与倒地流程，不直接删节点、不用任意大伤害替代死亡协议。每枪一次扣弹、后坐、枪声／开火通知；倍率不额外放大减速、精度干扰或击退。

例：每颗8伤害，敌人中5颗，基础40；无防护且允许秒杀则死亡，否则默认受到120伤害。10%概率与中1颗还是9颗无关；同枪两个目标各一次。保持全部射线先完成，避免前一个敌人死亡使后续弹丸穿透。

没有新敌人接口的旧训练靶／测试靶继续使用原受击入口与倍率反馈；训练靶只计数，不伪造防护、秒杀或敌人状态。

## 4. 独立被爆头状态：身体限制，不接管AI

`enemy_headshot_state.gd` 是由身体拥有的轻量RefCounted，保存剩余时间与本次武器效果快照。由原身体物理帧推进一次，不创建Timer、节点或第二个AI循环。复用已有 `apply_aim_penalty()` 和 `get_hit_movement_multiplier()`；不直接调用整个近战受击入口，以免再扣一次生命或产生额外击退。

- 状态保留移速来自攻击武器，默认0；与已有近战／枪击减速取较强者。最终倍率为0时不运行局部避让位移；不改共享移动速度资源。结束后其他尚未结束的减速继续，避免恢复陈旧速度。
- 通过原精度损失入口把精度降低至攻击武器上限，默认0%；本来更差时不抬高。状态内原恢复最多达到该上限；换枪不能重置限制。结束后按原精度恢复规则继续，不能瞬间补回。
- **不禁止开枪。** `can_fire()`、火控和射击入口保持原规则；AI仍可选择以当前精度发射。实际0%精度开枪及扣弹由身体专项验证。
- 不强制取消当前Utility动作，不清空团队任务，不注入额外占用或失败原因；感知、Utility和协调器继续自己的更新。原AI可以依原规则自然换动作或响应超时，不承诺状态期间永远固定同一个动作。
- 转向、跟踪瞄准方向、蹲起、换弹与近战保持原流程。已发出子弹与已结算伤害不撤回。
- 重力、碰撞、外力、受伤和死亡仍执行。最终受击移速为0时不开始新的自主翻越；零移速状态进入时若正在翻越，使用原身体安全落地分支，不让角色悬停在墙上。该处理只保障物理安全，不向AI发送“被硬直取消”的命令。
- 连续命中时效果强度更新为本次武器快照，剩余时间按KEEP_LONGER／RESTART策略处理，不累加；同目标每枪只请求一次。普通伤害不能提前覆盖本状态；本状态不再乘敌人的普通受击抗性，原普通受击仍遵守训练倍率。
- 暂停冻结；死亡、复位、退场、对话清理。换武器不解除，原训练查询在重新挂接后仍可用。

只读与通知接口：

| 接口 | 职责 |
| --- | --- |
| `receive_headshot_hit(damage, source, effects, reaction)` | 接受已冻结结果；共用原伤害／死亡流程，返回killed／staggered／headshot |
| `is_headshot_protected()` | 通过注入查询读取原训练防护 |
| `is_staggered()`／`get_stagger_remaining_seconds()` | 查询独立被爆头状态与剩余秒数 |
| `get_hit_reaction_state()` | 只读字典kind（headshot／none）、staggered、remaining_seconds、movement_multiplier、accuracy_cap |
| `stagger_started(seconds)`／`stagger_finished` | 给未来动画或表现层；持续刷新不重复进入通知，死亡清理也可能发结束通知 |

没有增加动画或让动画拥有时钟与解锁权限。准星消费 `headshot_resolved(world_position, outcome)` 显示“爆头击杀”“爆头 · 硬直”或“爆头”，不再显示爆头弹丸数；原 `headshot_hit` 信号保留兼容。

## 5. 结构与性能边界

- 不增加射线、碰撞体或逐弹丸反馈节点。霰弹抽样次数从命中弹丸数降到目标数；本枪结果只临时保存至结算完成。
- `headshot_resolver.gd` 只处理命中统计，既不选目标也不推进AI；玩家Combat保留射击所有权。
- 身体状态单时钟；不重写Utility、火控决策、协调器、波次或动画框架。Context新增内容仅为防护读取与注入。
- 保留用户调参、节点路径、旧资源结构和UID。未迁移原 `.tres` 字段，不运行远端同步覆盖本地。
- 实际速度与射击结果会被原AI观察到，因此可能间接影响其原有判断；“不接管AI”不是“所有战术行为绝对不受影响”的保证。

## 6. 验收与维护

定向覆盖真实射线、最准门槛、概率边界、每目标一次随机数、64颗弹丸、两目标回调快照、保护／秒杀／倍率致死、资源保存重载、直接复选框及原生撤销／重做。实际命中验证非默认40%移速／20%精度上限与非法值校验；身体验证精度0%时仍可实际射击、原减速共存、换弹和近战不被取消、连续刷新、暂停、换枪、对话、死亡／复位及翻越安全落地。

独立真实场景专项分别运行个人、普通协作和强协作：爆头瞬间原动作与任务保留；默认状态内本人不能自主位移、精度为0但AI证据时钟继续、队友实际开火；结束后由原流程继续实际射击。新增波次用例从最后一人的爆头秒杀入口验证减员、下一波与连续倒地尸体。没有通过修改AI候选、强制接受任务或延长期限使测试通过。

具体结果和保留诊断见[验证记录](../../enemy-tests.md)。这些定向验证不代表全部战术组合或整场帧率保证；未运行完整项目回归，也没有正式动画验收。
