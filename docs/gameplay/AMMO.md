# 弹药、换弹与缺弹掉落

Equipment 管理按弹种共享的备弹和各槽弹匣，WeaponData 保存枪械配置，WeaponAmmo 保存实例状态。玩家按 **R** 主动换弹；敌人由 AI 请求。拾取弹药只增加备弹，不直接补弹匣。

## 在哪里调整

| 位置 | 参数 | 作用 |
| --- | --- | --- |
| Player → Equipment → 初始共享备弹 | Initial Ammo → Ammo / Amount | 可扩展的出生备弹列表；旧四类未覆盖时保留原初值，脚本缺省各36发 |
| Equipment的主／副武器资源 → 射击与弹药 | Ammo Definition / 旧 Ammo Type | 资源定义类型；留空兼容原四类，同类主副枪共用一个备弹池 |
| 同上；敌人则展开Enemy的Weapon | Magazine Capacity | 弹匣容量，脚本默认12发；每把枪独立保存余量 |
| 同上 | Reload Seconds | 正常换弹秒数，脚本默认2秒 |
| Player → Combat | Sprint Reload Speed Multiplier | 奔跑中开始的慢速换弹进度倍率，默认0.5；整次耗时为快速换弹的两倍，途中停跑不加速 |

以上是脚本默认值，后续检查器调参优先，未覆盖用户已有武器设置。弹匣出生时装满，这部分子弹不占初始备弹。武器类型不等于射击模式，单发／自动与弹药类型分别配置。

右下角原武器栏显示每槽`当前弹量/容量 · 备弹数量`，换弹时显示进度百分比和“快速／奔跑会中断”或“慢速／可跑”。快速换弹暂停在半程时提示停跑后继续；收起的武器也标记已保留的50%。这些信息不依赖 Debug。备弹显示的是该武器所用类型的共享备弹，不是两份独立存量。

## 弹药资源与缺弹掉落

现有资源位于 `movement_demo/resources/ammo/types/`，可以直接在 Godot 文件系统中双击打开：

| 文件 | 类型／盒子颜色 | 每包数量初值 |
| --- | --- | --- |
| `rifle.tres` | 步枪／绿 | 15～30 |
| `pistol.tres` | 手枪／黄 | 6～12 |
| `smg.tres` | 冲锋枪／蓝 | 15～30 |
| `shotgun.tres` | 霰弹／红 | 3～6 |

这些数量是资源可调初值，**不根据武器弹匣换算**。在资源中设置 `Allow Random Drop`、`Drop Min Count`、`Drop Max Count`；上下限相同就是固定数量，要求最少1且最大值不小于最小值。四种普通弹药已开启掉落，新建类型默认关闭。

总弹药＝该类型共享备弹＋两把携带枪的同类匣内余弹，收起的枪也算；尚未切换到的枪按原满匣出生规则计入。同类只统计一次共享备弹，使用携带武器中的最大弹匣作为参考。严格低于一半才触发；两类都缺时比较“总量／容量”，比例最低者优先，平局主槽优先。有空余名额时掉一包，随机的只有数量。

**每个区域最多两包未拾取弹药**，所有弹种共用这两个名额；同帧尚未生成的包也占名额，霰弹同时杀死多人不会超量。达到两包后停止新的死亡掉落，拾取一包后允许后续新击杀再掉；不会补发之前被上限阻止的包。地面弹药仍不计入玩家库存，上限独立于缺弹判断；生成失败、区域重置或离场会释放相应名额。

掉落放在死者附近可达地面，不能放在墙顶或跨层；近处没有合法地面时跳过并给出诊断。默认靠近0.8米自动领取，墙体和不同楼层会阻挡；死亡、对话或暂停期间不领取，恢复后无需走出再走入。领取只加备弹，仍按 R 换弹。普通击杀、爆头、霰弹多人击杀均按每名敌人的实际死亡各结算一次。弹药跨波保留，离开区域、区域重置或卸载时清理，不进入跨重开的剧情库存。

弹药盒与名称／数量标签在渲染层级置顶，尸体和掩体不会挡住显示；位置仍取实际落点，自动拾取继续检查距离及墙体。置顶只修改该包的材质副本：标准／ORM材质保留颜色和贴图，无材质或自定义Shader使用标准材质显示模型，原模型资源不改写。

### 新增弹药与更换模型

1. 在 `resources/ammo/types/` 新建 **AmmoDefinition** 资源并保存 `.tres`，填写唯一 `Ammo Id` 和显示名称。仅改文件名不会改变类型。
2. 设置是否允许掉落、数量上下限。在 **掉落外观 → Drop Model** 拖入一个模型场景。
3. 在武器资源 **射击与弹药 → Ammo Definition** 拖入该资源。旧 `Ammo Type` 留作兼容；显式资源优先，此时隐藏旧选项。
4. 在 **Player → Equipment → 初始共享备弹 → Initial Ammo** 增加 **AmmoSupply** 条目，设置 `Ammo` 与 `Amount`。不填新类型则初始备弹0，出生弹匣仍装满；填写0不会被旧默认36覆盖。

盒子模型位于 `scenes/presentation/ammo/`，可复制后修改材质或换成正式模型。模型须为 **Node3D纯外观场景**，原点放在底面中心，避免碰撞／拾取脚本；通用拾取场景拥有检测与数量标签。更换模型或调整外观尺寸不改变拾取范围。空模型或不合要求的根节点回退到可见黄色盒子，仍可正常领取。

高级武器若不应获得随机补给，请使用独立弹种并关闭 `Allow Random Drop`；与普通枪共享同一弹种时，它们也共享捡到的备弹。ID、武器弹种和出生配置修改后重开生效，当前弹匣和已生成的包不会因热改资源ID换成另一种弹药。

旧场景四个 `starting_*_ammo` 字段保留加载，检查器统一展示解析后的资源列表；新列表逐类覆盖旧初值，未覆盖者保留原场景值。重复初始类型诊断并保留第一项，不累加；同ID资源的开关／数量／模型冲突时共用库存但暂停该类型掉落，请统一引用后重开。

玩家按R主动换弹，打空不会自动换；敌人由AI在弹匣打空后请求换弹。双方换弹时都能移动、转向，不能开枪。

上述整匣规则适用于 WeaponData 的 Fire Mode 单发／自动，以及未开启逐发装填的霰弹，旧资源编号保持。Fire Mode 选近战后没有可用弹匣和备弹，拒绝射击、消耗弹药及换弹，只允许近战兵装备；方法见 [近战说明](MELEE.md#近战兵装备近战武器)。

敌人头顶独立显示真实换弹百分比和剩余秒数，关闭 Debug 也显示，切换到接敌或攻击站位时保留；完成或取消后自动隐藏。动作与生命文字仍仅在 Debug 中显示：先到掩体再换弹为“前往掩体，准备换弹”，边走边换已补满但尚未抵达为“换弹完成，继续前往掩体”。之前统一显示“换弹安排”可能让此时靠近后的恢复射击看似瞬间换好；实际换弹计时不受玩家距离影响。

## 玩家规则

- R只在有枪、非死亡、非对话和非暂停时生效，场外也能准备换弹。满匣、无备弹或已经换弹时不重启。
- 按 R 成功开始时读取 Player 的 `is_sprinting`，整次换弹方式固定。非奔跑时开始＝快速换弹；奔跑中主动按 R＝慢速换弹，允许边跑边换，途中停跑也不会加速。切枪后的续换保留原快慢方式。
- 快速换弹中允许开始奔跑，但会立即中断。不到50%时清零并保持取消：停跑后可用匣内余弹开火，必须再按 R 才从零开始；达到50%（含恰好50%）时只保留50%，奔跑期间暂停，停跑后自动从半程续换，完成前余弹也不能开火。
- 再次中断强制续换仍只保留50%，不会保留后半程的额外进度。R不能在奔跑中把已保留的快速半程转换成慢速以绕过暂停。耐力与瞄准锁定原有的奔跑限制继续生效。
- 切枪对快、慢换弹都使用上述半程规则。不到50%时取消；达到50%时该枪保留半程，收起期间不计时，切回自动续换。奔跑中切回快速半程枪先等待停跑；慢速半程枪可边跑续换。另一把枪的弹量、开火能力与换弹进度独立。
- 普通受击不中断。进入对话或死亡按原生命周期规则清理当前枪的换弹，暂停世界时不推进也不自动续换。
- 蹲起不改变已经选定的快慢换弹方式、计时或半程；蹲姿准度加成不能抬高换弹及完成帧的强制最低准度。蹲姿近战等待起身期间不推进或自动续换，真正开始挥击才沿原半程规则中断；等待请求取消后恢复原换弹流程。
- 成功开始翻越沿用原半程中断规则；失败的翻越请求不影响换弹。翻越与受阻后安全下落期间不推进或自动续换，R请求拒绝；仍能切枪并保留各槽状态，切回半程枪也需等待真实落地才能自动续换。未新增共用 Ammo 的翻越规则，互斥仍由玩家 Combat 管理。
- 完成时只补足弹匣缺口，保留旧弹匣余弹；备弹不足则全部装入。未完成时不提前扣备弹。
- 若收起期间同类备弹被另一枪用尽，仍允许完成保留的后半程；只装入届时实际可用的备弹，完成后恢复匣内余弹可用，避免永久禁射。
- 切回武器保留弹量；共享同一个WeaponData的两槽也各有独立弹匣。开始换弹清理待发扳机，完成后重新按左键开火。
- 重新开始恢复配置的初始武器、满弹匣、共享备弹及其他场景初态，仍保留对话选择。

## 霰弹的可选逐发装填

在武器 **Shotgun → 逐发装填** 开启 **Shell By Shell Reload** 后，每完成一发才入匣并扣备弹；满匣或备弹用完结束。容量继续用原 Magazine Capacity，每发耗时用 Shell Reload Seconds（默认0.6秒），不使用整匣 Reload Seconds。默认关闭，原武器配置不会被改写。

该模式下，玩家新按右键瞄准可以中断；有余弹时瞄准新按左键也能中断并尝试开火。按住右键后再按 R 不会自动取消。中断、切枪或快速装填被奔跑打断时，保留已经装入的子弹，未完成的一发清零、不扣备弹、不保存50%阶段，之后按 R 重新补弹。原奔跑中开始的慢速倍率、暂停、对话和死亡规则继续生效。HUD显示当前这一发的进度，弹量随完成逐发增加。

敌人沿原请求与取消入口使用相同弹药状态，第一发完成不自动结束换弹；UI、原动作估时和协调快照通过 `ammo.reload_remaining_seconds()` 取得补满所需时间。`include_progress=false` 可只读评估打断后重装的耗时。未改变谁决定换弹的职责。完整操作及资源来源见[霰弹说明](SHOTGUN.md#一发一发装填)。

## 敌人规则与结构

换弹由已选择的动作请求：个人模式（无小队或0级）让原地换、先到掩体再换、边转移边换与其他候选共同评分；1／2级继续由协调器选择任务，并通过原换弹动作执行。身体的 `request_reload()` 只负责开始基础装填，不自行决定战术；动作切换保留已经开始的基础进度。换弹计时固定，期间可普通移动和转向、不能快移，结束恢复动作速度。

低墙后原地换弹、转移到低墙换弹都会主动请求蹲姿；蹲下过渡不暂停、重置或加速装填。个人评分对附近安全掩体提供软偏好，按实际路线长度和相对原地的真实遮蔽收益折减。参数在 **Training → Profile → Cover** 的 `Reload Cover Preference`（默认6，0关闭）和 `Reload Cover Preference Distance`（默认4米）；0偏好仍保留低墙蹲换弹与防护判断。团队采用原共同命令和协调约束，详见[敌人 AI](../enemy-ai.md)。

`scripts/weapons/weapon_ammo.gd`是小型RefCounted弹药状态对象，负责消耗、计时和补充，供玩家与敌人共用；WeaponData只保存配置。玩家Equipment持有以 `StringName ammo_id` 为键的共享备弹字典与各枪状态，Combat引用当前枪；Enemy自己持有无限备弹状态，近战兵不能请求枪械换弹。`ammo_snapshot()` 只读合并当前携带弹药，`add_ammo(definition, amount)` 只增加备弹，返回实际入账数。掉落选择与区域生命周期在 `ammo_drop_controller.gd`，有限地面检查在 `ammo_drop_position.gd`，`ammo_pickup.gd` 执行显示和一次领取；敌人AI和协调器不参与库存逻辑。

半程策略由玩家 Combat 决定；共用 Ammo 只提供通用 `suspend_reload(checkpoint)`、阶段保存和续换能力，不读取奔跑输入或训练配置，敌人未启用暂停策略。Equipment 为各槽保留弹药状态与快慢方式，收起武器不推进计时；没有把运行进度写入共享 WeaponData 资源。

换弹期间沿用当前移动和转向、跟枪与冷却，头顶状态追加“换弹中”。普通受击不取消换弹；死亡、换枪、失去兵种枪械资格、对话取消，离场刷新恢复满匣并等待再次激活。暂停随世界停止计时。压制仍按原定时规则结束，只统计实际开出的枪；敌人的掩体换弹由现有 AI 选择，详见[敌人武器](ENEMY_WEAPON.md)。

## 常用接口与验证

Equipment 的 `ammo_snapshot()` 返回只读合并数据，`add_ammo(definition, amount)` 返回实际入账数量；WeaponAmmo 的 `suspend_reload(checkpoint)` 提供通用进度保存，半程策略由玩家 Combat 决定。掉落、合法落点和领取分别由 `ammo_drop_controller.gd`、`ammo_drop_position.gd`、`ammo_pickup.gd` 管理。

对应专项为弹药、玩家换弹／续换、霰弹逐发装填与 `ammo_drop_test`，入口及现有局限见[测试说明](../testing.md)。修改资源 ID、弹种或初始库存后重新加载场景验证，不能从旧弹匣或已生成掉落推断新配置已生效。
