# 敌人波次使用说明

这套系统让你在场景里摆好各波敌人，然后按顺序出场。每波可以有多个小队，可以等上一波全灭再出场，也可以过几秒就加入战斗。日常配置不需要写代码或填写敌人名单。

## 先用第一关试玩

打开 `movement_demo/scenes/world/levels/lvl_1.tscn`，按 **F6** 运行当前场景。玩家在战斗区域内时开始第一波，清掉第一波后进入第二波。最后一波结束后不自动跳关。

第一关的结构示意如下，实际人数以你保存的场景为准：

```text
Lvl1
├── Squad                         ← 第一波的小队，在这里改首波敌人
│   ├── Enemy
│   └── Enemy2
└── EnemyWaves
    ├── Wave1                     ← 引用上面的 Squad，下面没有子小队是正常的
    └── Wave2
        └── Squad                 ← 第二波的示例小队
            ├── Enemy
            ├── Enemy2
            └── Enemy3             ← 用户从第一波移入的成员
```

**为什么第一波下面是空的？** 第一关已经有你摆好的 `Lvl1/Squad`。为了保留它的路径和配置，Wave1 通过检查器的 **兼容已有场景 → Existing Squads** 引用它，路径是 `../../Squad`。这代表第一波使用那个小队，并不是漏放了小队。修改第一波时直接选根目录下的 Squad 或其中的敌人。

基础接入阶段曾保存第一波两人、第二波三人的示例，其中 Enemy3 从第一波移入。两波都使用第一关近战预设，实例覆盖可以不同；人数和位置都可以继续调整，不是固定配置或最终难度安排。

把敌人从一波移到另一波时，将它拖到**目标波次的 Squad 下面**即可。比如从 `Lvl1/Squad` 拖到 `EnemyWaves/Wave2/Squad`，它就只属于第二波；需要改变刷新位置时再在3D视图移动它。不要让同一小队同时被多个波次引用。

## 常用修改

| 想做什么 | 在哪里操作 |
| --- | --- |
| 调整第一波 | 选 `Lvl1/Squad` 及其敌人 |
| 调整第二波 | 选 `EnemyWaves/Wave2/Squad` 及其敌人 |
| 改刷新位置、朝向 | 在3D视图移动、水平旋转敌人或整个小队；不要缩放角色 |
| 改血量、速度、武器 | 选敌人根节点，修改 `Max Health`、`Move Speed`、`Weapon` |
| 改个人训练 | 展开敌人的 `Training → Profile` |
| 改小队配合等级 | 选 Squad，展开 `Profile → Level` |
| 增加一名敌人 | 把敌人／兵种预制拖到对应 Squad 下，或者复制已有敌人再移开 |
| 同一波增加另一个小队 | 把 `scenes/world/squad.tscn` 拖到该 Wave 下，再放敌人 |
| 增加一波 | 复制当前第一关的 **Wave2**，改名后调整部署；也可以拖入 `scenes/world/enemy_wave.tscn` |
| 调整先后顺序 | 在 EnemyWaves 下调整 Wave 节点的上下顺序；不是按名字里的数字排序 |
| 等上一波全灭再加入 | 选对应 Wave，勾选 `Wait For Previous Clear`（默认开启） |
| 按时间加入，允许多波同场 | 选对应 Wave，取消 `Wait For Previous Clear` |
| 设置等几秒加入 | 选对应 Wave，修改 `Start Delay Seconds`，单位秒；计时起点见下表 |
| 删除一波 | 删除对应 Wave 节点；至少保留一波有敌人的有效部署 |

第一关增加波次时优先复制 **Wave2**。直接复制 Wave1 会复制同一个已有小队引用，需要清掉新副本的 `Existing Squads` 并放入独立小队，否则会提示重复引用。

复制敌人或小队后务必移动到合适位置。同波成员不能重叠；不同波可以使用同一组刷新点，但到时间时若仍被前波敌人占住，就会等待位置空出。需要同时出场的波次最好分开部署。

如果实例下面无法添加或编辑子节点，右键 `EnemyWaves` 开启 **可编辑子节点**。需要修改敌人内部的 Training 等节点时，可对对应敌人实例开启同一选项。

节点上的血量／速度等普通属性可以按单个实例覆盖。武器、训练和小队 Profile 是资源：编辑共享 `.tres` 会影响其他引用者。只想改一个实例时，先在资源菜单中选择**设为唯一**，或另存一份资源再使用。

## 波次顺序与加入时间

只看 **EnemyWaves 下面同一层 Wave 节点从上到下的顺序**：最上面是第一波，紧挨着它下面的是第二波。名字只是标签；把名叫 Wave3 的节点移到最上面，它就成为第一波。Wave 下面的 Squad 和敌人属于这一波，不单独计波数。

选中要调整的波次，设置这两个参数：

| Wait For Previous Clear | Start Delay Seconds | 这一波什么时候加入 |
| --- | --- | --- |
| 勾选 | 0 | 紧邻上一波全灭并清理后，尽快加入（默认行为） |
| 勾选 | 3 | 紧邻上一波全灭并清理后，再等3秒加入 |
| 不勾选 | 5 | 紧邻上一波实际出场后过5秒加入，不必等它死亡 |
| 不勾选 | 0 | 紧邻上一波出场后尽快加入，允许同时作战 |

第一波没有上一波，开关对它不影响：等待秒数始终从本轮战斗开始算。计时只累计本区域正常运行的时间；暂停、对话和玩家死亡期间冻结。

“上一波”只指紧挨着上面的那一波。例如第二波按时间加入，第三波勾选等待全灭，则第二波全灭后第三波可以开始等待，即使第一波还有敌人。最终完成仍须所有波次都已出场、所有敌人都死亡。

波次不会越过尚未出场的上一波。若第二波的刷新点被占住，它会等待；第三波的计时不会提前开始。`Start Delay Seconds` 是最早加入时间，不会绕过位置检查强行刷新。

## 在另一张地图中使用

本工程的 `lvl_1` 至 `lvl_5` 都有共用战斗区域接口。第二至第五关没有自动编排敌人，可以自己部署。

1. 打开目标关卡，把 `scenes/world/enemy_waves.tscn` 拖到关卡根节点下。一个战斗区域只放一个 EnemyWaves。
2. 把 `scenes/world/enemy_wave.tscn` 拖到 EnemyWaves 下，命名为 Wave1；再把 `scenes/world/squad.tscn` 拖到 Wave1 下，最后把敌人／兵种预制拖到 Squad 下。
3. 在导航面上摆好位置和朝向，留出完整身体空间。复制整个 Wave1 创建更多波次，并调整树中顺序。
4. 保存场景，保证有原项目的玩家节点，按 F6 运行。

新地图推荐这种层级，编辑时每波的小队都在它下面：

```text
关卡根节点
├── CombatZone
├── NavigationRegion3D
├── Player
└── EnemyWaves
    ├── Wave1
    │   ├── SquadA
    │   │   ├── Enemy
    │   │   └── Enemy2
    │   └── SquadB
    │       └── Enemy
    └── Wave2
        └── Squad
            └── Enemy
```

已有地图需要保留小队路径时，才使用 **Existing Squads**：增加数组项，把本区域的已有 Squad 从场景树拖进去。同一个小队只能属于一波，不能同时引用其他区域的小队；引用小队后不用再登记其每个成员。

## 运行时会发生什么

- 默认玩家进入所属 CombatZone 后开始。最后一名玩家离开该区域，所有受管波次实例清理，下次进入从首波重新开始。
- 每波达到自己的出场条件后才进入运行场景；尚未出场的部署不会提前碰撞、行动或计入目标。按时间加入可以让多波同时作战。
- 一波中的所有小队一起出场，独立统计所有成员死亡。尸体不需要自然消失；该波全灭后只清理该波，不影响其他仍在战斗的波次。
- 刷新点被玩家、敌人或其他可移动物体占住时，**整波等待**；让开后再生成，位置不变。
- 暂停、玩家死亡和对话期间不推进等待；对话结束后继续剩余时间。
- 所有波次都已出场且全灭后停止。最后出场的波先死光，也会继续等待更早波次的存活敌人。胜利画面、剧情跳转和存档需要另外接入。

平时无需改控制器设置。`Auto Start On Enter` 默认开启；`高级设置 → Spawn Retry Seconds` 默认0.25秒，表示被占位时多久重新检查一次，不是强制生成的倒计时。

## 没有刷出敌人时怎么检查

先看场景树节点的黄色配置提示，再看 Godot 输出中的 `EnemyWaves` 警告。

| 现象／提示 | 处理方法 |
| --- | --- |
| 上一波没死完，下一波就加入 | 检查下一波的 Wait For Previous Clear；需要全灭后加入就勾选 |
| 第一关 Wave1 下没有 Squad | 正常，它引用 `Lvl1/Squad`；去根目录下修改第一波 |
| 日志提示 Wave1 “has vanished” | 第一波继承引用失效；重新载入已修复的关卡场景，再运行 |
| 空波次／小队没有敌人 | 给该波添加 Squad，并把敌人放到 Squad 下；或者删除不用的空波 |
| 同一小队属于多个波次 | 删除重复的 Existing Squads 项；每一波使用独立的小队部署 |
| 小队必须属于本区域 | 将引用改为当前区域的小队 |
| 同波胶囊重叠 | 把同波敌人分开；只改名称不会改变占位 |
| 刷新点不在本区导航内 | 把敌人摆在本区有效导航面和 CombatZone 内，或按地图维护说明修正导航 |
| 与静态障碍相交 | 把刷新点移出墙、掩体或低顶，不只检查脚底是否露在外面 |
| 刷新点被角色／可移动物体占用 | 让占位物体离开，系统会按重试间隔再检查 |
| 等待导航同步 | 刚加载时属于正常等待；持续不变则检查 NavigationRegion3D 是否启用且有导航资源 |
| 活敌人被移除 | 不要用删除活节点代表击杀；战斗用原伤害入口，重新开始可恢复本轮 |
| 关闭了 Auto Start On Enter | 恢复勾选，或由自己的逻辑调用 `start_encounter()` |

静态摆放错误停止推进，需要在编辑场景修正后重新运行；临时角色占位会自动重试。系统不会跳过错误波次、自动挪动刷新点、推开玩家或超时强刷。

本轮开发中曾调整共用预制结构，已打开的旧场景仍保存了一个失效的 Wave1 继承引用，导致第二波被当成首波。这是预制修改衔接问题，不是把敌人拖入目标 Squad 的操作错误。当前每一波均为关卡中独立的波次实例，可以排序保存；如果编辑器仍开着当时的版本，请选择重新载入磁盘场景，避免保存旧缓存覆盖修复。

## 可选：接入自己的逻辑

```gdscript
# 例如关闭自动开始后，由机关启动。
$EnemyWaves.start_encounter()

# 查询当前状态，波次编号从1开始。
var status = $EnemyWaves.debug_snapshot()
print(status.status, status.wave, status.alive, status.pending, status.reason)
```

可连接 `wave_started(index)`、`wave_cleared(index)` 和 `encounter_completed()`。前两个编号从1开始，最终完成信号每轮只发一次；重复调用开始不会重复生成。重新开始整轮可以先 `reset_encounter()` 再 `start_encounter()`；生成仍会等待玩家在本区域可运行，清理完成前不会刷出新一轮。

多波同场时，`wave_cleared` 可以先报告第二波、后报告第一波。`debug_snapshot().alive` 是所有受管波次的总存活人数，`active_waves` 是仍有活人的波次编号数组；`wave` 是当前等待出场或最近出场的波次，不能当作唯一在场波次。

普通地图接入只需要场景配置，不需要调用这些接口。区域负责推进波次，其他脚本不要每帧再调用 `advance_from_region()`。
