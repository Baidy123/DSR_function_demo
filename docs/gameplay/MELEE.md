# 玩家与远程敌人近战

玩家近战、远程敌人的基础挥击与近战兵的专用武器已接入，双方各自实现攻击与受击。近战兵沿用原接近行为完成攻击；掩体接近等行为优化仍待后续。

## 操作与试玩

按 F5 运行主场景，进入战斗区域后走到敌人面前按 **V**。近战与射击使用相同的 `Combat.can_combat()` 区域限制；场外按 V 不会开始攻击、消耗冷却、打断换弹或播放剑光。无需瞄准或切换近战武器；使用当前手持枪械的近战参数。V 每次按下攻击一次，按住不会自动连击。

默认前摇 0.12 秒，之后在正面 90 度、水平距离 1.6 米以内选择最近的一个可命中目标，造成 25 点伤害。墙、门和掩体会阻挡；目标可以在前摇期间离开范围。挥空也会出现剑光并进入冷却。

敌人当前准度立即归零，之后沿用原有恢复等待和移动惩罚规则。默认向远离玩家的方向击退约 1 米，持续 0.2 秒；敌人自主移动会与外力合成，碰撞会阻挡或滑动，因此实际距离取决于场地。固定训练靶沿用命中计数／生命规则，不会被推动。NPC 不属于可攻击目标。

近战期间可以普通移动，朝向保持本次挥击方向，不能冲刺、射击、换弹或切枪。收招结束即可恢复其他武器操作；默认两次近战开始至少间隔 0.6 秒，切枪不能刷新冷却。

战斗区内有效的 V 近战可以打断换弹：未完成半程则按既有规则取消，完成半程则保留 50%，收招后恢复续换。被打断的开火请求会清除，继续开枪需要重新按下左键。近战不消耗子弹；每次成功开始挥击时扣除当前武器配置的体力，默认20点，体力不足则不能发起，也不打断换弹或消耗冷却。挥空、离场或中途取消均不返还已扣体力；一次挥击只扣一次，换枪不补充体力。把“近战体力消耗”设为0可关闭消耗。

体力沿用玩家现有的0～100数值与状态条。有效扣除后重新等待 `Stamina Recovery Delay`（默认0.5秒），再按原速度恢复；扣至0时，奔跑仍需等体力回满后才能恢复。近战只要求体力足够本次消耗，不额外要求回满。未装备武器、对话、死亡和暂停时不能发起近战；死亡、进入对话、本次所属靶场复位或失去有效战斗区域时，会取消未完成的挥击并清理剑光，不刷新已消耗的冷却。区域判定沿用射击规则：玩家必须与至少一个开启监测、属于 `combat_zone` 组的 Area3D 重叠；离开全部区域或区域停用、删除后，前摇中的攻击不再结算。

试玩重点：武器配置的范围是否合适、前摇与收招是否自然、击退能否创造需要的空间，以及近战与换弹的衔接。文中的默认值是脚本缺省值，资源中已保存的调参优先。

## 远程敌人

近战和射击、移动一样，属于敌人的基础执行能力，不是单独的默认行为或战术行为。现有“远程接敌”根据情况提供站定射击、直接退让、近战推开以及推开后退让等方案，交给既有 Utility 统一比较；近战方案标记为 `id = engage`、`plan = melee`，可附带已验证的退路。只在本竞技场激活、玩家可见、位于正面有效范围、没有遮挡且冷却完成时提供近战候选。近战不强制优先，但玩家持续贴近时能够实际选择。估计包含目标背后的碰撞空间、前摇期间已观察到的逼近，以及出手后的退让收益；不会把持续追近在整个窗口内一次性扣掉，也不会把挥击后的敌人一律当作原地站立。

选中后在前摇期间停步，前摇结束时再次检查目标，玩家可通过离开范围或躲到障碍后避免受击。命中后扣血、当前准度清零并物理击退；主副槽的准度记忆也归零，不能通过切枪绕过受击。伤害沿用生命入口，Debug 无敌仍只免除扣血。方案附带退路时，出手后即可在收招期间按原移动逻辑退让；路径失效则停步，不跳过收招。收招结束后重新交回 Utility，继续选择退让或射击。

敌人参数在 `Enemy → Weapon → 近战参数`，使用自己装备的 WeaponData；原有 `Shooting Enabled` 仅控制射击，近战由武器 `Melee Enabled` 控制。敌人没有体力系统，**“近战体力消耗（仅玩家）”在敌人这里无效**。挥击期间不能同时开枪或换弹；开始近战会取消自身换弹，之后仍由原换弹动作决定是否重新换弹。

身体冷却独立推进，切换动作、取消挥击和换枪不刷新冷却；死亡、失去区域资格、对话、动作权限撤销或装备变化取消未完成攻击，区域复位重置运行状态。暂停冻结计时。敌人 `EnemyPresentation` 提供可选近战动画和剑光，空素材不影响玩法。

基础能力存在于敌人共用的身体和服务中，由已选行为提交请求。远程 `ranged.tres` 保留原四个默认行为及原战术目录，没有近战训练勾选项。现有 `melee.tres` 保留巡逻、搜索、近战接近三个默认行为；接近行为现在会在合法范围内提交同一底层挥击请求，完成后继续原接近流程。关闭敌人武器的 `Melee Enabled` 可禁用挥击。本次没有优化近战兵的行为逻辑，也没有新增战术或调整 Utility 评分。

## 近战兵装备近战武器

在已有敌人的 `UnitType → Profile` 选择 `resources/enemy/units/melee.tres`，再给该敌人的 `Weapon` 选择 `resources/weapons/enemy_test_melee.tres`。无需创建另一个兵种、攻击节点或默认行为；地图中原有敌人的配置不会自动替换。

WeaponData 原有的 **共用参数 → Fire Mode** 现在可选“单发／自动／近战”，原单发0、自动1保持，近战为2；没有额外 Weapon Type。选近战后沿用下表数值，不能发射子弹或换弹，没有可用弹匣；检查器隐藏枪械字段但保留其保存值，切回单发／自动会恢复显示。

模式下拉框沿用原字段和原生撤销历史，由现有武器检查器在切换完成后延迟刷新；撤销／重做也会更新参数显示。这样即使已打开的资源在脚本热更新后漏发即时通知，直接资源面板和敌人内嵌 Weapon 面板仍能隐藏远程字段。维护时必须通过真实下拉框验证，不能只用代码直接赋值代替界面操作；专项覆盖见 [测试说明](../enemy-tests.md)。

专用近战武器只允许已有近战兵装备，其兵种通过原 capabilities 列表声明 `melee_weapons` 资格。玩家和远程兵不具备该资格：出生误配会提示并按未装备处理；玩家优先使用另一有效槽。运行时错误换装请求保留原有效武器，切换兵种导致资格失效时取消未完成挥击并卸下该武器。单发／自动枪械的附带近战仍可使用，玩家继续持枪按 V，远程敌人继续用枪械参数推开玩家。敌人体力消耗字段仍不生效。

近战兵沿用原导航、停止偏好和 Utility 候选，只补挥击请求及必要的攻击占用；停止距离限制在当前武器范围内，避免短武器够不到。掩体接近、突袭、评分与其他行为优化均留待以后。范围依据见 [最小接入设计](../superpowers/specs/2026-09-30-melee-weapon-and-melee-enemy-design.md)。

## 从枪械资源调参

选择 `Main → Player → WeaponSlots`，展开 `Primary Weapon` 或 `Secondary Weapon`，找到 **近战参数**。也可直接打开对应 `.tres`。射击伤害与近战伤害分别设置；两槽若引用同一资源，也会共享该资源的静态配置，单独调整时先复制资源。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `melee_enabled` | 开启 | 当前枪械能否近战 |
| `melee_damage` | 25 | 近战伤害，与 `damage` 子弹伤害独立 |
| `melee_stamina_cost` | 20点 | 开始挥击时的体力消耗；0关闭，不足则拒绝 |
| `melee_range` | 1.6 米 | 自身与目标脚底之间的最大水平距离 |
| `melee_angle_degrees` | 90 度 | 正面扇形总角度 |
| `melee_height_tolerance` | 1 米 | 允许的脚底高度差 |
| `melee_windup_seconds` | 0.12 秒 | 开始动作到实际出手 |
| `melee_recovery_seconds` | 0.25 秒 | 出手到恢复其他武器操作 |
| `melee_interval` | 0.6 秒 | 两次开始的最短间隔，至少覆盖前摇加收招 |
| `melee_knockback_distance` | 1 米 | 无障碍且目标不主动移动时的参考击退距离 |
| `melee_knockback_seconds` | 0.2 秒 | 击退外力衰减至零的时间 |

旧枪械资源没有保存这些字段时使用默认值。每次按 V 时固定本次参数，开始后的资源修改不会改变这一击。原有枪械伤害、弹药和瞄准参数未被改写。

“近战体力消耗（仅玩家）”只由玩家读取。敌人当前没有体力系统，即使敌人武器资源里显示此字段，修改它也不会影响敌人近战。

## 动画与剑光

玩家 `Visual/Presentation` 和敌人 `Presentation` 的 Animation Profile 提供 **Melee** 动画槽，填写模型中的片段名称即可。片段进度分别由玩家 Combat、敌人近战控制器的前摇加收招时间驱动，出手点位于 `前摇 / (前摇 + 收招)` 的归一化位置；默认约为 32.4%。素材的击打动作应与该位置对齐。没有该动画时回退 Idle，没有模型时仍正常攻击。

Combat 发出 `melee_started()`、`melee_struck(target)`（挥空时 target 为 null）及 `melee_finished()`；表现适配器读取 `melee_phase`、`is_melee_active()` 和 `get_melee_progress()`。结束或取消都会发出 finished；不要用动画回调来造成伤害。

Combat 的“近战表现 / Melee Effect Scene”默认引用 `scenes/effects/melee_slash.tscn`，留空仅关闭剑光。剑光约 0.14 秒后淡出，属于 Combat 的子节点，随角色卸载。替换场景需使用纯表现 Node3D 根节点，实现 `start(origin, direction, reach, angle_degrees)` 并自行结束释放；局部 -Z 为挥击正面。其脚本位于 `scripts/systems/effects/melee_slash.gd`，没有伤害或碰撞判定。

## 代码边界与验证

- 玩家攻击直接位于现有 `scripts/player/player_combat_v3.gd` 的近战函数区，没有新增玩家近战执行脚本或 Melee 节点。
- `player.gd` 配合移动、转向和对话取消，并通过 `try_consume_stamina()` 管理自身的体力扣除与恢复等待；Combat 检查攻击资格后调用。WeaponSlots 只配合切枪限制及提示，消耗参数仍保存在槽内武器资源。
- 敌人 `enemy_actor.gd.receive_melee_hit()` 独立处理扣血、准度和击退。击退经 `move_and_slide()`，已由正常移动推进的帧不会重复推进；AI 未激活时身体仍能完成受击移动。死亡和复位清除外力。
- 敌人调用链为 `远程接敌的近战方案被选中 → AI 转交 melee 意图 → enemy_melee_controller → enemy_actor`，选择器和统一评分公式不按动作 ID 特判。候选与请求位于现有 `actions/enemy_tactics.gd`，不新增默认／战术行为，保留原训练选择与其他配置；敌人不调用玩家 Combat 的近战攻击函数。
- 敌人行为通过 `allows_movement(owner)` 查询是否允许近战期间退让，不读取近战阶段枚举。身体的移动、转向、开火与换弹入口自行维护冲突规则，直接调用也不能绕过前摇限制；受击推移仍独立生效。表现适配器只读取 `presentation_state()` 快照。接口详见 [敌人基础执行](../enemy-ai.md#基础执行接口与冲突规则)。

`tests/run_combat_regressions.py` 默认包含近战功能、表现、物理、战斗区域及体力五组专项；分别验证真实 V 输入与伤害、动画／移动／区域清理、30／60／120 Hz 下有无正常移动调用时的击退、区域限制，以及当前武器体力消耗、不足拒绝、恢复等待和状态条同步。结果及其他回归见 [实施记录](../superpowers/plans/2026-09-30-player-melee.md)。

敌人阶段新增 `tests/enemy/enemy_melee_execution_test.gd`、`enemy_melee_utility_test.gd`、`enemy_melee_approach_test.gd` 及玩家侧 `tests/player_enemy_melee_hit_test.gd`，分别归入敌人／玩家回归运行器。追近专项使用实际场景的武器、训练和掩体，先正常交战再通过玩家移动输入持续贴近，不强制选中近战或堵住退路，检查自主出手、命中、击退、收招退让及开火互斥。执行与范围核对见 [远程敌人接入记录](../superpowers/plans/2026-09-30-ranged-enemy-melee.md)。
