# 五张关卡地图

当前默认主入口为第1关，直接 **F5** 即可游玩连续五关。每关入场显示可关闭的 2D 说明并暂停战斗；清空所有波次后点击过关按钮进入下一关，第5关显示通关。死亡只重开当前关，换关按下一关保存配置重新准备装备与生命。各场景仍可单独 F6 试玩，详见[五关游玩说明](PLAY_GUIDE.md)。

## 当前保存的试玩配置（2026-10-27）

`lvl_1.tscn` 至 `lvl_5.tscn` 均已保存玩家、相机、灯光、小队与敌人波次，可分别打开后按 F6 试玩。本次按用户要求上传其本地关卡布局、出生点、波次、武器、训练和导航配置；这些是当前试玩参数，不代表最终难度，也不改变运行时机制。

第四、第五关新增本关的近战／手枪／冲锋枪／霰弹兵预设，分别位于 `scenes/enemy/levels/lvl_4/`、`lvl_5/`，引用 `resources/enemy/training/levels/` 下同关同名训练。公共霰弹兵为 `scenes/enemy/types/shotgun.tscn`；玩家步枪为 `resources/weapons/test_rifle.tres`，敌人霰弹枪为 `enemy_test_shotgun.tres`。具体地图仍以各关已保存的引用为准，未批量替换跨关预设。共享武器和配合预设会影响所有引用者，调整单关时应先设为唯一或另存。

上传前验证：五关分别使用 Godot 4.7.2 headless 启动90帧，均退出0，无脚本或资源加载错误；退出卸载时均出现原波次控制器的成员移除警告。此检查确认保存配置可加载，不代表完整敌人回归或关卡难度验收。

## 敌人波次快速上手

完整步骤、第一波引用位置和排错表见[敌人波次使用说明](ENEMY_WAVES.md)。

第一关已经配置两波，直接打开 `scenes/world/levels/lvl_1.tscn` 按 F6 试玩。第一波引用原来的 `Lvl1/Squad`；第二波在 `EnemyWaves/Wave2/Squad`。人数以你保存的小队成员为准，可以继续修改，不代表最终难度。修改第一波仍选原 Squad／Enemy，位置、朝向、血量、武器和 Training 都沿用原检查器。

给其他战斗场景加波次：

1. 把 `scenes/world/enemy_waves.tscn` 拖到带 `shooting_range.gd` 的区域根节点下，再把 `scenes/world/enemy_wave.tscn` 拖到它下面并命名为 Wave1。
2. 把 `scenes/world/squad.tscn` 拖到 `EnemyWaves/Wave1` 下，再把敌人／兵种预制拖到这个小队下，在地图中摆位置和朝向。同一波可以放多个小队。
3. 复制整个 Wave1 增加波次，也可拖入 `scenes/world/enemy_wave.tscn` 新建空波。EnemyWaves 下同一层 Wave 从上到下就是出场顺序，名称不决定编号。选波次的 **Wait For Previous Clear** 决定是否等相邻上一波全灭，**Start Delay Seconds** 设置等待秒数：勾选则全灭后计时，取消则上一波实际出场后计时。默认勾选、0秒；首波从本轮开始计时。
4. 保存并运行：玩家入区启动，按各波条件推进，允许定时加入的多波同时存在；刷新点被玩家或可移动物体占用时自动等候，让开后出场。全部波次生成且全灭才算完成，最后玩家离场重置为首波。

已有地图不想移动小队时，在波次的 **兼容已有场景 → Existing Squads** 数组增加一项，将现有 Squad 拖入。它须在同一区域且只能引用一次；新地图优先直接把小队放在波次下。节点上的黄色配置提示会指出空波、缺敌人、重复／跨区引用等问题。摆在墙内或导航外的刷新点需手动改位置；系统不自动挪点或强刷。

血量、武器和个人训练仍改敌人，小队配合改 Squad 的 Profile。共享 `.tres` 的修改仍影响其他引用者，单只例外需设为唯一或另存。日常无需调整控制器；默认入场自动开始、占位每0.25秒重试，重试间隔位于“高级设置”。暂停、玩家死亡和对话期间等待不推进。完成信号不包含胜利界面、跳关或存档。

运行诊断可调用 `EnemyWaves.debug_snapshot()`，查看中文 `status`、`wave`（从1开始）、`alive`、`pending` 和 `reason`。当前实现沿原身体支持直立、未缩放角色，允许区域／小队平移和水平旋转。部署模板只存在内存中，不额外保存 JSON 或每波外部文件；当前五关均已由用户保存小队与敌人波次。

## 当前尺寸与外形约定

原始搭建的比例和外形初值如下；本轮用户明确指定的改动只有水平乘0.75，高度不变：

- 原始搭建采用20个SVG单位对应1米；水平缩放后 `meters_per_svg_unit=0.0375`。只取图纸内框中的实体，忽略文字、图例、箭头和物品标记，`source_rect`仍记录原SVG坐标。
- 地图中心为局部原点，地面基准为 Y=0。原图向右对应 +X，向下对应 +Z。
- 全身掩体和墙体高 2.2 米，半身掩体高 1.1 米，沿用原预制场景高度；根节点 Y 为高度的一半，底面贴地。
- 高掩体和建筑墙段的平面尺寸、位置在原布局上统一水平乘0.75。L形转角仍由原矩形墙段组合；门洞和绕行通道布局保留，宽度同样缩小，通行仍按原角色胶囊验证。
- 原始半身掩体短边最多1米，本轮缩为最多0.75米；长边、中心和已有碰撞偏移也按0.75调整，原1.2米翻越厚度上限保持。lvl3用户已有的加长碰撞及外观差异分别保留其比例，不借缩图重置这些本地修改。
- 外围墙厚由0.3米缩为0.225米，仍在内框以外；与建筑接边的部分保持闭合。墙体颜色和材质保留。
- 地板厚 0.2 米，中心 Y=-0.1，顶面为 Y=0，覆盖内侧区域及外围墙底部。

## 保持掩体识别与安全编辑

所有全身掩体、建筑墙段均实例化原 `scenes/world/cover.tscn`；半身掩体实例化原 `scenes/world/low_cover.tscn`。场景仅覆盖位置、外观资源、盒体尺寸与参考元数据，不覆盖 AI 站位参数或替换脚本。外围墙和地板是普通 `StaticBody3D`，只有网格与盒形碰撞，不挂掩体脚本、不加入 `cover_region` 分组，不提供 AI 掩体候选。

- 保留 `StaticBody3D`、`cover_region.gd`、原碰撞层／掩码、运行时 `cover_region` 分组，以及 `Mesh`、`CollisionShape3D`、`Presentation`、`ImpactReceiver` 的路径与脚本。
- 半身掩体继承 `low_cover=true`、`vault_enabled=true`，高掩体保持原默认值。离墙间距、候选采样、墙角范围等参数沿用原预制场景。
- 所有根节点保持 Scale=(1,1,1)，碰撞子节点保持默认变换。每块拥有独立且 `resource_local_to_scene=true` 的 `BoxMesh` 和 `BoxShape3D`，两者尺寸相同，编辑一块不会同时拉伸其他块或另一份地图实例。
- 已开启掩体实例的可编辑子节点。调整尺寸时同时修改 `Mesh → Mesh → Size` 与 `CollisionShape3D → Shape → Size`，保持盒体直立、底面贴地。不要改成不受现有查询支持的多边形／凹形碰撞，不要删除或改名固定子节点。

具体参数与编辑方法见 [竞技场说明](ARENA.md)。组合墙段仍按多个原有矩形掩体识别，候选点继续受实际遮挡、碰撞和导航过滤；不把实体接缝当作可站位置保证。

## 区域、导航与空小队

五张地图均已接入原有区域控制器，结构如下：

```text
Lvl1～Lvl5（shooting_range.gd）
├── CombatZone（Area3D + BoxShape3D）
├── Squad（原 squad.tscn 的空实例）
└── NavigationRegion3D
    └── Environment
        ├── FullCover
        ├── HalfCover
        ├── Walls
        ├── Boundary
        └── Ground
```

CombatZone 覆盖地图内侧范围，高 3 米、中心 Y=1，碰撞层为 0、检测掩码为 1；沿用 `zone_volume.gd`，区域标识分别为 `lvl_1` 至 `lvl_5`。空 Squad 自动注册到本图的区域服务，每图有独立的本地 Profile，默认“仅视野共享”；需要战术配合或强配合时在 Squad 的 Profile 中选择。区域原有的玩家入场激活／离场复位规则保持。

将 `enemy.tscn` 放到 Squad 下的可通行位置即可。玩家与相机可分别拖入两个独立预制；lvl3已有这些实例，其他地图的玩家、相机、灯光仍由使用场景配置。已有角色尺寸保持，水平出生点随地图缩放，实际站立空间与导航仍需要有效。

每张图引用独立的 `resources/navigation/lvl_N_navigation.tres`，已烘焙并保存。几何沿用现有 AI 要求，置于所属 NavigationRegion3D 下；移动地图时保持根节点及父节点比例为 1。掩体自动识别和静态信息更新不等于自动重烘导航。

修改地图几何后，可以选中该场景的 `NavigationRegion3D`，点击工具栏的“烘焙导航网格”。公共掩体预制的 `NavigationBakeObstacle` 子节点会根据实例的真实盒体碰撞排除墙内和墙顶，包含低掩体继承与碰撞尺寸覆盖。不要删除该辅助节点，也不需要把半身掩体移出实体碰撞层。

烘焙完成后保存场景；若导航网格是外部 `.tres`，同时在 Navigation Mesh 资源菜单中执行“保存”，确认路径仍为本图的 `resources/navigation/lvl_N_navigation.tres`。运行时读取保存的资源；单次编辑器烘焙不等于该资源已写盘。需要保留局部版本时先“另存为”独立资源并保持场景引用一致。

需要一次重烘全部五张图时，先保存场景，再在仓库根目录运行以下维护命令：

```powershell
& 'E:/Godot/Godot_v4.7.2-stable_win64_console.exe' --headless --path movement_demo --script res://tests/bake_levels.gd
```

该命令只重烘这五张图，不运行敌人测试。掩体使用与原生按钮相同的轮廓辅助；没有辅助节点的普通外围盒体仍由维护命令补充排除，不重复添加掩体轮廓。它不修改实际碰撞或 AI 代码，但会覆盖五张图的导航资源。当前参数为角色高度 1.75 米、导航半径 0.5 米、格子水平／垂直精度各 0.25 米、最大爬升 0.25 米，适用于现有平地布局；多层／斜面地形需要另行适配。

`vault_enabled` 只开放翻越尝试，实际仍需要地面、落点、身体通道和接近方向符合现有条件。本阶段不包含 AI 实战验收。
