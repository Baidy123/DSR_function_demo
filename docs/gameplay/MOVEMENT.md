# 角色移动练习

## 当前姿态与翻越（2026-10-08）

玩家按 **C** 切换手动蹲下／站起，蹲行仍使用 WASD。开阔处和背向矮墙可以保持蹲姿瞄准；只有当前瞄准方向被可利用的矮墙挡住时，右键才临时请求站起，松开右键或转离该墙后恢复手动蹲姿。手动选择站起会清除回蹲意图。头顶没有完整站立空间时保留实际姿态，不能穿过低顶。

右键自动起身期间按一次 **C**，表示改为手动站立：随后松开右键保持站立，再按一次 **C** 才正常蹲下。不按 C 时仍按默认规则松开右键回蹲；长按 C 的键盘重复事件不会连续切换姿态。

按 **Space** 翻越附近标记为可翻越的低掩体：有方向输入时按输入方向寻找墙面，静止时按当前朝向。预检覆盖入口、墙厚、整段胶囊通道和另一侧的地面及站立空间；失败不消耗弹药、体力或攻击冷却。执行中逐帧进行真实碰撞，动态受阻或近战推力会取消预定路径并安全下落，落地前继续占用动作，不能在墙顶提前开火。普通方向输入不覆盖空中轨迹。

翻越期间禁止射击、近战和换弹推进，但仍受伤；保留原切枪能力。落地沿当前观察方向重新索敌，不恢复旧目标牵引，按手动姿态恢复，仍按右键也可以继续蹲瞄。暂停冻结轨迹；对话取消轨迹并安全落地；死亡沿原暂停／重开流程处理。镜头使用 `get_camera_ground_height()` 保持地面高度，避免跟着跨墙过程上下跳动。

翻越首次中断时清除轨迹产生的合成速度，再交给重力与独立近战击退推进；后续重复中断不清除已积累的下落速度。上升段挨打不会把翻越速度当成向上的物理冲量。伤害、无敌和水平击退仍按原规则执行，真正离开战斗区域仍会触发该区域的敌人复位。

玩家站姿固定 **1.75 米**；当前胶囊半径沿场景原值。站／蹲外观和实体胶囊逐实例独立更新，根节点保留脚底位置，正面标记、观察点和枪口跟随实际姿态。蹲姿网格模板为 `resources/models/crouch_capsule.tres`，实例保留旧材质；`Player/Visual/Body` 等路径不变。

| Player 检查器参数 | 默认值 | 用途 |
| --- | --- | --- |
| Crouch Height | 1.0 米 | 完成蹲姿时的身体高度 |
| Posture Transition Seconds | 0.2 秒 | 站蹲连续过渡 |
| Crouch Move Multiplier | 0.5 | 蹲行相对普通移动速度；蹲姿不奔跑、不额外耗耐力 |
| Standing / Crouching Eye Height | 1.55 / 0.88 米 | 实际观察点，影响可见性 |
| Standing / Crouching Muzzle Height | 1.30 / 0.72 米 | 实际射线起点，枪口被挡仍会打墙 |
| Vault Duration | 0.8 秒 | 翻越基准时长，几何查询会限制极快的长轨迹 |
| Cover Interaction Distance | 1.5 米 | 玩家查找低掩体的距离 |

1.75 米站高为用户要求；表中姿态、速度、时间和点位为当前可调试玩初值。移动声音配置见 [听觉](HEARING.md)，蹲姿精度见 [射击](COMBAT.md)。蹲姿 V 先验证资格、体力和起身空间，完成起身后再次验证才扣一次体力并挥击；等待期间切枪、翻越、离场或对话取消请求。

## 初始移动阶段记录

这是第一步：用 3D 占位角色验证“先原地转好，再移动”。

## 打开与运行

1. 打开 Godot，在项目管理器中点击“导入”，选择本目录的 `project.godot`。
2. 进入编辑器后，打开 `scenes/main.tscn`，按 F6 运行当前场景，或按 F5 运行项目。
3. 点击游戏画面后，用 WASD 移动；W+D 等双键走斜线。
4. 黄色短条代表角色正面。换方向时观察它先转动，角色再行走。
5. 按 F8 停止运行。重新运行会回到场地中央。

本地使用 Godot 4.7.2，GDScript，Compatibility 渲染器。

## 先看这两个文件

- `scenes/main.tscn`：可在编辑器中直接查看的场景，包含平地、边界、角色、灯光和摄像机。
- `scripts/player/player.gd`：挂在 Player 节点上的移动脚本，共三段逻辑：读方向 → 原地转向 → 对齐后移动。

主要节点：

```text
Main
├── Floor                 地面与碰撞
├── Borders               场地边界，防止走出镜头
├── Player                CharacterBody3D，负责移动与碰撞
│   ├── CollisionShape3D  角色的碰撞形状
│   └── Visual            外观分组，当前随 Player 一起旋转
│       ├── Body          蓝色占位角色
│       └── FrontMarker   黄色正面标记
└── Camera3D              固定倾斜俯视，不跟随角色旋转
```

`project.godot` 保存工程设置和 WASD 输入映射。`tests/` 是自动检查，可以暂时不读。若看到 `addons/godot_ai`，它是本机环境加入的工具插件，移动脚本不调用它。

## 怎样理解移动脚本

每个物理帧先清空水平速度，所以角色不会带着上一个方向的速度继续滑行。

按键产生一个目标方向。脚本比较“当前面朝角度”和“目标角度”：还没对齐时，旋转 visual 引用的节点（当前为 Player 自身）；已经对齐时，才设置水平速度。最后由 `move_and_slide()` 执行移动和碰撞处理。

`Input.get_vector()` 将斜向输入长度限制到 1，因此斜走不会比直走更快。这里的 WASD 按画面方向移动，不是左右键控制转向的坦克式操作。

## 调整手感

停止运行，在场景树中选中 Player，右侧检查器会显示：

| 参数 | 临时测试值 | 作用 |
| --- | --- | --- |
| Move Speed | 3.0 | 行走速度，单位为场景单位/秒 |
| Turn Speed Degrees | 720.0 | 转向速度，单位为度/秒；转 90 度约需 0.125 秒 |

这些数值和固定倾斜俯视镜头是测试设置，尚未经过用户手感确认。建议一次只改一个参数，再运行比较效果。

目前的输入边界处理：松键立即停止移动与转身；反向键同时按下互相抵消；转身期间更换按键时改朝最新方向转。这些是本版简单处理，可根据试玩反馈修改。

## 奔跑与耐力（2026-09-14）

已按讨论加入：按住 Shift 奔跑，速度为走路的 2 倍；满耐力可连续跑 5 秒，从空回满需 3 秒。参数为已同意用于试玩的初值，后续可调整。

- 奔跑消耗耐力；停止消耗后，行走、站立、原地转向都会在 `Stamina Recovery Delay` 等待结束后恢复耐力。
- 未耗尽时可以随时再次奔跑。
- 耗尽后仍可行走，但必须回满才能再次奔跑；一直按着 Shift 会在回满后的下一物理帧自动续跑。
- 仍然先转好再移动，转身速度沿用现有的 720 度/秒。
- 当前按奔跑输入状态计费：对准方向、按住方向键和 Shift 时，即使顶住墙也会消耗耐力。
- 本步没有新增耐力条；先通过速度变化验证规则。

实现位于 player.gd：stamina 保存 0～100 的耐力，stamina_exhausted 保存耗尽后的锁定状态，is_sprinting 表示当前是否进入奔跑移动分支。_update_stamina(delta) 根据经过的时间消耗或恢复耐力。project.godot 新增 sprint 输入，绑定 Shift。

2026-09-30：玩家近战通过同一脚本的 `try_consume_stamina()` 扣除体力并重设恢复等待；消耗数值取自当前武器资源的近战参数。扣空后仍需回满才能奔跑，近战则只检查本次体力是否足够。没有单独的近战体力池，见 [玩家近战](MELEE.md)。

在 Godot 中按 F6 运行，按住 W+Shift 观察加速；持续按住，约 5 秒后降回走路速度，再过约 3 秒恢复奔跑。碰到边界会被挡住，可以换方向继续观察，或重新运行测试；注意转身期间也会恢复耐力。

停止运行后选中 Player，可在检查器调整：
- Sprint Speed Multiplier：2.0，奔跑速度倍率。
- Sprint Duration：5.0，满耐力持续奔跑秒数。
- Stamina Recovery Duration：3.0，空耐力恢复到满的秒数。

本次实现顺序：先新增奔跑测试并观察缺失功能导致的 8 项失败，再实现 Shift 输入及耐力逻辑，最后回归检查原有移动。已通过 18 项奔跑检查和 14 项移动检查；本次未进行图形界面试玩，手感待用户确认。
