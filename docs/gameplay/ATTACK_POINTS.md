# 墙角攻击点与后续计划

> 当前实现（2026-09-29）以 [敌人 AI 维护说明](../enemy-ai.md) 和 [正式回归清单](../enemy-tests.md) 为准。下方按概率触发、旧节点路径、整段最大散布必须无障碍等内容保留为历史记录，不应据此修改当前模块化 Utility AI。

高掩体当前候选为墙角 270° 扇环，内圈排除过度贴角位置。运行预览改为填充小区域：绿色合格、橙色未通过、暗红色内圈禁用。查询在遮挡边界局部细分，以模拟胶囊身体轮廓的五层七列加权射线判断部分遮挡，默认 20%～65%。射线角宽随距离和身体尺寸变化，不使用固定 45°～60° 扫描背景墙。

2026-10-08 用户要求半身掩体采用外围一圈架枪／蹲藏共用区域：低墙使用 `Wall Gap` 与 `Hide Depth` 形成连续矩形环带，不生成墙角扇环、内圈禁区或侧向 Peek。环带单元仍通过原预算评估，但不作高墙轮廓细分、不套用高墙20%～65%的部分遮身门槛；实际遮蔽率继续进入评分。低墙的候选、提交和占位复核使用同一已知头肩／躯干射击样本，运行预览按批次冻结这些样本。保留真实站立空间、枪口、导航和射程限制，不能从隐藏玩家当前姿态推断射界。详见 [竞技场](ARENA.md) 和 [敌人 AI](../enemy-ai.md)。

中心弹道和枪口前半米空间必须通畅，远处外围散布擦墙降低火力质量。区域同时受导航、身体余量、感知和射程限制；绿色是有限采样估计，提交目的地和占位时继续复核。空间查询留在共享分帧预算内，动作按共同 Utility 评分参选。

## 已确认范围

优质攻击位置是墙角附近能遮住部分身体、同时保有射击机会的位置。采用碰撞盒自动生成，并在检查器调节距离。主动选择这些位置属于有能力门槛的战术行为；兵种＋训练配置索引继续暂缓。

#### 在编辑器中试玩

选中Arena/Enemy/AI/Tactics，在Action Capabilities中调整：

- `Can Use Attack Positions`：是否有该战术能力；关闭仍保留普通换位和躲藏。当前是供试玩和未来配置赋值的接口，尚未按兵种／训练自动分配。
- `Attack Position Chance`：每次从看不见变为真正看见玩家，或敌人真正中弹且有攻击者位置信息时，抽一次；两种触发共用参数，0从不触发、1每次尝试、默认0.5。连续看见不会重复抽，失败后也不会每帧重试；下一次有效中弹可再次尝试。攻击占位或掩体动作中不重复启动。

建议先调成1，按F5进入竞技场让敌人发现。头顶依次显示“查找墙角攻击位置→前往墙角攻击位置→墙角占位射击”。查找独立于Debug Attack Points，关闭红绿显示仍正常使用；每帧最多检查64点／约2.5毫秒，提交目的地时再验证最新目击信息。

主动目的地除原空间／路径／射程／部分遮身检查外，还要在敌人的感知距离内。当前敌人视距8米而枪射程30.1米，不能只按枪的射程选择。移动和开火继续遵守原Fire While Moving、反应时间、跟枪、连射停顿等规则；未见玩家时不盲射。

途中失视继续前往所选点；靠近时实际身体位置也须合格，避免提前在墙后停步。到点仍未发现玩家回原追踪／搜索；位置失效则退出本次行动，看到玩家时回普通交战。玩家重新可见但当前行动还有效时保持目标。成功触发原躲藏动作会抢占攻击行动，来弹抽取失败或找不到躲藏位置则继续攻击行动。路径无进展2秒或超过“预计路程时间＋3秒”退出，避免永久卡住。

本轮通过180项相关检查：新攻击行为32、攻击点评估31、区域几何23、射击节奏36、掩护撤退射击13、躲藏受击28、完整躲藏探头4、竞技场激活13。旧射击节奏测试关闭新专项选位以固定测试站位；新行为测试独立覆盖真实走位和到位开火。已核对实机状态、实际持续射击、检查器参数及最终启动日志；独立审查无阻碍，游戏停止，手感待用户试玩。Peek合并、训练索引、完整战术评分继续待后续决定。

### 到位误退出修正（2026-09-20）

用户反馈很少选墙角、途中退出、到位后离开。本步已复现并修复其中一个明确错误：到位容差允许脚下与采样目的地相差约10厘米，玩家换角度后，实际脚下仍合格但旧目的地挡枪，原逻辑会错误退出。HOLD现在只检查实际脚下和真实目击；MOVE仍复查目的地，不继续前往已经失效的位置。

开启AI/Cover的Debug Cover Selection后，输出中的`[AI][攻击占位]`会区分新目击未抽中、没有合格候选、查找期间目标变化、转移目的地失效、实际站位失效、失去视线及超时等原因。默认50%和每次新目击只抽一次的规则未改变。

针对性回归5项、攻击行为32项、攻击点评估31项通过，共68项；编辑器启动的游戏中也复核了“实际脚下合格、旧目的地失效时继续HOLD”。尚不能据此认定另外两类反馈都已解决，仍需实际试玩。用户提出必要时增加“中弹概率触发寻找墙角”，作为后备方案记录，本步未增加此触发；兵种／训练配置结构继续暂缓，先稳定敌人行为。

### 敌人中弹触发攻击占位（已加入，2026-09-20）

用户明确授权加入中弹触发。enemy_ai.gd在敌人实际受伤且存活的分支，先更新原有受击位置估计并处理掩体反应，再通知AttackPositionAction。附近来弹没有造成伤害时不触发本项；致命伤、场外、无攻击者位置、能力关闭、无枪及近战也不会启动。

新触发与目击共用Tactics的Attack Position Chance（当前默认50%）。已在查找、转移或占位时不重新抽取，也不因连续受击不断更换目的地。原掩体动作优先；HIDE中弹按原规则退出躲藏后，可以尝试攻击占位。抽中仍需找到有效位置，并非中弹后必定架枪。

未看见玩家也可使用本次受击估计位置查找，保留原Attack Position Uncertainty误差，不伪造last_seen_position，不跟踪隐藏玩家实时坐标；真正取得视线后复核改用最新目击。到位仍未见玩家则退出，沿用原追踪／搜索规则；未修改搜索中心规则。红绿调试预览仍基于目击记忆，尚未目击时它不代表受击动作的候选检查结果。

验证：中弹触发28项（包含真实导航到位并开火）、原攻击动作32项、架枪保持5项、掩护撤退射击13项、躲藏受击28项，共106项通过；Main启动及运行日志检查通过，独立审查无阻碍，游戏已停止。旧架枪复现测试在内存固定复现时碰撞尺寸，不改用户场景。

试玩：按F5进入竞技场，射击敌人；开启AI/Cover的Debug Cover Selection，输出会显示“中弹触发”或“本次中弹未触发”，成功选位后头顶依次显示查找、前往、墙角占位射击。可将Tactics/Attack Position Chance临时设为1方便验证；没有合格位置仍会退出，不能据此保证所有中弹都移动到墙角。具体手感待用户试玩。

### 连续区域的几何与显示

用户看过编辑器临时对比后选择前者：每个墙角保留墙外相连的270°扇环，排除朝墙内的90°。下方第一步的8个固定点及旧参数已被替换，保留为历史记录。

- `Attack Inner Radius` / `Attack Outer Radius` 控制内外半径，暂定0.55／1.5米；`Attack Sample Spacing` 控制检查密度，暂定0.4米。距离基于碰撞盒局部坐标，随缩放变化。
- 区域连续定义，查询时才按径向和圆弧采样；相邻区域重合样本去重。有限采样不保证找到区域内每一个很窄的可用位置，减小间距会更细也更耗时。
- 编辑器橙色轮廓和半透明填充表示完整候选区域；其中贴墙、越界、枪口受阻、没有部分遮身等位置仍须运行时淘汰。
- 运行标记改为共享网格的红绿十字，每个掩体显示可用数量及最多两种主要淘汰原因。自动评估每帧最多64点，查询约2.5毫秒后让出，整轮完成后统一显示，再间隔0.25秒开始下一轮；显示因此有少量延迟。
- 整轮使用开始时的最新目击位置，不读取墙后玩家的新位置。关闭、死亡、离场或失去警戒／目击记忆立即清理未完成批次和显示。
- 连续区域已接入上方的主动占位动作；Peek合并及训练配置自动分配仍待后续讨论。

本轮区域／实例23项、评估与分帧生命周期31项、原区域32项、四面36项、躲藏探头4项、竞技场激活13项通过，共139项。查看编辑器及运行画面、核对运行日志；实机1288候选分21帧完成，测得每帧平均约2.6毫秒、峰值约4.5毫秒（含收集或绘制），不作为其他机器的性能保证。临时A/B对比已清理，游戏停止，人工手感待用户试玩。

## 在 Godot 中使用

1. 打开 `scenes/arena.tscn`，把文件系统中的 `scenes/world/cover.tscn` 拖到场景树的 `NavigationRegion3D/Environment` 下，再移动到需要的位置。这保证它位于当前 AI 使用的导航区域内。
2. 根节点控制整体位置、旋转和比例；初始方块长 3 米、高 2.2 米、厚 1 米，中心离地 1.1 米。摆放时让碰撞盒底面对齐地面。
3. 选中掩体根节点，在检查器调整 `Attack Inner Radius`、`Attack Outer Radius` 和 `Attack Sample Spacing`；前两项改变范围，最后一项改变运行检查密度。实际外半径至少比内半径大0.05米。
4. 橙色扇环是攻击候选区域，青色矩形是躲藏候选，黄色十字是 Peek；两类显示由 `Show Attack Points In Editor` 和 `Show Regions In Editor` 分别控制。
5. 要精确修改盒子尺寸，右键该实例开启“可编辑子节点”，将 `Mesh → Mesh → Size` 与 `CollisionShape3D → Shape → Size` 改成相同值，局部位置也应一致。新增实例的尺寸资源互不影响。改变高度后调整根节点高度，使底面仍贴地。
6. 新增、移动或改变实体尺寸后，选中 `NavigationRegion3D` 重新烘焙导航，再按 F5 检查敌人绕行；AI会按能力及概率在有效区域内选择攻击位置。

编辑器橙色区域仅是几何候选。运行时再根据实际敌人碰撞体、已知威胁方向和射击位置筛选；绿色也只代表对该已知位置合格，不保证未知威胁方向下安全。

## 第二步：攻击点评估与运行显示（历史实现）

用户同意完全没有身体遮挡的点直接淘汰，普通空地交火仍走现有流程。本步只查询和显示，不切换敌人的动作、导航目标或射击请求。

`scripts/enemy/services/enemy_cover_selection.gd` 提供 `get_attack_assessments(threat_origin, target_point)` 和单点 `assess_attack_point`，条件为：

- 使用当前胶囊检查站立空间，沿用烘焙导航，且路径必须真正到达候选点；地图外、错误高度、堵墙和只到断开边缘的部分路径均淘汰。
- 从当前敌人的预计枪口（脚底上方0.8米）到已知目标射线通畅，且在当前武器的实际射程内；不预测散布后的命中率，也不把当前冷却、反应等待当作点位缺陷。
- 身体中部上／中／下和左／中／右共9点采样；至少一部分、但不能全部被所属掩体遮挡。完全无遮挡直接淘汰，不借其他不相关墙体的遮挡冒充当前掩体的保护。

采样使用当前直立、未缩放的胶囊敌人。`3/9` 表示9条采样射线中3条被墙挡住，不是精确身体面积或受伤概率。地图几何变更仍需重新烘焙，未增加动态障碍路径重规划。
