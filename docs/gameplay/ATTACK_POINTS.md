# 掩体攻击位置

攻击位置是从掩体几何生成、再经运行检查筛选的候选区域。是否采用由兵种能力、训练解锁及个人／团队决策共同决定；旧版“发现掩体即按概率优先冲向攻击点”的叙述不再代表当前选择流程。完整旧方向、实施与失败记录见[历史记录](../history/2026-10-28/gameplay/ATTACK_POINTS.md)。

## 区域配置

选择使用 `scripts/world/cover_region.gd` 的掩体根节点：

中心弹道和枪口前半米空间必须通畅，远处外围散布擦墙只降低火力质量。区域同时受导航、身体余量、感知和射程限制；绿色是有限采样估计，提交目的地和占位时继续复核。空间查询留在共享分帧预算内，动作按共同 Utility 评分参选。

| 字段 | 脚本默认值 | 作用 |
| --- | --- | --- |
| Attack Inner Radius | 0.55米 | 高墙角攻击区内半径 |
| Attack Outer Radius | 1.5米 | 高墙角攻击区外半径 |
| Attack Sample Spacing | 0.4米 | 攻击区径向／圆弧采样最大间距 |
| Wall Gap | 0.55米 | 墙面到躲藏带近边距离 |
| Hide Depth | 0.4米 | 躲藏带宽度；低墙外围带同样使用 |
| Show Attack Points In Editor | 开启 | 显示区域预览，不改变运行选择 |
| Low Cover / Vault Enabled | 默认关闭 | 标记低墙／允许尝试翻越；仍需真实几何校验 |

保存的掩体覆盖优先，尺寸和间距会受节点变换影响。高掩体四角各形成墙外270°扇环，排除墙内90°，围绕碰撞盒生成；不是在四角各放一个固定点。低掩体改用完整外围站／蹲共用带，不应用高墙的角内圈排除与高墙 Peek 区。

## 候选资格与使用

1. 打开 `scenes/arena.tscn`，把文件系统中的 `scenes/world/cover.tscn` 拖到场景树的 `NavigationRegion3D/Environment` 下，再移动到需要的位置。这保证它位于当前 AI 使用的导航区域内。
2. 根节点控制整体位置、旋转和比例；初始方块长 3 米、高 2.2 米、厚 1 米，中心离地 1.1 米。摆放时让碰撞盒底面对齐地面。
3. 选中掩体根节点，在检查器调整 `Attack Inner Radius`、`Attack Outer Radius` 和 `Attack Sample Spacing`；前两项改变范围，最后一项改变运行检查密度。实际外半径至少比内半径大0.05米。
4. 橙色扇环是攻击候选区域，青色矩形是躲藏候选，黄色十字是 Peek；两类显示由 `Show Attack Points In Editor` 和 `Show Regions In Editor` 分别控制。
5. 要精确修改盒子尺寸，右键该实例开启“可编辑子节点”，将 `Mesh → Mesh → Size` 与 `CollisionShape3D → Shape → Size` 改成相同值，局部位置也应一致。新增实例的尺寸资源互不影响。改变高度后调整根节点高度，使底面仍贴地。
6. 新增、移动或改变实体尺寸后，选中 `NavigationRegion3D` 重新烘焙导航，再按 F6 检查旧竞技场中的敌人绕行；AI 会按兵种能力、训练资格、实际路线和运行检查选择攻击位置。

候选必须检查实际导航路径、完整身体站位、墙体和队友占用、公共预约，以及从计划姿态枪口到合法已知目标样本的射界。未来站姿位置按站姿身体与枪口核对，不能借当前蹲姿通过狭窄空间。

高掩体进攻评估目标轮廓暴露，并将可用射界计入质量；低墙使用自己的站／蹲观察和射击规则，不机械套用高墙暴露阈值。枪口近处与中心有效通道必须安全；远处外围散布被墙挡住可以降低质量，不能据此把全部合法中心射线一律拒绝。具体采样是有限近似，不是连续空间穷举。

在 **UnitType** 中确认该兵种提供相应战术，在 **Training → 战术解锁** 启用。默认行为与可选战术分开维护，训练不会自动创造兵种没有的能力。个人模式由统一Utility比较候选；普通／强配合由协调器选择具备命令提案资格的已装配动作。当前掩体进攻动作已有engage岗位、分帧攻击点提案和真实执行入口，须满足可见、有弹及原几何条件；不是只供个人模式使用。接入范围和验证边界见[敌人AI](../enemy-ai.md)。

编辑时先核对掩体碰撞与模型一致，再调整区域尺寸和采样间距。减小间距会增加候选与查询负担，不保证战术一定胜出；地图边缘、队友占位或无合法射界时没有可用点是正常结果。完整操作见[竞技场](ARENA.md)。

## 代码职责

路径相对 `movement_demo/`：

`scripts/enemy/services/enemy_cover_selection.gd` 提供 `get_attack_assessments(threat_origin, target_point)` 和单点 `assess_attack_point`，条件为：

- 使用当前胶囊检查站立空间，沿用烘焙导航，且路径必须真正到达候选点；地图外、错误高度、堵墙和只到断开边缘的部分路径均淘汰。
- 从当前敌人的预计枪口（脚底上方0.8米）到已知目标射线通畅，且在当前武器的实际射程内；不预测散布后的命中率，也不把当前冷却、反应等待当作点位缺陷。
- 身体中部上／中／下和左／中／右共9点采样；至少一部分、但不能全部被所属掩体遮挡。完全无遮挡直接淘汰，不借其他不相关墙体的遮挡冒充当前掩体的保护。

采样使用当前直立、未缩放的胶囊敌人。`3/9` 表示9条采样射线中3条被墙挡住，不是精确身体面积或受伤概率。地图几何变更仍需重新烘焙，未增加动态障碍路径重规划。

### 查看检查结果

按 F6 运行 `main.tscn` 并在旧竞技场中让敌人看见玩家。`Arena/Enemy/AI/Cover` 的 `Debug Attack Points` 默认开启；debug运行时分帧检查后统一更新。绿色十字为可用，红色为淘汰；每个掩体汇总可用数量和主要淘汰原因。短文字含义：占位=身体空间被占，无路=不可达，挡枪=射界受阻，无掩=没有身体遮挡，超距=超射程，无枪=没有武器。

新增 `scripts/debug/attack_point_preview.gd` 只负责显示。看见玩家后，最新目击位置影响射界和遮挡判断；同一个点会随着玩家方向变化而合格或淘汰。失去视野时只用 `last_seen_position`，忽略隐藏玩家实际移动，不将搜索提示当作新的目击。未发现玩家、结束警戒、敌人死亡、离场或关闭显示时隐藏标记；非debug构建不创建预览，未进行release导出验证。

## 验证与限制

相关入口包括 `attack_points_test`、`attack_point_validation_test`、`attack_region_quality_test`、`low_cover_band_test`、`cover_tactical_safety_test` 及真实掩体运行测试。静态区域正确、候选质量正确、动作确实执行和帧耗时达标分别验证，不能互相替代。

旧高墙专项的通过数不覆盖后续低墙、团队调度或用户地图修改。本次只整理说明；当前失败、性能门槛和日志要求见[敌人测试](../enemy-tests.md)。
