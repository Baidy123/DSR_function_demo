# 玩家生命、体力显示与战斗重开

更新：2026-09-24。历史验证保留在末尾；当前 Debug 规则以本节为准。

## 当前规则

- 玩家出生时满血，最大生命试玩初值为 100；在 Main → Player → Health 的检查器中调整 Max Health。
- 生命归零后停止移动、射击、对话与敌人运行，显示“重新开始”按钮。
- 点击按钮回出生点，恢复生命、耐力、敌人、靶子及武器运行状态。场景节点（包括门）恢复初始状态。
- NPC A 的答应／拒绝选择保留，重新找 A 不会重新提供已选过的选项。没有新增存档系统，退出游戏重新运行仍会清空本次对话选择。
- 本步没有新增敌人攻击、自动回血或受击硬直。

## 无敌与受伤测试

1. 打开 Main，选中 **Player → Health**，勾选 **Debug Mode** 可设置启动时的 Debug 总开关，默认关闭。
2. 运行时也可在“远程 → Main → Player → Health”检查器切换，或点击右上角的 **Debug 总开关**。
3. 点击右上角 **测试受伤 -25**，通过玩家的统一伤害入口模拟一次受击。
4. 无敌会阻止扣血，但仍记录命中并触发准度惩罚；测试受伤按钮也遵守这一规则。不会回血，也不能把已经死亡的玩家复活。
5. 无敌及测试按钮仅供 debug 构建使用；release 构建隐藏按钮且忽略无敌设置。本轮未导出 release 版本。
6. 场景重开后，无敌恢复检查器保存的初始值；运行时临时勾选不作为存档保留。

总开关同时控制玩家无敌、声音范围圈、敌人头顶文字、攻击点预览和左上角战斗调试信息。关闭后立即清理残留圆圈／攻击标记并停止攻击点预览查询；声音和攻击点的原细项开关仍可进一步关闭显示，无法越过总开关开启。编辑器已开启的“可见导航”也受总开关限制，未开启该细项则不会自动新增导航网格。

正常生命、体力、弹药、玩家及敌人的真实换弹进度与瞄准准星不受 Debug 影响，继续遵守各自的显示规则。敌人换弹完成或取消后隐藏普通模式的进度文字，动作和生命诊断仍由 Debug 控制。右上角总开关与测试受伤按钮仍可操作。输出日志沿用各自现有设置，本次没有增加日志总开关。

`scripts/debug/debug_settings.gd` 自动加载只保存总开关、通知各视图，并限制 release 构建。Health 的旧 `debug_invincible` 代码入口作为总开关别名兼容现有测试；检查器改用 `debug_mode`。

## 体力条与输出日志

左下角集中显示生命（红色）和体力（青绿色）两条状态条及数值；对话时隐藏状态条，避免遮挡正文和选项。体力在奔跑和成功发起近战时减少，经过恢复等待后回复。近战消耗由当前槽内武器的“近战体力消耗”配置，见 [玩家近战](MELEE.md)。耗尽后显示“恢复中”，沿用回满才能再次奔跑的规则；近战只需余量足够本次消耗。显示组件只读取原有耐力状态，不保存另一份体力或消耗参数。

Godot 的“输出”面板照常显示，同时把运行日志写入工程内 `logs/game.log`；旧运行日志由 Godot 保留为带时间的文件。自动检查日志放在 `logs/tests/`，已整理此前根目录的 49 个 `.log`。不新增游戏内日志窗口。日志不提交 Git，`logs/.gdignore` 避免 Godot 导入日志。耐力数值不再逐帧打印。当前自有脚本使用以下分类：

- `[玩家][受击]`：输入伤害、实际扣血、前后生命与最大生命。
- `[玩家][无敌]`：命中的伤害数值、“无敌，未扣血”和当前生命。
- `[AI][掩体]`、`[AI][搜索]`、`[AI][追踪提示]`：现有 AI 调试信息，保留各自的开关。仅整理当前使用的 v8 / v9，历史版本脚本未改。

无效伤害（非正数、NaN、无穷）及死亡后的重复受击不扣血、不重复输出有效受伤记录。致死伤害会把实际扣血限制在剩余生命，不记录负生命值。

项目设置 `debug/file_logging/log_path` 使用 `logs/game.log`（文件系统相对路径）；已验证从当前编辑器运行 Main 时落在 `movement_demo/logs/`，实际受伤记录可读。命令行验证可通过 `--log-file` 指定 `logs/tests/` 中的独立文件。尚未验证导出版本的日志位置。
