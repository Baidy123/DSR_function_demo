## 试玩

F5 运行 Main，从出生点向右走，经“竞技场 →”通道进入紫色地面区域。相机继续跟随现有 Player，无场景切换。绕过中央高墙，让敌人正面看见你，再退到墙后观察头顶状态变化。

- 随机巡逻：未发现玩家时，在竞技场导航区域中随机选可到达的位置，绕墙前往；抵达后停留再选下一点。
- 看见玩家：不断更新最后位置，并寻路接近；靠近约 1.3 米时停下，本步没有敌人攻击。
- 前往最后位置：失去视线，只走向此前记住的位置，不跟踪墙后的新位置。
- 搜索：到达后左右查看约 2 秒，仍未看见则恢复巡逻；重新看见会继续接近。
- 背后进入 2 米近身警戒范围也会被发现，但隔墙不会触发。
- 受击存活时前往攻击者附近的位置，默认随机偏移最多 1 米；未重新发现玩家时不会跟踪其后续位置。
- 敌人可被现有枪械射线击中，死亡后停步并退出锁定。玩家离开竞技场 CombatZone 后，敌人恢复出生位置、生命、姿态和待机状态。

## 节点和代码

Main/Arena 是 arena.tscn 的实例，位置 (20, 0, 0)。竞技场包含自己的地面、高障碍物、边界、连接通道、CombatZone 和 Enemy。Main 的右侧边界分成两段，为通道留口；原 NPC 位置、对话、靶场与武器配置保留。

enemy.gd 挂在 CharacterBody3D 胶囊敌人上；NavigationAgent3D 提供绕墙路径，脚本负责移动、朝向和感知。can_see_player() 检查所在区域、距离及射线遮挡；近身范围内忽略视角。发现玩家时更新 last_known_position，受击时也会将它设为攻击者附近的位置。player_combat.gd 在实际命中后传入攻击者位置；Arena 根节点复用 shooting_range.gd，在离场时调用敌人的 reset_target()。

选中 arena.tscn 的 Enemy，可以调整 Move Speed、Sight Distance、Sight Angle Degrees、Search Seconds、Stopping Distance、Max Health；Close Awareness Radius 控制近身警戒距离，Attack Position Uncertainty 控制受击定位偏差。高墙尺寸和位置可在 NavigationRegion3D/Environment 下编辑。

移动障碍物后，选中 NavigationRegion3D，使用编辑器的 Bake NavMesh 并保存导航资源。也可在项目目录运行：

```powershell
& '../Godot_v4.7.2-stable_win64_console.exe' --headless --path . --script res://tests/bake_arena.gd
```

导航网格保存为 arena_navigation.tres。当前体素烘焙后的路径高于地面 0.5，NavigationAgent3D 的 Path Height Offset 设为 0.5，让脚底位置与路径对应。导航代理按每个物理帧更新路径，参考 [Godot 官方 NavigationAgent3D 文档](https://docs.godotengine.org/zh-cn/4.x/classes/class_navigationagent3d.html)。

## 掩体自带四面区域与有效 Peek（2026-09-19，按最新要求修订）

已按用户确认实现：掩体四面均有连续躲藏区域，先根据已知威胁位置选择背向面；斜角可同时有两个候选面，再验证当前掩体是否真正遮挡。失去视野时沿用已有记忆和来弹信息，本次选位不额外读取隐藏玩家的新位置。

### 节点与代码

六个 CoverA～CoverF 的 StaticBody3D 挂载 cover_region.gd。它读取自己 CollisionShape3D 的 BoxShape3D，沿 X/Z 四个面生成中部矩形区域；每对相向面共用两个相应端点外的 Peek，共四个 Peek 点。位置跟随碰撞盒的偏移、旋转、缩放和尺寸，移动或复制掩体时无需另外维护点位。

arena.tscn 中独立的 CoverPositions 已移除。旧 cover_point.gd 留作历史文件，当前场景不再使用；敌人仍使用 enemy_cover_tactical_v9.gd，通过 get_candidates() 获取区域内候选，通过 is_hiding_position() 验证实际躲藏位置。

### 编辑器查看与调节

打开 Arena，选中 NavigationRegion3D/Environment 下的 CoverA～CoverF。青色矩形是四面候选躲藏范围（运行时再过滤不可用位置），黄色十字是 Peek 点；辅助线只在编辑器显示，不产生碰撞、不保存为需要维护的独立节点。

| 参数 | 当前试玩值与作用 |
| --- | --- |
| Hide Length Ratio | 0.75：长边面中间 75% 可用于躲藏 |
| Short Hide Length Ratio | 0.25：短边端面只用中间 25%，保留少量选位空间 |
| Hide Depth | 0.4 米：矩形区域沿离墙方向的宽度 |
| Wall Gap | 0.55 米：墙面到区域近边的距离，给敌人身体留空间 |
| Peek Outset | 1.0 米：Peek 超出对应面端点的距离 |
| Sample Spacing | 0.75 米：沿区域采样的最大间隔，同时加入敌人最近的区域内点 |
| Show Regions In Editor | 是否显示编辑器辅助线 |

距离随掩体节点缩放。区域以碰撞盒为准；修改掩体物理尺寸时需同步可视模型，并重新烘焙导航。本次墙体几何未改变，沿用现有导航。

### AI 如何使用

- 躲藏候选必须位于威胁对侧，身体能站下，有可达路径，且由当前掩体遮挡；沿用原撤退距离和掩护质量评分。
- Peek 沿墙端外、靠墙体厚度中线设置，避免只在背面横移后斜射线仍穿墙。每个面可使用对应的两个端点，选择有身体空间、导航和通向已知威胁位置射界的一端。
- 实际走到 Peek 的 0.12 米内且视线通畅才进入 WATCH；若途中已经真正发现玩家，仍按原规则提前回到接敌行为。
- 导航提前结束时，仅在最后短段身体空间通畅的情况下补走；被堵住或超时则回到原调查流程。
- 旧 Peek LOS Weight 已移除，因为视线现在是必要条件；Require Assigned Cover 保留为掩护质量判定开关，不再需要手动指定 Cover Body。
- 本步仍是现有胶囊敌人的移动和观察，不包括半身掩体、蹲伏、攻击或群体战术。

### 躲藏受击退出与短边收窄（2026-09-19）

用户确认：躲藏中被击中时优先离开躲藏，回到接敌流程；短边改为中间25%的小区域，长边保留75%。
